A picture or a document is put on a record from the page, through the host's own storage (FR-163). A host hands `mount`, `<Embed>`, `GraviewProvider` or the Shell `files: { upload(file: Blob, name: string): Promise<FileValue>; maxBytes: number; kinds: readonly string[] }` (`HostFiles`), and `PagesApp` takes it in its context; `upload` stores the bytes and answers the value the record keeps. A file field's editor is drawn on every face where the record's values are changed — the scene's record, the routed record page, the routed face's forms and the strip's ask — and a field that holds nothing yet is drawn there too when an act may write it. It takes files picked, a photo taken (`<input capture>`, offered where the pointer is a finger), files dropped and files pasted, several at once for a list. A camera's photograph, and a JPEG or WebP bigger than a page needs, is drawn again in the page no larger than 2,048 pixels before it is sent (`resample`, which `downscale` now uses too); a HEIC the browser can read is sent as a JPEG, one it cannot read is sent as it is where the host takes HEIC and refused in words where it does not. What the host takes is said before anything is sent ("or drop or paste them here · pictures and PDF files, up to 10 MB"), and what it refuses is said in the editor's words: "“big.png” is 14 MB; this host takes files up to 10 MB.", "“quote.pdf” is a PDF file; this host takes pictures.", or the message `upload` threw ("“porch.png” wasn’t kept: the disk is full"). What is kept becomes the ordinary act that sets the field, which the room records and undo takes back, and a list's files may be given a caption, moved earlier and removed. Without `files` the editor says "This host doesn’t take files, so none can be added here." and offers no way to add one.

For development and the harnesses, `@graview/ship/dev` has a door that keeps files in memory and serves them back (`devFiles()`, a Vite plugin, and `devFilesHandler`; `/__graview/files`, same-origin only, never in a build), and `@graview/ship/browser` has `filesAt(url, { maxBytes, kinds })`, the `files` a page hands that sends to such a door, or to a host's route that answers the same. The todo example's tasks take attachments through them under `pnpm dev`. `scripts/verify-files.mjs` drives it on both faces in three engines.

Compatibility: additive. Ops, stored formats, the wire, the document format, the compiled format, check finding codes and tool names and schemas are unchanged by the seam itself. New: `HostFiles` from `@graview/core`; `files` on `FrameOptions` (so `mount` and `<Embed>`), `GraviewProviderProps`, `ShellProps` and `PageContext`; `HostFilesContext` and `useHostFiles` from `@graview/react` and `/provider`; `filesAt` from `@graview/ship` and `/browser`; `devFiles`, `devFilesHandler`, `DEV_FILES_PATH`, `DEV_FILES_KINDS` and `DEV_FILES_MAX_BYTES` from `@graview/ship/dev`. `capabilities().shipped` gains FR-163. What Graview Cloud changes: it passes the `files` its route already answers to `mount`.
