A record follows the record it derives from, and a computed field can be sent to a connection, Roadmap f-keep-linked. Homeflow's events are copies of its plan items, drives and routines: renaming a plan item to "Costco" left its event, and the Google event, as "Huguenot Park & Costco", because nothing said the event was the plan item's. A kind now says it derives from another — `"derives": { "from": "plan-item", "via": "source", "set": { "title": { "expr": "name" }, "start": { "expr": "date" } } }` on the event — and the store keeps the two in step in the same change as the edit that moved either one, with no schedule: a plan item made, changed or newly linked hands each event linked through `source` the values `set` works out from it (each expression read standing on the plan item, `to` the event), in the same op, so one undo takes the edit and what followed it back together, and a connection's next pass sends what the event now says. A field set from one of the source's own stored fields as it is (`{ "expr": "name" }`) and changed on the event — on its page, or by the calendar's edit landing — goes back to the plan item and on to the item's other events, when whoever changed it may make the plan item's own edit (a seat that may not, or a field the plan item declares `fixed`, leaves the plan item as it was). A field worked out any other way stays as it was changed, and `store.findings()` says the record is out of step — the new stored-data code `derived-out-of-step`, "Long run: Where says "The beach", and it follows Long run, which works it out as "Jacksonville"" — with the repair that sets it again (`repairPlan` says "1 field of a record that follows another would be set again from its source"). Archiving the source archives its events, bringing it back brings them back, and removing it archives them, kept. It holds for an act, a host's own `applyPrimitives`, `preview` and `previewAll`; a store whose app derives nothing does no more work than before. Relations declared either way round are followed, and a chain of kinds that follow one another is followed to its end. `graview check` says `derives-kind` (no such kind, or the kind itself), `derives-relation` (naming the relations that do join the two), `derives-field`, `derives-value` (an argument, which no act asks for here), `derives-name` (a name the source does not have) and `computed-written`, in the person's voice. The edit vocabulary gains `set-derives` (`{ kind, derives | null }`), said in a sentence by `editDocument` and the same sentence by `diffDocuments`; a renamed kind, relation or field is followed, and a removed one takes the values that read it, and the `derives` with it when nothing is left. `graview describe` gains "Kept in step with another record". A node definition written in TypeScript may say `derives` too (`DerivesDeclaration`: `from`, `via`, `sourceEnd`, `back`, `values`).

A connection may now map a computed field — a Google event's title, times, place or description, or a Notion property — read-only on the way out: worked out over the store's graph on each pass, sent when it changes, never read back (a change to it in the calendar lands nowhere), and never asked of the act that makes a record from the other side (`ResourceMapping.computed`, each also in `ours`). A connection that only reads refuses one as `connection-computed-read`. `a-derived-record-follows-its-source.test.ts` holds both, Homeflow's case among them: renaming a plan item renames its event in the same change, and the next pass sends the new title.

Keeping records in step costs a hosted page 5.1 KB more up front (5_159 bytes minified, 1_815 gzipped), and a page handed a compiled app 4.5 KB (4_583, 1_640), under raises naming this changeset; the pages face alone 4_185 / 1_418 more, a visitor's form 4_186 / 1_408 and handed a compiled app 4_587 / 1_679, every face and the embed with the studio handed in 3.3 KB gzipped, and Cloud's worker 22_738 bytes, each under a raise of its own (`scripts/budget-raises/a-record-follows-the-record-it-derives-from-*.json`).

Compatibility: ops and primitives — unchanged; what follows an edit is ordinary `patch-node` primitives in the edit's own op, so a log folds the same on every build. Stored formats — unchanged; a compiled app's `KindPlan` may carry `derives` within `graview-compiled@1`, which a page that predates it ignores and so keeps nothing in step. The wire — unchanged. The declaration and check finding codes — `kinds.<kind>.derives` is a new optional key, the errors `derives-kind`, `derives-relation`, `derives-field`, `derives-value`, `derives-name` and `connection-computed-read` are new and said only of what is new, a computed field in a connection that `connection-field` refused before is now taken, and `validateGraph` gains the code `derived-out-of-step`; no declaration that passed is refused. Derived tool names and input schemas — unchanged; the edit vocabulary an agent proposes changes in gains `set-derives`. What Graview Cloud does: write Homeflow's events, drives and routines as kinds that derive from their plan items rather than copies, and map the event's computed title into its calendar where it wants one; a build that predates `derives` refuses it at `kinds.<kind>.derives`, so Cloud stores one only on a build whose document schema has it, and its health view may count `derived-out-of-step` as it counts the other stored-data codes.
