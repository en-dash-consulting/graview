A Notion connection's report names the kind each sentence is of, `runConnections` hands a host each pass's reports, and the guests typed in a field take a cap, Roadmap f-connection-reports-and-guest-cap (request:notion-said-names-its-source and request:guests-field-form-takes-max). In a Notion connection of several `sources`, only "Made N properties … for <kind>" and "no property in the data source for <kind> …" said which source they were of; "left alone in Notion: …" and "<name>: the property … is left out" did not, so a host showed them for the whole connection — and a note two sources both said ("left alone in Notion: Total (formula)") was said once, for whichever came first. A host read a pass only as `sayReport`'s line, split on " · ". And `guests.max` existed only on the `{ via }` form: an app whose guests are addresses typed in a field could not cap them.

Now every sentence of a connection of several sources names its kind — "left alone in Notion for task: …", "task's Estimate: the property Estimate is …, so it is left out", "could not make … in Notion for task: …" — and a note two sources say is said for each; a connection of one source says what it said. `SyncReport.saidBy` stands beside `said`: the same sentences in the same order, each `{ kind?, sentence }`, so a host shows each beside its kind without reading the words. `runConnections` takes `onReport(connection, report)`, called with each connection's report as each pass ends, the first included, and answers `firstPass`, the first pass's reports by connection name. `fields.guests` may be `{ "field": "<field>", "notify"?, "max"? }`, which `"guests": "<field>"` is said short: an event over `max` is held unsent in the same words as the relation's ("Dinner has 3 guests; this connection invites at most 2"), and `graview check` judges it with the same findings, `connection-guests-max` at `fields.guests.max` and `connection-guests-field` at `fields.guests.field`. `guestsInField` and `guestsViaRelation` on `@graview/core/sync` read either form. The graview-sync skill says all three. Cloud's worker comes to 1_580 bytes more (2_526_632 B, 2467 KB), under a raise of 1_600 naming this changeset; no page's first load moves.

Compatibility: ops and primitives — unchanged. Stored formats — unchanged. The wire — unchanged. The declaration and check finding codes — a calendar connection's `fields.guests` gains the `{ field, notify?, max? }` form, which a build before this one refuses by path (`connections.<name>.fields.guests`); no new code, and no declaration that passed is refused; the words of a Notion connection of several sources' report sentences changed, and they are display only. Derived tool names and input schemas — unchanged. `SyncReport` gains the optional `saidBy`, `RemoteSystem.pull`'s answer the optional `saidOf`, `RunConnectionsOptions` the optional `onReport` and `RunningConnections` `firstPass`. What Graview Cloud does: its Connections page shows each of `saidBy`'s sentences under the kind it names, reads a pass from `onReport` rather than splitting the line, and writes `{ "field", "max" }` for an app whose guests are typed in a field, dropping its 413 net (`guestCapped`) once it runs on this build.
