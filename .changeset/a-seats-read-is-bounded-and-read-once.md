A seat's read is bounded, and a read it already made is not sent again (FR-167). One turn in an app of 30 components, 28 skills and 84 strengths ran seven steps whose input grew from 5.6k to 91k tokens: `get_graph` answered the whole graph, about 28,000 tokens, the model asked for it three more times, and every step resent all of it, $0.60 for one question. Now no read answers more than `READ_CHARS` (8,000) characters of JSON, for a seat's turn and an MCP client alike, since both call the same runtime. `get_graph` answers a page of at most `READ_PAGE` (25) records with the edges out of them, `total`, and `more`: "and 117 more nodes: call get_graph with offset 25 for the next page." `get_node` answers a record's fields and its links as `{ kind, id, label }`, `READ_LINKS` (20) each way a page, never the linked records' own fields, with "and 24 more links in: call get_node with id "component-1" and offset 20 for the next page." `search_graph` answers at most `READ_HITS` (20) hits whatever `limit` asked, without every match's id, and "and 65 more records match: narrow the words, or add kind:<kind>." `get_violations` answers `READ_PROBLEMS` (20) a page. A text longer than `READ_TEXT` (600) characters is cut and says "… (cut at 600 of 5000 characters)", and any other read too long to fit, a place described in full, answers `{ cut, partial }`, the cut saying how long it was and to ask for less. Within one turn of a host's model, a call with the same name and input as an earlier one, in any order of its keys, is answered `{ already: "Already read: see the answer to call 1 of this turn, which is above." }` and counts toward the turn's twelve calls, so a model asking the same thing over and over is stopped as before. The bounds are exported from `@graview/tools` as named constants. The reads are a chunk of their own, fetched with the first read: a page whose seat is never asked carries none of them, the scene face before it draws is 742 bytes smaller and a hosted page's first load is unchanged. `capabilities().shipped` gains FR-167.

Compatibility: ops, stored formats, wire messages, the document format, the compiled format and check finding codes are unchanged; `capabilities().shipped` gains FR-167. Tool names are unchanged; the read tools' answers, titles, descriptions and three input schemas moved, so a surface's hash moves with them. `get_graph` takes `offset`, is titled "Read the graph", and answers `{ nodes, edges, total, more? }` a page at a time where it answered every node and edge. `get_node` takes `offset` and answers `out` and `in` as `{ kind, id, label }` links where it answered whole edges, with `more` when there are more links or problems. `get_violations` takes `offset` and answers `{ violations, total, more? }` where it answered an array. `search_graph` answers at most 20 hits, with `more`, and no longer `matched`. What a host or an agent does: read `get_violations`' `violations`, follow `more` with `offset`, and read a link's `id` where it read an edge's `to` or `from`.
