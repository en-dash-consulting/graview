A host that routes its own requests answers them as ship does. What `POST /graview/ops` means — a batch sent again answered once with the asking seat's own ops, a stale write a conflict, the host's `limit` (busy, `limit`, `unavailable`), a refusal's reason, the ops as the seat may see them once `flush` says they are durable — lived only inside `createStoreHandler`, and the shared wire helpers were internal, so a host that keeps its own routing (Graview Cloud's worker) lost idempotency and conflicts the moment it routed a request itself. `liveProtocol(...)` now answers the routes with meaning: `post(body, { seat, via })` is `POST /graview/ops` as a function, answering `{ status, body, headers }` and `landed`, the ops it put in the store for the host to `publish`; `state(asked)` and `since(seq, asked)` are `GET /graview/state` and `GET /graview/since` as the seat sees them. `createStoreHandler`'s routes call them — one implementation, and a test holds every body the route can meet to the same status, body and headers both ways. The socket's call and the post share one judgement of a change, too. A body that is not JSON is now answered 400 `invalid` where it was a 500. `WireAnswer` and `WireAsked` are exported from `@graview/ship` and `@graview/ship/runtime`.

Compatibility: additive. `LiveProtocol` gains `post`, `state` and `since`; the routes answer as before, but for an unreadable `POST /graview/ops` body, now 400 with the reason `invalid` rather than 500. A call whose `calls` is not a list is read as no calls, as the socket always read it. The wire and live protocols, `WIRE_PROTOCOL`, `REFUSAL_REASONS`, ops, stored formats and check codes are unchanged.
