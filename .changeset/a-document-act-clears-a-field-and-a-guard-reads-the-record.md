A document act clears an optional field when its effect sets it to null (Roadmap f-act-clears-optional-field). `"effects": [{ "set": { "assignee": null } }]` on a kind whose `assignee` is optional was refused — "does not match what task declares — Assignee: Invalid input: expected string, received null" — so unassigning or clearing a date needed a stand-in value. A null now removes the value, on the act's subject, on a record it makes, on the record at the other end and on linked records, and an undo puts it back. Only a literal `null` clears: a value worked out to nothing (an argument not given, `first()` of nothing) is judged by the store as before. A required field set to null is refused in words that name it ("Untitle" cannot clear Title of Write the page: every task has one), and `graview check` warns at the value (`act-clears-required`), naming the kinds that require it when an act is on several; a null set on an optional field passes. An argument cannot carry null, so an act that clears a field says so in its own `set`.

An act's condition and refusal can say which value a name is, and `graview check` says when a name could be either (Roadmap f-guard-reads-record-not-argument). The rule language's scope rules, in an act's `allowedWhen` and `refusal`:

- `$subject.<field>` is the record's own field. `$subject` is the record the expression is judged on, spelled as an act's effects spell it, and still the outer record inside a `where` or an `every`.
- `$arg.<name>` is the call's argument by that name, or nothing where the call gave none. It is read in an act's condition, refusal and the values it works out, and is nothing anywhere else — a label, a computed value (one an act's condition reads included), a rule's condition or sentence, what a kind follows, a workflow step's values, a view's conditions — where `graview check` warns of it (`arg-outside-act`); a `$arg.<name>` the act takes no argument for is warned of too (`act-arg-unknown`).
- A bare name is a member's field inside `where`, `every`, `some` and the rest read per member; else the call's argument by that name, where it gave one; else the record's field.

The member's field coming first is new: inside a `where` or an `every`, a bare name that is a field of the member is now that field even where the act was handed an argument by the same name, as the start page always said; a name that is no field of the member is still the argument. A field rename follows `$subject.<field>` and an argument's rename `$arg.<name>`; the checker types `$subject.<field>` as the field, and its sight warning (`act-reads-hidden-kind`), what a rule reads beyond its subject, a view's names and the design critic all read `$subject.<field>` as the record's own. No other name is spelled with a `$`, nor any name after a dot, and either is refused in words that point at `$subject` and `$arg`. `graview check` warns, naming the act and the field, of each bare name in a condition or a refusal that is both a field of the kind the act is on and one of its arguments (`act-name-means-both`); `$subject.<field>` or `$arg.<name>` answers it. The graview-permissions skill says the rules where it says when an act may run, and the graview-invariant skill and the start page where they say the rule language.

Tests: `a-document-act-clears-an-optional-field-set-to-null` clears optional fields on the subject, on a record the act makes, at the other end and on linked records, undoes it, refuses a required one by its name, and warns at an effect's path, a shorthand's `sets`, the far records' and for an act on two kinds. `a-guard-reads-the-records-own-value-as-dollar-subject` holds each scope rule in a condition and a refusal, inside `where` and `some`, the renames, the refused spellings, and the warning and what answers it. `an-act-that-reads-what-its-runner-may-not-see` follows `$subject` in a condition and a refusal.

The declaration and check finding codes — a document that compiled still compiles: `$subject` and `$arg` are new in the rule language, where a `$` was refused before; a null set on an optional field now runs; inside a `where` or an `every` in an act's condition, refusal or set value, a member's own field is read ahead of an argument of the same name; four warning codes are new, `act-clears-required`, `act-name-means-both`, `act-arg-unknown` and `arg-outside-act`; a refusal says `{$subject.<field>}` as it says `{<field>}`, a choice by its label and money as money, and `{$arg.<name>}` as its argument is declared.
