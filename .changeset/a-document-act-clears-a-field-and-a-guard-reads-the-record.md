A document act clears an optional field when its effect sets it to null (Roadmap f-act-clears-optional-field). `"effects": [{ "set": { "holder": null } }]` on a kind whose `holder` is optional was refused — "does not match what lease declares — Holder: Invalid input: expected string, received null" — so releasing, unassigning or clearing a date needed a stand-in value. A null now removes the value, on the act's subject, on a record it makes, on the record at the other end and on linked records, and an undo puts it back. A required field set to null is refused in words that name it ("Unname" cannot clear Name of Build the page: every lease has one), and `graview check` says so at the value (`act-clears-required`); a null set on an optional field passes.

A guard can say the record's own value where an argument has the same name, and `graview check` says when a name means both (Roadmap f-guard-reads-record-not-argument). In an act's `allowedWhen` and its `refusal`, a bare name reads the argument the call gives by that name, and the record's field only when the call gives none; so an act that `writes: ["holder", "expiresAt"]` and asks `holder == null or expiresAt < now()` judged what the call said. `$subject` in the rule language is the record itself, spelled as an act's effects spell it: `$subject.holder == null or $subject.expiresAt < now()` reads the record's own values whatever the call says, and a refusal says `{$subject.holder}`. It is the outer record inside a `where` or an `every` too, a rename of the field follows it, and `graview check` types it as the field. No other name is spelled with a `$`, and one that is is refused, pointing at `$subject`. `graview check` warns, naming the act and the field, of each bare name in a condition or a refusal that is both a field of the kind the act is on and one of its arguments (`act-name-means-both`). The graview-permissions skill says it where it says when an act may run, the graview-invariant skill and the start page where they say the rule language.

Tests: `a-document-act-clears-an-optional-field-set-to-null` clears two optional fields and undoes it, refuses a required one by its name, and checks the finding at an effect's path and a shorthand's. `a-guard-reads-the-records-own-value-as-dollar-subject` refuses a call on a live record whatever it sends, names the record's own holder in the refusal, allows it once the record's own time has passed, shows a bare name reading the argument, reads the outer record inside a `where`, follows a rename, refuses another `$` name, and warns of a condition's and a refusal's names that mean both and of nothing else.

A hosted page's first load grows by 0.7 KB up front (0.4 KB handed a compiled app), the act's runtime and `$subject` in the parser and evaluator (`scripts/budget-raises/act-clears-a-field-guard-reads-the-record-hosted-page.json`). Every face grows by 3.5 KB, Cloud's worker by 6.9 KB, a visitor's form handed a compiled app by 0.4 KB and the guest host drawing a worker view on the open kit by 0.4 KB, under a raise of their budgets; the scene face before it draws measures 1_134_725 B, under 1109 KB.

Compatibility: ops and primitives — unchanged. Stored formats — unchanged. The wire — unchanged. The declaration and check finding codes — a document that compiled still compiles; `$subject` is new in the rule language, where a `$` was refused before; a null set on an optional field now runs, and two codes are new: `act-clears-required` (an error, for an act that was refused every time it ran) and `act-name-means-both` (a warning). Derived tool names and input schemas — unchanged.

What Graview Cloud does: an act can now release or unassign with `null`, and HQ's lease kind can drop its stand-in date. A guard or refusal that names a field the act also takes as an argument gets a warning on save; writing `$subject.<field>` answers it. The ballot template's `add-candidate-here` refusal says `{name}`, which reads the candidate's name the call gives rather than the race's; `{$subject.name}` says the race.
