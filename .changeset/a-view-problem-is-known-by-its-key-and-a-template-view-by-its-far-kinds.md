A view's problem is compared by its own key where it has one, and a template's view that reads a relation without its far kind is refused as a proposed view is (HQ f-view-problem-key-follow-ups). `viewProblemKey` on `@graview/core/revisions` keyed a view's problem by its view, where and words, so a fault reworded between versions (`far-kind-not-handed`, whose `key` is made of names alone) was said as mended and made again; `ViewProblem` now takes the problem's `key`, and `problemsMade` compares problems that carry one by it, and those that carry none by their words as before. `graview check` of a template judged its views' kinds and relations by name only, and passed a view of the dishes reading `broughtBy` (dish to household) without `household` in `reads.kinds`, which `checkProposedManifest` refuses; it now refuses it at `views.<n>.reads.edges` in the same words ("\"dish-list\" reads the relation \"broughtBy\", from dish to household, and is handed no household, so no link of it reaches the view: add \"household\" to its manifest's reads.kinds."). The check is one: it moved to core (`unhandedEdges`, `unhandedEdgeProblems`, `farKindsRefused`, `farKindKey` on `@graview/core`), and guest's `edgesReadWithoutTheirKinds`, `edgesReadWithoutTheirKindsProblems`, `checkProposedManifest` and `farKindKey` are it. Core's tests hold a reworded problem with a key neither made nor mended, one without a key still known by its words, and the template's view refused and, with the kind handed, passing.

Compatibility: the declaration and check finding codes — changed: a template whose curated view reads a relation whose far kind it is never handed is refused by `graview check` (an `error`, code `view`, at `views.<n>.reads.edges`), where it passed; a document alone is judged as before. The JavaScript API is additive (`key` on `ViewProblem`; `unhandedEdges`, `unhandedEdgeProblems`, `farKindsRefused`, `farKindKey` and the `ViewReads` and `EdgesOf` types on `@graview/core`); `viewProblemKey` returns a different key for a problem with a `key`, so a host that stored keys it made for such a problem compares them once anew. The wire, ops and primitives, stored formats, and derived tool names and input schemas — unchanged.
