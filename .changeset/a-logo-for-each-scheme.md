A brand's logo has one for each scheme. Nick, building the TrueNorth recon app: the brand took an emoji or one mark, a client's real logo (a JPG on white) had nowhere else to go, and on a dark theme it sat as a white slab — the app drew it under `filter: invert(1) hue-rotate(180deg)` and `mix-blend-mode: screen` of its own. `brand.logo` is still a string, or now `{ light, dark? }`: the light one in the light scheme, the dark one in the dark, the light one there too where there is none. Whether a light logo is opaque on white cannot be known from it, so inverting it is asked for rather than guessed: `{ light, darkFallback: "invert" }` draws it inverted and screened onto the ground in the dark scheme alone, and beside a `dark` one it is never used, which `graview check` says (`brand-logo`, a warning at `brand.logo.darkFallback`). In a document the same object takes `alt` (`{ "src", "alt" }` and a string still mean one logo), each mark is judged as the one was (`brand-mark` at `brand.logo.light` or `brand.logo.dark`), and `set-brand` takes `logo: { light, dark }` and says "The logo gets one of its own for the dark scheme." (or "The logo is drawn inverted in the dark scheme.", "The logo is the same in both schemes."), as the preview of a change does. A declared app's logo is checked too now: a pair with no light one, a fallback other than `"invert"` (`brand-logo`), and a mark that could act (`brand-mark`). Contrast checks are on the colors, as before.

The default shell's bar and a design's own draw it with `AppMark` (`@graview/primitives`, handed the brand on `context.brand`): both marks are in the page, each `data-graview-scheme-only="light"` or `"dark"`, and the theme's sheet for the scheme the page is in hides the other's — so the logo switches with the scheme however the page chose it, with no hook — and a light one the brand asked to invert carries `data-graview-logo-fallback="invert"`, which only the dark sheet styles. `logoOf(brand)` and `logoFor(brand, scheme)` (`{ src, invert }`) on `@graview/core` are for a design that draws its own image. The static page's masthead does the same; a worker view is handed the logo its scheme draws. `graview-logo`, a skill of its own, says all of it: `graview-brand` gives its marks to it, split along that seam rather than shaved. A hosted page carries 1.5 KB more up front for it (1_541 bytes, 509 gzipped; the compiled page 1.4 KB, 1_461 / 482), under a raise of each budget by that; the scene face before it draws 1_541 bytes more, the pages face alone 982 / 337, the embed without the studio 987 / 318, every face 4_241 / 1_439, the embed with the studio 4_161 / 1_421, and the guest host 80 bytes before a worker is drawn and on the open kit, each under a raise of its budget by what it measured.

Compatibility: ops, stored formats, the wire and derived tools are unchanged. The declaration: `brand.logo` gains a third form, `{ light, dark?, alt?, darkFallback?: "invert" }`, and every document that compiled still compiles the same; the TypeScript `Brand.logo` is `string | BrandLogo`, so code that read it as a string reads `logoOf(brand)?.light`. Check finding codes: new `brand-logo` (an error for a declared app's pair with no light one or a fallback it does not know, a warning for a fallback beside a dark one), and `brand-mark` now also at `brand.logo.light` and `brand.logo.dark`, and for a declared app's logo. New on `@graview/core`: `logoOf`, `logoFor` and the type `BrandLogo`. The `set-brand` edit takes `logo: { light, dark?, alt?, darkFallback? }`. What Graview Cloud does: `add_image` each file as now, then `{"op": "set-brand", "logo": {"light": "/graview/assets/<sha>.jpg", "dark": "/graview/assets/<sha>.png"}}` (or `"darkFallback": "invert"` with a light one alone, when the person says the logo is a picture on white); a page that draws its own masthead uses `AppMark` or `logoFor`, and a stylesheet it writes itself for a scheme hides `[data-graview-scheme-only]` of the other.
