Three 1.0 foundations: a link keeps an id and data of its own, a caller names the records it makes, and a cursor is opaque on the wire. A link was `{ kind, from, to }` with nothing else to say; it may now carry an `id` and `data`, a JSON object of at most 4,096 characters (`EDGE_FIELDS`), and every reader keeps and folds them — the graph, its snapshot, the log, the wire, a seat's view of an op, an export, `snapshotHash` (a graph without them hashes as before), a merge (which moves a link whole), a migration's fold and every adapter, the SQL ones in the edge table's optional `data` column, which `createTables` adds to a table made before it and without which a link carrying either is refused rather than kept without them. A `remove-edge` whose link carries an id removes the link holding that id, and one that names none removes by kind, from and to as before; `Graph.linkById` finds one. They are reserved, not open: no derived act writes them, and a second link of one kind between the same two records is still refused, now in words when it says it is another. Every act that creates — in code, in a document, a repeat — honors a caller's `id` exactly when it is free and 1–200 characters with no space: a taken one is refused and the whole change with it, never renamed, a malformed one is refused before anything runs, and an act that names its records itself says so rather than drop the id. A seat that does not see everything may ask for an id of its own, one ending `.<seatMark(me)>`. `ApplyResult.minted` says the id each call's act minted first. An id a page minted on its own is a hint, not a demand: `openRemote` sends the call with `mintedHint` (a new optional field of `MutationCall`), and the store makes the record under it when it is free, so the rebase keeps the id and a press naming the record before the answer lands on it — and mints as ever (`-2`) when somebody took it meanwhile, a later call of the same change following it to the record made. Two people adding "Groceries" at once both land, and the log keeps each call without its hint. On the wire, where a reader stands is a cursor (`Cursor`, `cursorAt`, `seqAt` in `@graview/ship`): `/graview/since?seq=`, `/graview/here`'s `seq` and the socket's `hello` take one, and `welcome`, `ack`, `ops`, `/graview/state`, `/graview/since` and `/graview/here` say one; the store keeps numbering its ops. `docs/stability.md` says each in a subsection of its own. Core's tests keep, remove by id, undo, refuse and hash a link with its id and data and round-trip it through the SQL adapter's column, and chain an agent's records by its own ids in one batch, in code and in a document; ship's keep a record's id across the wire, land two people's same-named records as the name and `-2` on pages that agree, follow a taken hint within a change, and still refuse a caller's taken id, and read a token and an old number alike. About 1.9 KB more up front on a hosted page and one handed a compiled app and 1.8 KB on the pages face alone and on a visitor's form alone, under raises of those budgets (`scripts/budget-raises/edge-fields-client-ids-opaque-cursor-*.json`); the scene face's limit before it draws moves to 981 KB; and Cloud's worker imports come to 2,003,930 bytes, 4,004 more, so their byte budget moves from 2,000,000 to 2,004,000.

Compatibility: ops and primitives — additive: `GraphEdge.id` and `GraphEdge.data` are optional and no format number moves; a log without them folds as before, and a build before this one folds a log with them to the same graph while there is one link per pair. Stored formats — additive: the SQL adapters read and write an optional `data` column on the edge table and never need it while no link carries an id or data. The wire — changed, for one minor: a position is a cursor string where it was a number on `welcome`, `ack` and `ops`, and `/graview/state`, `/graview/since` and `/graview/here` answer `cursor` beside what they answered; a server reads a page's old number (0.1.48 and earlier) for one minor and stops in the next, and a page before this one reads none of the positions it is sent, so it keeps working; a seq that is neither is refused `invalid` where it was read as nothing. Acts — a caller's `id` is now refused when it has a space, is over 200 characters, or names a record the act did not make, where it was taken or dropped; a seat that does not see everything may ask for an id ending in its own mark, where it could ask for none. A call may carry `mintedHint`, additive: a server before it ignores the field and mints as it did, and `openRemote` sends it only for an id the page minted, so a concurrent create of the same name still lands as `-2`. Derived tool names and input schemas — unchanged. What Graview Cloud does: keeps a cursor it is handed as a string and sends it back, and reads `?seq=` with `seqAt` if it answers `/graview/since` itself; a Durable Object's `graph_edges` gains `data` when its adapter opens with `createTables`.
