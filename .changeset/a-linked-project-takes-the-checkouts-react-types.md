A linked project takes React's types from the checkout, as it already takes React. On 2026-11-17 csstype 3.2.4 reached npm while this repository's lockfile still held 3.2.3, and every project `graview create --link` made failed its own typecheck in `src/ui/pages.tsx` (`Type 'CSSProperties' is not assignable to type 'Properties<string | number, string & {}>'`): the framework's `.d.ts` named React through the checkout's `@types/react`, the project's code through a copy its own install had just resolved, and the two carried different csstypes. A linked project's `@types/react` and `@types/react-dom` are now written by path to the checkout's own (`link:<checkout>/node_modules/@types/react` under pnpm, `file:` under npm, one `../` longer in a workspace), by package name and never by a version inside the checkout's store, so whatever npm publishes next there is one copy. `graview create --link` refuses a checkout whose React types are not installed, and says to run `pnpm -C <checkout> install`. An installed project's manifest is unchanged. Held by unit tests of the scaffold and the create command, and by `smoke:create`'s `aLinkedProjectSharesTheCheckoutsReactTypes`, which also forces a different csstype on the linked project's install and typechecks it again.
