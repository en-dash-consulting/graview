A view revised, a picture taken or an act run says what it broke, Roadmap f-revisions-say-what-broke (request:help-agents-revise-views-and-data-without-silently-breaking-what-they-did-not-mean-to-touch). A chat rewrote Homeflow's home view whole: the "This week" section's markup stayed and the rules that laid it out (`.hf-week`, `.hf-wk-*`) did not, and the picture it was shown was the first screen, which looked as it had. Nothing said so until a person scrolled. The framework had what judges a view (a headless run's drawing and stylesheet, its problems) and an act (every op and primitive it kept, the rules it broke), but nothing that set a change against what it replaced.

`@graview/core/revisions` is new, a host's and on no page. `compareViewRevision(before, after)` reads two versions of a worker view — each its source, and where the host ran it the run's `css` and `drawing`, or a class list, and the page's height — and names the classes the revision still draws that a rule styled before and none styles now, the rules taken out while the markup they styled is still drawn, the sections (a heading, a named landmark) drawn before and not now, and how the page's height moved, as entries and sentences: "A class it still draws lost every rule that styled it before: .hf-week." A class no rule ever styled — a hook the view listens on, a utility — is never said. `MEASURE_PICTURED_PAGE`, evaluated in a page as it is pictured, and `picturedCoverage` say how much of the page a picture held and name the sections it left out: "First screen only (900 of 5,100px); not shown: This week, Dinner." `graview shots` prints that line under a picture that holds less than its place. `problemsMade(before, after)` sets two judgments apart — rules that held and fail after, view problems new after, and what was mended — each keyed as it is keyed next time, with the act a rule names to repair it. `beyondAsked(answer)` reads an act's or a batch's answer and says every record and link it changed beyond each asked act's own: what its body wrote elsewhere, what followed it, the links a removal took, an act in the batch nobody asked for. The graview-worker-view skill says to run both versions of a view being revised and hand them to `compareViewRevision`, and to picture past the first screen. Tests: `a-revised-view-is-compared-with-what-it-replaces`, `a-revised-view-says-what-it-stopped-styling` (both versions run headless), `a-picture-says-what-it-did-not-show`, `a-change-says-the-problems-it-made`, `an-act-says-what-it-changed-beyond-what-was-asked`, and the shots test.

Compatibility: ops and primitives — unchanged. Stored formats — unchanged. The wire — unchanged; `@graview/core/revisions` is a new entry, and `ShootOptions.onShot` is handed the picture's coverage as a second argument. The declaration and check finding codes — unchanged. Derived tool names and input schemas — unchanged.

What Graview Cloud does: `propose_view` and `apply_view` run the kept version and the proposed one headless and carry `compareViewRevision`'s `said` and entries in their answer, with "restore_view name=… is one call away" when it regressed after an apply; a picture evaluates `MEASURE_PICTURED_PAGE` and carries `picturedCoverage(...).said` beside it; `propose_view`, `act` and `act_batch` carry `problemsMade(before, after, { rules })`'s `made` in the same answer — "this change broke: …" with the repair act — and `act` and `act_batch` carry `beyondAsked(answer, { asked, label })`'s `text` and entries.
