A loopback store believes a seat only from its own page. `graview serve` on 127.0.0.1 believes the seat a request names in its headers, because only this machine reaches it — but a page on another origin in this machine's browser reaches it too, and every answer said `Access-Control-Allow-Origin: *`, the live wire took its seat from the upgrade's query, and `x-graview-kind: system` was read as the system's seat, which passes every policy and every sight. A page anywhere the browser would let reach loopback (another local dev server, a name rebound to 127.0.0.1) read the whole store, records the policy hides included, and wrote to it as the system. Now the loopback `graview serve` keeps to its own origin and host, as `graview preview` does (`ownOrigin`), on HTTP and on the live wire, and lets in only the origins `--allow-origin` names (`ServeOptions.allowOrigins`), at a host that is this machine. A store that keeps to its own origin names no origin but an allowed one in its CORS answer, echoed with `Vary: Origin`, in place of `*`. And a header names the system's seat only where the host says so: `trustSystemSeat` on the handler, `seatFromHeaders(request, { system })`, which `--trust-seat-headers` turns on; anywhere else `x-graview-kind: system` is read as a person's seat. `graview serve --trust-seat-headers` behind a trusted network believes every header as it did. The rota harnesses and `pnpm serve:rota` name the rota dev server's origin. `a-loopback-store-believes-a-seat-only-from-its-own-page.test.ts` holds it.

A program on this machine still reaches the loopback store as any seat but the system's: `graview mcp --remote-url` and `graview apply --remote-url` work as before, and `graview apply --template --remote-url` against a loopback `graview serve` runs as a person unless the server was started with `--trust-seat-headers`.

Compatibility: the wire — a loopback `graview serve` refuses 403 a request whose page is on another origin unless `--allow-origin` names it, answers no `Access-Control-Allow-Origin: *`, and reads `x-graview-kind: system` as a person's seat without `--trust-seat-headers`; `createStoreHandler({ trustSeatHeaders: true })` reads it as a person's seat unless `trustSystemSeat` is said. A host with its own `seatOf` is unchanged. Ops and primitives, stored formats, the declaration and check finding codes, derived tool names and input schemas — unchanged.
