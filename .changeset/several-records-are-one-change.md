Several records are chosen and acted on at once, as one change. Every act on a page was on one record, so marking six tasks done was six rounds and six undos. A kind's list on the pages, a kind's stop in the scene and a status board now choose records: a box at each row's start (on a desk, shown as the pointer or the keyboard reaches the row and always once one is chosen), Shift for a range, Cmd/Ctrl-A for the list, Space on a row, Escape to put the choice down, and on a phone a long press, after which a tap chooses rather than opens. A bar over the face, fetched with the first one chosen, says "6 tasks chosen" to a screen reader as it changes and offers the acts every chosen record shares — the derivation's own, in its order, with "Move to Declined" for the kind's state field and archive, merge and remove behind More — asks an act's questions once for all of them, and runs it as one batch with one undo, attributed as any act is. A record the act may not run on — the policy, the seat's sight, the act's own refusal — is named with why and stays chosen, and the rest are done: each record is judged first, without being told to anybody, and the batch is all-or-nothing only when the store refuses it whole after that (a served store's server), which the bar says ("None of it was kept"). `actsForSeveral` and `actOnSeveral` are on `@graview/tools/several` (and `@graview/tools`), and a seat does the same with `act_on_several` (`{ act, records, args }`), which answers the batch, the records changed, those already so and those refused. The hosted page carries 33 bytes more up front (22 gzipped): the names the first chunk now exports to the bar's chunk.

Compatibility: derived tool names and input schemas — one tool is added, `act_on_several`, listed for every seat that is not read-only, so the surface's hash moves; every act's tool and every other tool is unchanged. `@graview/tools` gains the `./several` entry; `AnswerArgs` takes an optional `store`.
