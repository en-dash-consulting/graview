Who may tidy an app's views when the host says nothing is judged as the store judges an act. `keepsTheApp`, the default gate of `/graview/views`, matched the seat's own roles against the grants, so an agent acting for a reader with a keeper's roles of its own, and a declared provider whose `may` lets it do nothing, could hide, delete and restore every view for everybody while the store refused them every act. Now an agent acting for a person is judged by the roles the two share (`actingAs`), and a declared provider keeps the app only where its `may` leaves no act out, whether the app is administered, has a policy or has neither. Ship's views test holds that both agents are refused 403 while the keeper, and an agent acting for the keeper, still tidy.

Compatibility: ops and primitives, stored formats, the declaration and derived tool names and input schemas — unchanged. The wire — `/graview/views` refuses (403) an agent acting for a person who does not keep the app, and a declared provider whose `may` leaves an act out, where a host passes no `mayTidyViews`; a host that passes one decides as before.
