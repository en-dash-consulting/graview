An act may ask for a record that can be left out, and links it only when one is chosen. A Thanksgiving app's "Add a dish" made the dish and connected it to `$to`, the household bringing it, so the household had to be chosen; `"to": { "required": false }` was refused for saying no `type`, and `{ "type": "string", "required": false }` drew a text box and, left empty, refused the act and its preview with 'there is no record ""'. An argument of an act's `args` that names a record (one an effect's `from`, `to`, `target` or `remove` reads) may now be declared with no type: `{ "required": false }` asks for it with a picker of the relation's kinds that has an empty choice, every other field drawn as before (a photo is still an upload); `{ "required": true }`, or nothing, asks for one as before; a `description` is the question the picker and an agent's tool schema ask. Left empty, the effects that read it are skipped, so the dish is made and linked to no household; chosen, it is linked. An argument declared with a type keeps its type, and left out, the link or change it would have named is skipped too rather than refused. An argument that is neither shape is refused as `arg-shape`, naming both; one with a type is told what is wrong with it as a field (`acts.<act>.args.<arg>.type`). Held by a unit test of core (`an-optional-record-argument-is-a-picker-and-links-only-when-chosen`).

Compatibility: the declaration and check finding codes — additive: an act's `args` takes `{ "required"?, "description"? }` with no type for an argument naming a record, and a new finding code `arg-shape` refuses an argument of neither shape, where the compiler said "Invalid input"; an act whose optional argument was left out applies, skipping the effect that read it, where it was refused. Ops and primitives, stored formats, the wire, and derived tool names and input schemas — unchanged. What Graview Cloud does: nothing; an agent may now declare a record argument that can be left out.
