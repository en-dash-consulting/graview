A worker view reads today from graview, a view that pins a day is said as a problem, and a change names the places that show it, Roadmap f-views-know-today. A chat added records to a Cloud app with act_batch and every act succeeded, but the app's home view had `TODAY = "2026-11-01"`, "Tomorrow · Mon 2 Nov", "due Fri 30 Oct" and a "What's next" list written into its source, so it went on showing the day before. Nothing told the agent, so it reported done. The description of the place also said each row's title two or three times when the row had a button, so a correct drawing read as a broken one.

A view's props now carry `today`, the app's today as its rules read it: a pinned day where the store is pinned, otherwise the date in the app's time zone. The `graview` global gains `graview.today` and `graview.fromToday(day)`, which says a day or an instant against today in the words a record's page uses: "today", "tomorrow", "yesterday", "in 3 days", "2 weeks ago", and with `{ due: true }` a past day is "overdue". `datesPinned(source, { today, title })` on `@graview/core/revisions` reads a view's source for a date given to a name that means today, today's words beside a written date, and a written date that passed within the last month. It says each one in a sentence: "Home may be out of date: it says “Tomorrow · Mon 2 Nov” and today is Mon, Nov 2. Read today from graview instead." A date handed to `graview.fromToday` is not counted. `runWorkerViewHeadless`, which `graview view check` and a host's view check run, now lists these sentences among its problems. `placesTouched(app, ops, { kindOf, views, today })`, also on `/revisions`, takes a commit's ops and names the places that draw the records it made, changed, removed or linked: the home, a lens, a kind's list, a view the host keeps. It returns them in the app's order with "These appear on Home and Tasks.", and names each touched place a script view draws, with the dates that view pins. In a place's description, a row's title is said once: a link inside the row to the row's own record joins the row, and a line or a button that repeats the title keeps only its other words ("Ann", "Open"). The instructions `graview mcp` gives an agent now tell it to read the home with describe_place after changing records. The graview-locale skill says to read today rather than write it, and to look at the places a change touches; graview-worker-view points to it. Tests: `a-view-that-pins-today-is-said-and-a-change-names-where-it-shows` (core), `a-view-reads-today-from-graview` (guest), the MCP instructions in `an-agent-attaches-with-a-shell`, and a new `drawn` harness claim, `aViewReadingTodayDrawsTheRightRelativeDay`. The worker view's runtime grows by 1.2 KB (0.5 KB gzipped), which every face and the guest host drawing a worker view carry, and Cloud's worker by 9 KB, under raises of those budgets (`scripts/budget-raises/views-know-today-*.json`). A hosted page's first load is unchanged.

Compatibility: ops and primitives — unchanged. Stored formats — unchanged. The wire — additive: `GuestProps.today` is pushed to every worker view, and a view written before ignores it. The declaration and check finding codes — unchanged; the pinned-date sentences are problems of a headless run, not check findings. Derived tool names and input schemas — unchanged.

What Graview Cloud does: get_problems and open_app carry the "may be out of date" problems wherever they run a kept view headless, or call `datesPinned` on its source with the app's today. act and act_batch can carry `placesTouched(app, ops, { kindOf, views, today }).text` in their answers, so an agent is told "these appear on Home" and to look at a view that writes its own dates.
