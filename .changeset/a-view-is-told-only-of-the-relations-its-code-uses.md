A view is told to read only the relations its code uses (Roadmap f-reads-edges-warning). Graview Cloud warned every view that read two kinds to add each relation joining them to `reads.edges` — every season, game and era view was told to read eras, coachedBy and homeField, though it drew every link it used — since a manifest's `reads.kinds` hands a view records and only `reads.edges` the links between them. The warning was Cloud's own (`unreadEdgesSentence`), so the framework now says it, narrower: `unreadEdges(store, manifest, source)` on `@graview/guest/host/views` names a relation only when it joins two kinds the view is handed, its manifest does not read it, and its code names it as a quoted string (`"coachedBy"`, `'coachedBy'`, `` `coachedBy` ``); `unreadEdgesSentence` says it, with what to add, or nothing. A view whose code names no unread relation is told nothing. Guest's test holds a seasons view told nothing while its code walks only the relation it reads, told of exactly the two relations its code names and does not read, and never of a word that only contains a relation's name or of a relation to a kind it is not handed.

Compatibility: ops and primitives, stored formats, the wire, the declaration and check finding codes, derived tool names and input schemas — unchanged. Additive on `@graview/guest/host/views` (`unreadEdges`, `unreadEdgesSentence`). What Graview Cloud does: in propose_view's answer and get_problems' view problems, calls `unreadEdgesSentence(app.store, manifest, source)` in place of its own, which needs the view's source in get_problems as well.
