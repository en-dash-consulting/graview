A worker view's own accessible controls are held to drawing alike on the page and in a headless run, states and all. Roadmap `feature:views-aria-checked-on-a-span-makes-the-browser-fall-back-to-the-plain-list-while-the-headless-run-passes`, filed from Threat Watch by Graview Cloud: a `<span class="box" role="checkbox" aria-checked="true">` ran headless ("It runs") and the page drew the kind's own list in its place until `aria-checked` came out. The open kit has taken every `aria-*` attribute and every role but the app's chrome's and notices' since it was made, and the page and the run draw through the one renderer and judge (`host/open-render.ts`, `host/open-judge.ts`), the page into a document and the run into a tree of plain objects; what is new is that this is held, and in a real browser. On this version the filed markup draws, ticks and is spoken in Chromium, WebKit and Firefox, so the stop Threat Watch saw is not in the drawing: a kept view that fails is replaced by the kind's own face and says why only through the definition's `onFailure (reason, detail)`, which is where the host learns it.

`guest`'s tests send a view's records for a checkbox, a mixed one, a switch, a pressed toggle, a disclosure with `aria-controls`, a tab list and its panel, a radio group, a slider, a progress bar, a current link, a listbox with an active descendant, a tree item, a menu item checkbox, a sorted grid, a field with an error message and a polite live text through the view's own runtime, and find every state and property and every role kept on the page; the run's tree the same element for element and attribute for attribute; the app's notices and chrome (`role="alert"`, `role="status"`, `aria-live="assertive"`, a named section) refused alike on both sides and said as problems; and the view run headless with none. `guest-sandbox --transport=open` draws Threat Watch's checkbox beside a switch, a toggle, a disclosure, tabs, a radio group and a slider in Chromium, WebKit and Firefox: drawn as the view drew it, never stopped or replaced, its `[aria-checked=true]` rule styling it; each control said with its state in the engine's accessibility tree; a press ticking it again; and the same view run headless drawing attribute for attribute what the page drew. The `graview-view-drawing` skill and the guest README say how to build such a control.

Compatibility: no change to the wire, the stored formats or the API; what the open kit draws is as it was.
