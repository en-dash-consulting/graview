A drop reads when the host says each file was made (FR-195). Roadmap f-drop-reads-upload-at, from Graview Cloud: its `POST /graview/files` answers a photograph with `at`, the instant it read from the file's EXIF, and a view's drop (FR-193) never read it. A required time a drop fills — a moment's `takenAt`, a detection's day — came from the file's `lastModified`, which a copy off the camera, a download or a sync sets to the moment it happened, so three photographs taken on Saturday and dropped on Monday were three moments on Monday. Now `FileValue` takes `at`, an ISO date and time with a `Z` or an offset (`fileAt` from `@graview/core` reads one; `isFileValue` refuses anything else there, and a drop leaves off an `at` it cannot read, EXIF's own `2026:10:17 09:12:00` say, rather than refuse the file), and a drop fills a required time from the stored value's `at` first, then the file's `lastModified`, then the drop's own time in the record a drop makes by default; an instant with an offset fills an argument that takes one as it was said, and one that takes only UTC or a day as that. `event.files` in a view's `drop` carries the stored `at` where the host said one. A record keeps the `at` its host answered, as it keeps a picture's size. The guest-sandbox drop harness proves the three photographs land at Saturday's times. A hosted page's first load carries 0.2 KB more (0.1 KB gzipped), the file value's `at` read where a record's file is judged; the embed's faces and the guest host carry the same. `capabilities().shipped` gains FR-195.

Compatibility: ops and stored formats are unchanged; a file value that kept no `at` reads as it did, and one with an `at` that is not a date and time is refused where it was ignored before. The declaration is unchanged. The wire: a `dom-event` `drop`'s `files[].at` is the host's stored `at` where it answered one, else the file's last change as before; `capabilities().shipped` lists FR-195. Derived tools: a file argument's schema gains an optional `at`. What Graview Cloud does: keep answering `at` from the files route's upload, as an ISO instant with a `Z` or an offset; nothing else.
