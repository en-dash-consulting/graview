On the one face, a view drawn where the page cannot read has its lines to the city. At Nearby a built-in page draws a line from each record it shows to that record's building; a worker view (drawn in a shadow root) and a frame guest (a document on another origin) drew none, so a page made of them floated beside the city tied to nothing. Now each element a view marks with `data-record`, the mark a link to a record already is, has its line, leaving from the element as it is drawn in that frame, exact while the page scrolls and as it moves a level. A worker view's host measures them when the face asks; a frame guest's client (`GraviewGuest.connect`, `@graview/guest/client.js`) says where its records are over the port as they move (`records`), and the frame's host keeps only what is inside the frame and names a record the seat may see. A record page drawn by a view that marks nothing still has one line, from the view to its record, and the Connected list no longer repeats what a view shows. The element a view is drawn in holds the boxes under `RECORD_BOXES` (`@graview/core/record-boxes`), for any face that draws lines. The `graview-view-links` skill says what draws a line.

Compatibility: the look is unchanged except where the one face (`sceneUnderPages`) draws a worker view or a frame guest, which now has lines. The JavaScript API is additive (`RECORD_BOXES`, `RecordBox`, `judgeRecordBoxes`, `holdRecordBoxes`, `recordBoxesOf`, `recordBoxesMoved` on `@graview/core/record-boxes`, a new entry; `GuestHostOptions.onRecords`, `GuestLimiter.records` on the guest host, `GuestRecordBox` on `@graview/guest`). Ops and primitives are unchanged. Stored formats are unchanged. The wire is additive: a frame guest may send `{ type: "records", nonce, boxes }`, which a host that draws no lines drops unread, within an allowance of its own beside the frame's messages. The declaration and check finding codes are unchanged. Derived tool names and input schemas are unchanged.
