The build is the socket's, and a host numbers its own protocol. `liveProtocol({ build })` was one string for every socket, but Graview Cloud learns the build per upgrade — the worker that carried the socket says which shell it serves. Now `live.open(seat, via, { build })` keeps the host's build in the socket's state as `hostBuild`, which survives a hibernation and is said in that socket's welcome, and `build` may be a function of the socket, `(peer) => string | undefined`; a route answers with its request's `build` (`WireAsked`), else the protocol's. And a host that changes its own half of the wire — its routing, its auth, its shell — had no way to send an old page `reload` with its unsent calls carried: `minProtocol` judges ship's `WIRE_PROTOCOL`, which a host does not move. `openRemote({ hostProtocol })` now says the host's own number in `hello.hostProtocol`, and `liveProtocol({ minHostProtocol })` (and `createStoreHandler`'s) answers a hello below it — absent is 0 — with `reload` carrying `hostProtocol`, which `openRemote` handles as any reload: the page reloads and offers its calls again. `hello.protocol` stays `WIRE_PROTOCOL`.

Compatibility: the live protocol — additive: `hello` gains an optional `hostProtocol`, `reload` an optional `hostProtocol`, `LiveSocketState` an optional `hostBuild`, `LiveProtocolOptions` `minHostProtocol` and a function form of `build`, `open` an optional third argument, `RemoteOptions` `hostProtocol` and `createStoreHandler` `minHostProtocol`. A server without `minHostProtocol` serves every page as before; one with it sends `reload` to every page that does not say a `hostProtocol` at or above it, so a host turns it on with the build that starts saying one. `WIRE_PROTOCOL`, `REFUSAL_REASONS`, ops, stored formats and check codes are unchanged.
