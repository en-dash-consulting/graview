A question about a plan alone is asked of an empty store, and `planFrom` says so. A product's review asked what goes with a declined line of a plan (`dependentsOf`, `without`) of an object shaped like part of a store, with its acts and its policy and no graph; `planFrom` has read the store's graph since a plan's name equal to a record's id was refused, and that object stopped working then. The store a plan is made over is a real one: for a question about the plan alone, the app's own store made with nothing in it, which orders, judges and cascades a plan exactly as a store full of records does. `planFrom`'s documentation now says this. Held by a unit test of the tools (`a-plan-alone-is-asked-of-an-empty-store`).

Compatibility: ops and primitives, stored formats, the wire, the declaration and check finding codes, and derived tool names and input schemas — unchanged. The JavaScript API is unchanged. What a product does: make the store a plan-only question is asked of with its own store factory and no records, never a cast stub.
