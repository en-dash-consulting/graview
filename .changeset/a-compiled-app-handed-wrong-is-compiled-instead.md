A compiled app handed wrong is compiled instead (FR-123). `appFrom` threw out of the page when a compiled app said the right format but was torn on its way — an act's plan that was not there, relations that were not pairs, a kind with no fields — so `appFromOrCompile` never reached its fallback; it now refuses one as `compiled-shape`, and the page compiles the document. And `appFromOrCompile` built whatever compiled app it was handed, even one compiled from an earlier version of the document handed beside it, so a host whose cache lagged ran yesterday's acts in the page. It now builds one only when its document is the one handed, by canonical text (`canonicalize`), and compiles the document otherwise; a host hands the document a compiled app was made from, as it stands in the current document format. A test hands it each of these, and holds that names such as `__proto__` and `constructor` in a compiled app reach no object's prototype. The ship skill says a compiled app is built only beside the document it was made from. The check costs the handed page about 1 KB: it loads 513.9 KB up front, against its 520 KB budget (557.7 KB compiling in the page).

Compatibility: additive. A compiled app `appFrom` built before is built the same; one it threw on is refused as `compiled-shape`, and one handed beside another document is compiled in the page. The compiled-app format, ops, stored formats, the document format, wire messages, check codes and tool schemas are unchanged.
