The starter reads a template as a person would and composes from its whole reading, and the app's own tidying has an edit, Roadmap request:starting-document-drops-rules-and-views, request:starter-readme-excerpt-without-markdown, request:read-starter-keeps-fit-precision, request:still-unmet-takes-traits and request:edit-op-for-app-tidying. Five things Graview Cloud's starter and chats had been doing for themselves.

A kinda turn asks about a template's kinds, rules and views alike, and `readStarter` reads back the ones to drop as `StarterPart`s, but `startingDocument`'s `drop` took only kinds and traits by name, so Cloud removed the unticked rules and views itself. `drop` now takes a `DropPart` (`{ part: "kind" | "rule" | "lens" | "trait", name }`, on `@graview/core/compose`) beside a bare name, so a `KindaReading`'s `drop` goes in as it comes: a rule by its name, a view by its title, each said in `left`, kept out of `took` and one of the `edits` that make the same document from the base (`remove-rule`, `remove-lens`); a rule or view the base lacks is said and changes nothing. `composeReshape` takes the same. `a-starting-document-drops-the-rules-and-views-a-person-unticked.test.ts` holds it.

A template's README went to the model as its first 280 characters raw — `# Title`, badges and markdown. `about` now starts at the first plain sentence, with the markdown taken out (a link said as its words, emphasis and code as their text, a list item as its line, a table, an image and a code block left out) and is cut at a word (`readmeExcerpt` on `@graview/tools/starter`). A fit's `level` was the score rounded to two decimals and then scaled, which put levels on 0.04 steps (3.1 read as 3.12); it is now the expected level itself, rounded once (`expectedLevelOf` beside `scoreOf`), and ranking reads it first. `stillUnmet` takes the traits themselves (`readonly TraitName[]`) as well as a reading. `the-starter-reads-a-template-as-a-person-would.test.ts` holds each.

`set-tidying` covers a kind or a relation, so a chat set `tidying.autoAcceptAt` at the top of a document with a JSON Patch. The edit vocabulary gains `set-app-tidying` (`{ autoAcceptAt: n | null }`, 1 to 10,000; null takes it away and leaves no empty `tidying`), said in a sentence ("The app makes a suggestion on its own once 4 people vote for it.") that `diffDocuments` says of the same change. `the-app-says-when-a-suggestion-is-made-by-an-edit.test.ts` holds it, and the tidying skill names the edit.

The new edit and its sentences cost Cloud's worker 2.0 KB (2_018 bytes), every face 0.2 KB gzipped (250 bytes, 177 measured) and the embed with the studio handed in 0.3 KB gzipped (300 bytes, 219 measured), each under a raise in `scripts/budget-raises/the-starter-and-app-tidying-*.json`; a hosted page's first load is unmoved.

Compatibility: ops and primitives — unchanged. Stored formats — unchanged. The wire — unchanged. The declaration and check finding codes — no shape or code changes; the edit vocabulary gains `set-app-tidying`, which a build before this one refuses as an edit it does not know. Derived tool names and input schemas — unchanged; the starter's state says a template's `about` as plain prose and a ranked template's `level` to the hundredth of a level. What Graview Cloud does: hands a kinda reading's `drop` to `startingDocument` and stops removing unticked rules and views itself; drops its own README cleanup; and has a chat set `autoAcceptAt` with `set-app-tidying` rather than a JSON Patch.
