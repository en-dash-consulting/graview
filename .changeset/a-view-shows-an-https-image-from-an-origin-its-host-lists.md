A worker view shows an `https:` image from an origin its host lists. An artwork whose picture was a Wikimedia address drew nothing in a view, because a view loads nothing the host has not made or holds; the only way round it was a `data:` image in a text field, which is cut at 20,000 characters. A host now lists the origins a view's images may come from — `images: { origins: ["https://upload.wikimedia.org"] }` on `mountWorkerView`, on a registered worker view's definition, and on `runWorkerViewHeadless` — and an image there is drawn as the view gave it, asked for with no referrer (`referrerpolicy="no-referrer"`, set on every `img` before its source), so the origin learns nothing of the page it is drawn on. An allow-list rather than an image proxy, because a proxy fetches whatever address a view hands it from the host's own server, and an address is data a view writes: it would carry what the view reads to any origin through the host, and to the host's network besides. With a list the view never chooses an origin, nothing is fetched on the host's side, and a list entry that is not an `https:` origin, an `http:` address and one with a password in it are refused. Any other address is refused as before, and now said once, in the view's console and to the host's `onProblem`: "The image "https://collector.example/c.png" was not drawn. Its origin is not one the host lists for images (https://upload.wikimedia.org). A view shows a data: image, the app's own image (/graview/assets/…), a picture on a record (pictures in its manifest), or an https: image on an origin the host lists (images.origins)." A headless run says the same. A picture the app holds belongs in an `image` field, which keeps the uploaded file (what `add_image` stores, `/graview/assets/<sha256>.<ext>`) and a view draws by that path. The graview-view-drawing skill teaches it, and the guest harness holds it in a browser.

Compatibility: ops, stored records and the declaration are unchanged. The guest wire is unchanged; a headless run's input carries `imageOrigins` beside its places. `mountWorkerView`, `WorkerViewDefinition` and `runWorkerViewHeadless` take `images?: { origins: readonly string[] }`, none by default, so no view loads anything it did not before. `OpenRefusal` may carry the `address` an image asked for, the open renderer and drawing take `imageOrigins` and `onRefused`, and `imageRefusedWords(address, origins)` and `imageOriginsOf(list)` are new beside `judgeAttribute`.
