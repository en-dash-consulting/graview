A workflow's step may read and write another app (Roadmap f-workflow-steps-in-another-app). Until now a step could only read the app's own kinds and call its own acts, so a sync that reads HQ and writes Graview Public could not be a built-in workflow: an agent step offered `@self/graview-public/set-ticket-status` was refused as "not an act of this app". An agent step's `reads` and `acts`, and an act step's `act`, now take another app's kind or act written the way a relation to another app's kind already names one — `@`, the app's address, `/`, the name: `"@self/graview-public/ticket"`, `"@self/graview-public/set-ticket-status"`.

The checker cannot see the other app, so it holds such a name to its shape, and refuses one that is not `@<address>/<name>` as `workflow-far-reference`. A host that knows the other apps hands it a resolver — `resolveFarApp(address)` answering `{ name, kinds, acts: { <act>: { title, description, input } } }`, on `compileDocument`, `editDocument`, `documentWorkflowFindings` and `workflowFindings` — and the checker then refuses an app it does not know (`workflow-far-app-unknown`), a kind or act that app lacks (`workflow-kind-unknown`, `workflow-act-unknown`, as for this app's), and an argument an act step hands that the far act does not take or one it requires left out (`workflow-far-args`). `workflowsOf` says what a workflow `reaches` in other apps beside the kinds it reads and writes here, and a step's sentence names the app.

`runWorkflow` reaches another app only through the host's `farApps` — `otherApp(address, origin)` answering `{ shape, read(kind, { limit }), act(call) }`, or nothing when this workflow may not reach that app — as the workflow's own actor. It never writes into another app's store itself. A dry run asks that app to preview, and lists each far act on the run's `far`, naming the app, with "nothing was kept there"; a real run has the act made there with the run's lineage (`run`, `actor`, `key`, `model`, `confidence`), so that app's log says which workflow's run made it and `workflowOrigin` reads it; `approve: "ask"` or an unsure `suggest` puts it in that app's Suggested tray. An agent step is shown the far records its host lets it read and offered the far acts with the input schemas its host says. A host with no `farApps` refuses the step in words: "this host does not let workflows reach other apps". `farAppsOver({ "@self/graview-public": { store, name, reaches } })` is that host over stores in memory, and `farAppShapeOf(store)` says an app as the resolver answers it. The `graview-workflows` skill says how.

Compatibility: ops and primitives — unchanged; a far act's op is made by the far app's host, with the lineage keys an op already keeps. Stored formats — a document's workflow step may now hold a name beginning "@" in `reads`, `acts` and `act`, which an older build refuses as `workflow-shape`; a kept `WorkflowRun` gains an optional `far`, absent on runs that reached no other app, so runs kept before read as before. The wire — unchanged. The declaration and check finding codes — new: `workflow-far-reference`, `workflow-far-app-unknown`, `workflow-far-args`; `workflow-kind-unknown` and `workflow-act-unknown` also name a far kind or act the resolver says is missing, and their fix now says another app's name may be written `@<address>/<name>`; nothing that passed before is refused. Derived tool names and input schemas — unchanged; an agent step's model is offered a far act under its whole name (`@self/graview-public/set-ticket-status`) with the input schema the far host says.

What Graview Cloud does: implement `FarApps` over its workspaces and grants — `otherApp(address, origin)` returning the app as `origin.author` may reach it, reading as that actor, running each act with `call.lineage` on its op and logging it as from `origin.workflow` — and pass it as `farApps` to `runWorkflow` and `seatWorkflows`; pass `resolveFarApp` to `editDocument` and `compileDocument` so a preview refuses what the other app lacks.
