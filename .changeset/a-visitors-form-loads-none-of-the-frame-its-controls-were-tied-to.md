A visitor's form loads none of the frame its field controls were tied to. The doors to a field's own controls (`@graview/primitives/form`: a file, a linked record, a repeat, a day and a time, and the day picker the time field opens) each imported `@graview/primitives/frame`, the barrel a routed page draws first, so that the files every door reaches are one chunk (TIED DOORS). A visitor's form fetches those doors and never draws that barrel, so every part of a module both reach that only the frame's files use went into the form's first load: about 41 KB of the lenses' places, the popover, the theme's marks and ground and the view state, and with 0.2.12's map lens, file previews and record times it came to 401,808 B minified, over the 400,000 B a visitor's form handed a compiled app is held to. The form's doors are tied to `@graview/react/provider` instead, which every page that draws a form drew first: that form now loads 360,181 B first (130,053 B gzipped, from 146,852 B), a visitor's form alone 266,644 B (from 309,942 B), and a hosted page loads the same bytes in the same 13 chunks as before. Nothing a form draws or does changes. Held by the embed's budget test (`loads a visitor's form handed a compiled app under 400 KB first`) and the hosted page's (`loads at most 13 chunks before it draws`).

Compatibility: the look — unchanged. The JavaScript API — unchanged; no name moves. Ops and primitives — unchanged; a form's controls are split into a page's chunks differently. Stored formats — unchanged. The wire — unchanged. The declaration and check finding codes — unchanged. Derived tool names and input schemas — unchanged.
