Text is typed together: the second phase of collaborative text, the act and its rules, with no wire or editor yet. Whether two people may type into a field at once is the declaration's, never the value's: `isCollaborativeField` says a Markdown field, a document's `text` and a string declared to hold more than 500 characters are, a short string is not, and `markCollaborative(schema, on)` says otherwise; a document's field says `"collaborative": true | false`, which only a text or string field takes (the checker's error `field-collaborative`), `toDocument` writes where a declaration marked a field against its type's default, and `graview describe` lists. The act and its merging are `@graview/core/typing`'s, a new entry: an app opens far more often than somebody types into a long field, so a page carries only the store's hooks for it, `@graview/ship`'s server and runtime entries load it, and a face loads it once a field typed together is focused (phase 4). Loaded, every store answers to the built-in act `type-text` (`TYPE_TEXT`, `{ node, field, at, remove, insert, rev? }`) — a store made before it loaded too — and no list of acts offers it, as `keep-link` is: it is permitted to whoever may run an act that writes that field of that record — a declared act whose `writes` names it, or the kind's `edit-<kind>` and what that rides — judged under the caller's sight. The store reads the field's text at revision `rev` back off the log and carries the keystroke over every splice taken since, writing one `splice-text`; the first keystroke into a field with no text yet writes the text it inserts whole, as a patch, so its inverse is exact, and the keystrokes after it splice. A field kept from the caller reads to it as holding no text, so its keystroke is a whole write, which field sight refuses as an argument the act does not take, alike whatever the field holds. It refuses as `invalid` a field that is not typed together, offsets the text did not have, and a keystroke against text written whole since. A whole value written over a field typed together — by any act, an edit, an agent or `applyPrimitives` — is written as the one splice that makes the change: against the text at the revision `ApplyOptions.base` names for the field, a three-way merge, so an agent's rewrite merges with somebody typing; without one, against the text now. A splice claims no base, so `FieldRevisions.baseFor(ops, skip, collaborative)` skips a field typed together and `openRemote` passes `store.collaborative`; a stale write is a conflict only for a field that is not. Undo carries a person's splices back over the splices of the same field since (`undoneInverses`, and `undoPrimitives(ops, log)` for a preview): a later splice on that field no longer blocks it, text somebody else deleted since shrinks out of what it takes back, and a later whole write or the record's removal still blocks it; redo is the undo of the undo. Without `@graview/core/typing` a store answers to no `type-text`, writes a whole value as written and lets a later splice block an undo, as before. A splice over a field's `max` is refused `invalid`, and `required` is judged on the text that results. Core's tests hold that an agent's whole write merges with concurrent typing, that undo out of order takes back only that person's run, that a kept field is refused alike whatever it held, that the first keystroke into an empty field is a patch and then splices, `max` and `required`, that a field not typed together refuses `type-text`, that a document field's `collaborative` key compiles and checks, and that the main entry merges nothing until the entry is loaded. Only the store's hooks are on every page: 1.1 KB more up front on a hosted page and on one handed a compiled app, and on the pages face alone and on a visitor's form alone, under raises of those budgets (`scripts/budget-raises/text-is-typed-together-*.json`), and the scene face's limit before it draws moves to 983 KB.

Compatibility: ops and primitives — additive: no primitive and no op field is added; a log a store with `@graview/core/typing` writes holds a `splice-text` where an earlier build wrote a `patch-node` of a whole value over a field typed together, and folds to the same graph, on any build since op format 3. Undo of typing is allowed where a later splice of the same field blocked it before. The declaration and check finding codes — additive: `"collaborative"` is a new optional key on a document's field, refused by path by a build before it, and `field-collaborative` is a new error only for that key on a field that is neither text nor string. The wire — unchanged in shape: `openRemote` no longer claims a revision of a field typed together in a call's `base`, so a server never refuses a keystroke or a merged whole write as stale; a server that still compares one an older client claims refuses as before. Derived tool names and input schemas — unchanged: `type-text` is offered by no list, so no tool names it. What Graview Cloud does: takes this build with phase 1's; its worker loads `@graview/core/typing` through `@graview/ship/runtime`, which its import budget is to take.
