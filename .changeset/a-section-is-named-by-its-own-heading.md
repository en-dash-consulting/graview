A worker view's section is named by its own heading (FR-219), Roadmap f-view-labelledby. `<section aria-labelledby="ls-h"><h2 id="ls-h">Drivers</h2>` is how a page says what a section is about, and the open kit refused it ("Not drawn: <section> does not take aria-labelledby.") with the section's own words, since a named section is a region landmark. A name read from a heading the view drew is the view's, so `aria-labelledby` and `aria-describedby` are now drawn on any element while every id they name is an element of the view's own drawing — judged as each batch ends, so the heading may come after the section, and the view's ids are its own in the shadow root it is drawn in, so none is rewritten. One that names an id the view does not draw is held back and said: `Not drawn: <section> aria-labelledby names "missing", which is no element of this view. It names elements the view draws itself, by their id (<h2 id="…">), drawn once each is there.`; it is drawn once that element is, and taken back if it goes. A section's `aria-label` and `title` stay refused, and `role="region"` named by an id that names nothing is held back as an unnamed one is. Guest's test draws a section labeled by the heading after it, keeps the attribute pointing at the heading, and refuses one naming a missing id. With FR-220 and FR-221 beside it, the guest host drawing a worker view on the open kit carries 2,402 bytes more minified (917 gzipped), registering a worker view 1,076 (384), and every face some 950 bytes more gzipped, each under a raise of its budget (`scripts/budget-raises/views-name-sections-choose-pictures-*.json`); a hosted page's first load is unchanged. `capabilities().shipped` gains FR-219.

Compatibility: ops and primitives, stored formats, the declaration and derived tool names and input schemas — unchanged. The wire — additive: an open-kit refusal may have the reason `reference` with the `ids` it named; `capabilities().shipped` gains FR-219. A view that pointed `aria-labelledby` or `aria-describedby` at an id it never drew loses the attribute where it kept it before (it named nothing in the shadow root either way). What Graview Cloud does: takes this build; its views may label a section by its heading.
