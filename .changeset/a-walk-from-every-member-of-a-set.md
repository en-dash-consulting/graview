A walk from every member of a set (FR-101). `out(S, 'edge')` and `in(S, 'edge')` walk a relation from each record of a set and give every record they reach once, in the order first reached; `out('edge')` still walks from the record itself. Sets meet with `&`, join with `|` and part with `-` (between numbers `-` still subtracts), binding tighter than a comparison, so LifeLogics' coverage meter is one declared figure on a package's card: `count(out(out('includes'), 'answers') & out(first(all('party') where role == 'client'), 'needs'))`, "3 of the 5 things they need, answered". Every step reads the graph the seat is served, so an offer a seat may not see answers nothing and a need it may not see is not counted. A walk costs what the set it walks from costs, so the check's cost degree is unchanged (a walk chain over a sweep inside a sweep inside a sweep is still `computed-cost`, an error), and at run time each member walked and each record reached spends from the expression's budget. The check holds a walk's relation to the declared ones (`view-edge`) and a list walking from a set to the kinds it reaches; a rename of a relation rewrites it where a walk from a set names it. Inside a template's braces a `|` within brackets is a join, and the formatter's bar is the last one outside them. The `graview-invariant` skill says the walk and the set operators. `capabilities().shipped` names FR-101.

Compatibility: additive within `graview-document@1`. `out` and `in` take an optional set before the relation, and `&`, `|` and `-` between sets are new to the rule language; an expression that parsed before means what it meant, except that a bar inside brackets in a template's braces (`{count(a | b)}`), which was read as a formatter and refused, is now a join. `BinaryOp` gains `"&"` and `"|"`. The wire: `capabilities().shipped` gains `FR-101`. Ops, stored formats, check finding codes and tool schemas are unchanged.
