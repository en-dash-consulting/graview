A design reaches the router through `@graview/pages`, and the routed face runs on React Router 8. A product's design, page or test used to import `Link`, `useParams` and the rest from `react-router-dom`, a dependency of its own, so a second copy or another major than the one `PagesApp` mounts left the page asking a router that was never set. `@graview/pages` now exports `Link`, `NavLink`, `MemoryRouter`, `useLocation`, `useNavigate`, `useParams` and `useSearchParams` (with `LinkProps` and `NavLinkProps`), always the router the face put above them, and which router answers is the package's business alone. React Router 8 has no `react-router-dom`, so the face imports `react-router` and asks for React 19.2.7 or later. `graview create` no longer writes `react-router-dom` into a project, writes React `^19.2.7`, imports `useParams` from `@graview/pages` in `src/ui/pages.tsx`, and leaves the router out of a linked project's `dedupe`, since the only copy is the one `@graview/pages` brings. A linked project's tests take that copy through vite (`server.deps.inline`), so it holds the project's React rather than the checkout's, and a project's build sets aside the router's `"use client"` without saying so, so a first build says nothing about it. `graview doctor` says it is a problem when `react-router-dom` or `react-router` stands beside `@graview/pages`, with the fix, because a project that missed this has no other sign of it: `useParams` from its own copy answers `{}` with no error, so every record page says nothing lives at its address. The example apps and `@graview/ship`'s README say the same. Tests: `a-design-reaches-the-router-the-face-runs-on` (pages), the scaffold's `reaches the router through @graview/pages and never depends on it`, and doctor's `a router of a product's own`. The pages face alone and every face grow by 3,228 bytes minified and shrink by about 400 gzipped, under a raise of each budget (`scripts/budget-raises/pages-owns-the-router-pages-face.json`, `scripts/budget-raises/pages-owns-the-router-every-face.json`). A hosted page's first load is unchanged.

Compatibility: ops and primitives — unchanged. Stored formats — unchanged. The wire — unchanged. The declaration and check finding codes — unchanged. Derived tool names and input schemas — unchanged. `@graview/pages`, `@graview/embed` and `@graview/studio` ask for `react` and `react-dom` `>=19.2.7` where they asked for `>=18` (`@graview/pages` names `react-dom` for the first time). Every package and a new project ask for Node `>=22.22.0` where they asked for `>=22`, React Router 8's floor. A product that imports from `react-router-dom` must import the same names from `@graview/pages` instead and drop `react-router-dom` from its dependencies and its `dedupe`, or its record pages stop working with no error; `graview doctor` says so. A linked project whose tests draw a page also adds `test.server.deps.inline: ["react-router"]` to its vite config, or they fail with `Invalid hook call`.

What Graview Cloud does: nothing to change; it imports nothing from the router and runs React 19.3.
