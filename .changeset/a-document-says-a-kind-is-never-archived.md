A document can say a kind is never archived (FR-173). `defineNode({ archives: false })` gave a TypeScript kind no `archive-`, `unarchive-` or `merge-<kind>`, and a document had no way to say it, so a hosted app offered all three on every kind — a checklist's steps, an app's settings — whether setting one aside meant anything or not. `"archives": false` on a kind now says it: the compiled app gives that kind its edit and remove and none of the three, `toDocument` writes it from a declaration that says it, `describeApp` says "Steps are kept or removed, never archived or merged", and a grant naming one of the three on that kind is `grant-act`. `editDocument` gains `set-archives` (`{ kind, archives }`), which says what the app stops or starts offering — "Categories are kept or removed, never archived: the app no longer offers archive-category, unarchive-category or merge-category, …" — says the agent's tools moved, and is refused as `grant-unknown-mutation` while a grant names one of the three, naming the `remove-grant` to send first; the preview of a changed document says the same sentence. The studio holds it on a kind as "never archived", hands it back as `set-archives`, and writes it into the declaration it writes back. A record of the kind already archived is not left where nothing can bring it back: `planMigration` brings each back in the same op that lands the change and says so ("2 archived category records brought back, since category is now kept or removed, never archived.", `counts.broughtBack`), and `set-archives` says it will. Every other migration now keeps an archived record archived — it cleared the mark on every record it planned, and said nothing. The grant check is the checker's (`compileDocument`), not the page's: a hosted page's first load is 20 bytes gzipped more for all three of this wave's follow-ups, and the every-face and studio-handed-in budgets are raised by 2_431 / 760 and 2_431 / 740 bytes (scripts/budget-raises/what-the-0-1-29-wave-left-every-face.json, scripts/budget-raises/what-the-0-1-29-wave-left-studio.json).

Compatibility: the document format gains an optional `kinds.<kind>.archives` (only `false`) within `graview-document@1`; a document without it compiles to the same app. The edit vocabulary gains `set-archives`. Derived tools change only for a kind that says it: it has no `archive-`, `unarchive-` or `merge-<kind>`. `MigrationPlan.counts` gains `broughtBack`, and a migration keeps `$archived` on a record (it cleared it before). Check finding codes are unchanged (`grant-act` and `grant-unknown-mutation` read one more case).
