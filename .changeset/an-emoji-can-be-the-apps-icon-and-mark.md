An app can name one standard emoji as its page icon and, where it has no logo, its mark. A brand's icon was an SVG or a path, so an app somebody made in a chat had a blank tab and an empty corner of the bar until somebody drew it a picture. `brand.favicon` now also takes `{ emoji: "🏡" }`, in a TypeScript `Brand` and in a document alike: exactly one emoji as the reader sees it (Intl.Segmenter), and one of the standard emoji every emoji set draws (`RGI_Emoji`), so a skin tone, a joined emoji and a flag — 🏡, 👩🏽‍🌾, 🇺🇸 — are each one, and two emoji, letters or nothing are refused in words: `"🏡🏡" cannot be the app's icon, because it is 2 emoji, and a mark is one` (`brand-emoji`, at `brand.favicon.emoji`), from `compileDocument`, `graview check` on a declared app, and `editDocument`. `set-brand` takes `favicon: { emoji }` and says "The app's page icon and mark become 🏡." (or "The app's page icon becomes 🏡." when the app has a logo), and the preview of a changed document says the same sentence. Where the brand has no logo, `AppMark` draws the emoji as text on the app bar of both faces and in an embed, and the routed face's static pages put it in the masthead; with a logo, the logo is the mark and the emoji is only the icon. `faviconHref` makes the icon an SVG with the emoji as text, so a self-hosted app's tab shows it in the reader's own emoji font; a host that wants it alike on every system renders it from a bundled emoji set into icon PNGs and serves those instead, as Graview Cloud does. New from `@graview/core`: `emojiProblem`, `emojiMark`, `emojiOf`, `emojiSvg` and the `FaviconSpec` type. The graview-brand skill says it in two lines. The every-face and studio-handed-in budgets are raised by 2_385 / 795 and 2_409 / 920 bytes (scripts/budget-raises/an-emoji-as-the-apps-mark-every-face.json, scripts/budget-raises/an-emoji-as-the-apps-mark-studio.json); a hosted page's first load stays within its budget.

Compatibility: the document format's `brand.favicon` gains a second form, `{ "emoji": "<one standard emoji>" }`, within `graview-document@1`; a document with a string `favicon` compiles to the same app. The TypeScript `Brand.favicon` is now `FaviconSpec` (`string | { emoji: string }`), so code reading it as a string narrows first. `set-brand`'s `favicon` takes the same object. Check finding codes gain `brand-emoji`. Ops, stored formats, the wire and tool names are unchanged. What Graview Cloud does: render `brand.favicon.emoji` from its bundled emoji set into the icon PNGs it serves, and serve those rather than the framework's text SVG.
