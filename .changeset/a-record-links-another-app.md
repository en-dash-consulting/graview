A record can link another app, and the host says what that app is called (FR-171). A relation's `to` names kinds inside one document, so a scenario in one app could not point at a house in another. The first step is a field: `{ "type": "app-link" }` in a document, `appLinkField()` in a declaration, holding another app's address — `@owner/app`, an id its host knows it by, or an absolute http(s) address, at most 500 characters (`isAppAddress`). The store refuses anything else as `invalid`, `editDocument`'s `add-field` and `retype-field` take the type, a migration keeps a value that is an address and clears one that is not, a spreadsheet's cell is read as one or refused in words (FR-177), `graview types` writes it as a string said to be another app's address, a form asks for it with "@owner/app or https://…" as its placeholder, and an act's tool schema gives it the address's `pattern` and `"x-graview-app-link": true` so an agent sets an address rather than a name. A host hands `resolveApp(address, viewer)` to `mount`, `<Embed>`, `GraviewProvider` or the routed face's context, answering `{ name, icon?, headline?, href }`, `{ denied: true }` or `null`: the field draws as that app's icon, name and home headline, linked to `href`, on a record's page and in the scene's record panel, and as its icon and name on a list's row and a document card's field block. A viewer the host refuses sees "linked app (no access)" and nothing of the app. Without a resolver, or where the host knows no such app, the address is drawn as it is kept, a link only when it is an absolute http(s) address. The host is asked once per address and viewer, however many records link it, and a throw is taken as `null`. Where an act may write the field, a "Change" control beside the link edits the address. What draws it is a chunk fetched with the first app-link drawn: a hosted page's first load is 509 bytes larger (557 327 bytes over the vendors document, 556 818 on main), 501 handed a compiled app, and the scene before it draws 1 647, all under their budgets; the embed's pages face carries 1 884 / 1 607 bytes more minified / gzipped, every face 7 001 / 3 726, each raised by a file of its own. A relation whose `to` is another app's kind, an expression that walks it and the history of the far value are left for 0.2. `capabilities().shipped` gains FR-171.

Compatibility: additive. The document format gains the field type `app-link`, and `graview-compiled@1` carries it; a build that predates it refuses the type by path, and a page that predates it refuses such a compiled app as `compiled-shape` and compiles the document. `mount`, `<Embed>`, `GraviewProvider` and the routed face's context gain an optional `resolveApp`; `ReadableField` gains `app`, `ScalarField` gains `app`, and a document card's resolved field block gains `app`. A derived tool's input schema for a declaration with no app-link field is unchanged. What a host does: read `capabilities().shipped` for FR-171 before writing an `app-link` field, and pass `resolveApp` to have one drawn as the app rather than as its address.
