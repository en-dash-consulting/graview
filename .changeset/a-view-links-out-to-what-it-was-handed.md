A worker view links out to an address it was handed: a record's own `url`, its contact's `mailto:`, its `tel:`. Roadmap `feature:views-can-t-draw-an-external-link-even-to-a-record-s-own-url-field`, filed from Threat Watch by Graview Cloud: `<a href="https://…">` was refused ("<a> does not take href") and a record's URL drew as text. An `<a href>` is drawn now where its address — `https:`, `mailto:` or `tel:`, as the URL parser says it — is a value of a record the view was shown, and, where the host lists origins for links (`links: { origins: ["https://nvd.nist.gov"] }` on `mountWorkerView`, a registered view's definition and `runWorkerViewHeadless`), any `https:` address on one of them. The host draws every `<a>` to open in a new tab, `rel="noopener noreferrer"` and `referrerpolicy="no-referrer"`, set before its address and never the view's to change, so the page is never navigated, the tab it opens has no hold on it and is told nothing of it; and it marks a link out with an arrow after it whose alternative text, " (opens in a new tab)", is in the link's accessible name. A press on one is not also taken by the face around the view for a press on the card. Anything else — an address the view built, `javascript:`, `data:`, `http:`, a password in it — is drawn with no `href` and said once, in the view's console and to the host's problems: "The link "…" was not drawn: it is no address this view was handed. A view links out only to an address a record it was shown holds (a url field), as the record holds it; a record or a place of this app is <a data-record> or <a data-place>.", or that a view links only to an https:, mailto: or tel: address. A headless run judges a link by the same code over the records it showed the view, and says the same sentence among its problems.

Why handed and not any `https:` address: a view reads what the seat sees and can write any string, so a link it made is a way out of the app — `https://elsewhere.example/?d=` and whatever it read, one press away, however the link is dressed. An address the view was handed carries nothing it chose but which one it links. A list of origins is the host's choice for its place, as `images.origins` is; a manifest cannot widen it, since the manifest is the view author's own word.

`guest`'s tests draw, on a page, a record's `https:` url, `mailto:` and `tel:` as links opening in a new tab with no opener and no referrer; refuse the handed url with what the view read added, an address elsewhere, an unlisted origin, `javascript:`, `data:` and `http:`, each said in its sentence; draw any `https:` address on a listed origin and no other; and find a headless run saying exactly the page's sentences. `guest-sandbox --transport=open` draws a view's links to the car's own page and its dealer's address in Chromium, WebKit and Firefox, and inside Claude's widget: drawn to open in a new tab with no opener and no referrer and an arrow after them, each a link in the accessibility tree whose name says it opens in a new tab; the car's page with what the view read added and a `javascript:` link drawn with no `href` and written down as refused; a press opening the address in a new tab whose `window.opener` is null and whose `document.referrer` is empty, the page staying where it was; and the same view run headless refusing the same two links in the same words and nothing else. The `graview-view-drawing` skill says what a link out may be and why, `graview-worker-view` points at it, and the guest README says it. The guest host drawing a worker view on the open kit carries 2.4 KB more (946 bytes gzipped) and registering one 30 bytes (11 gzipped), each under a raise that says so (`scripts/budget-raises/a-view-links-out-to-what-it-was-handed-*.json`).

Compatibility: additive. `links` is a new optional key on `mountWorkerView`'s options, a worker view's definition and `runWorkerViewHeadless`'s options, `HeadlessInput.linkOrigins` a new optional field, and `<a href>` a new attribute the open kit draws where it was refused; a view that drew an `href` before now draws it where it was handed it. The wire and the stored formats are unchanged.
