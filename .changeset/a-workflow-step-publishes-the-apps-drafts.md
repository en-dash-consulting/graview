A workflow step can publish an app's drafts. In an app that publishes (`publishing: { mode: "on-publish" }`), a scheduled sync could make its changes but not publish them, so it still needed somebody outside the app to finish. Publishing was reachable only as the built-in `publish` act a publisher presses, never as a step: an act step naming it was refused as an unknown act. There is now a `publish` step kind (`STEP_KINDS.publish`, `PublishStep`, `publishStep` on `@graview/core/workflows`; `runPublishStep` on `@graview/tools/workflows`):

- `{ "publish": "head" }` publishes every draft, as the head stands when the step reaches it, so a step before it that made changes has them published too; `{ "publish": "run" }` publishes only through what the run read as it began and the last op it made, so a change somebody else made while it ran stays a draft.
- It runs the same `publish` act through the run's one door, as the workflow's own actor, under the step's or the workflow's `approve`: `apply` publishes, `ask` puts it to a person in the Suggested tray, and a dry run (and the first run after a change) previews it and publishes nothing.
- The run says what it published, or would: a note ("Published 3 changes (seqs 0 to 2): readers are served them now.", "It would publish 3 changes (seqs 0 to 2); nothing was published.") and `run.published`, one entry per publish step with how many changes, the first and last seq among them, how far readers are served, and whether it was previewed, published or suggested. The agent tool `run_workflow` answers it too. With nothing new to publish it publishes nothing and says so; in a live app the step is skipped, in words.
- `graview check` refuses a publish step in an app that is live, where every edit reaches readers as it is made: `workflow-publish-live`, with the fix. An act step naming `publish` is pointed at the publish step.

The publish op now carries the lineage its caller gave, so a workflow's publish is under its run in Activity like its other ops. `draftsOf` on `@graview/core/publishing` says what a publish through a seq would publish, and the publish act's own "Publish 3 changes" reads it. The `graview-workflows` skill says how to end a sync with a publish. Held by unit tests of core (`a-publish-step-is-checked-and-said`) and tools (`a-workflow-publishes-the-apps-drafts`).

Compatibility: the declaration and check finding codes — additive: a workflow step may be `{ "publish": "head" | "run", "approve"? }`, and every step that was valid stays valid; one new finding code, `workflow-publish-live` (error); an act step that names `publish` is still `workflow-act-unknown`, its fix now naming the publish step. Ops and primitives — additive: a publish op may carry `lineage` where the caller said one; one without it is read as before. A run (`WorkflowRun`) may carry `published`; absent when no step published. The wire, stored formats and derived tool names — unchanged. What Graview Cloud does: run a workflow with a publish step on its schedule as it runs any other, with the app's `publishing` on the store it hands `runWorkflow` and `@graview/tools/workflows` loaded (it loads `@graview/core/publishing`), and show `run.published` (or the run's notes) where it shows a run.
