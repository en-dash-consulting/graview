A rename carries the kept views that read it, or the preview says they will break (HQ feature:f-rename-carries-kept-views). Renaming a relation, a field, a kind or an act left every kept view whose manifest named the old key no longer fitting the app, while the preview said nothing would break. `editDocument` given the host's views (`views`) now carries each manifest the change reaches — the kind it is attached to, `reads.kinds`, `reads.edges`, `accepts`, `pictures` and `acts`, a derived act's new name included — and answers `views`, every view as it stands after the change, for the host to keep in the same change as the document so one undo takes both back, and `carried`, each view it moved (net: a name renamed and renamed back is not moved) with what it read and what it reads now; a view renamed in the same change comes back by its new name. Where a view's `source` is handed, it says which views' scripts still name an old key — a kind, a relation or an act the change renamed, or a renamed field of a kind the view is handed, named in its manifest or not — and that they read nothing by it until changed; a script is never rewritten. `diffDocuments(stored, proposed, { views })` names each view that reads a kind, field, relation or act (declared, or derived for a kind or a relation) the change takes away (`brokenViews`), says so in a sentence, and counts the change as breaking for it; given the carried views, it finds none. `HostView` says `reads.edges`, `accepts`, `pictures` and an optional `source`.

Compatibility: the look — unchanged. The JavaScript API — added: `EditOutcome` gains `views` and `carried` (only where `views` were handed), `CarriedView`, `diffDocuments`' third argument (`DiffOptions`), `DocumentDiff.brokenViews` and `BrokenView`; `HostView` gains `reads.edges`, `accepts`, `pictures` and `source`. A host that passes its views to `diffDocuments` sees a rename that strands a view as breaking where it was not. Ops and primitives — unchanged. Stored formats — unchanged. The wire — unchanged. The declaration and check finding codes — unchanged. Derived tool names and input schemas — unchanged.
