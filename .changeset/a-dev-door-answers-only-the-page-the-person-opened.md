A dev server's doors answer only the page the person who started it opened. The studio, local, model, decision, files and views doors asked one thing of a caller, `sameOrigin`: no other site's `Origin` or `Sec-Fetch-Site`, and a Host that is this machine. A browser always says where a request came from, so that kept other sites' pages out; a program that is no browser says nothing, and to that check it looked like the page — another account on this machine, a container sharing its loopback, or anyone on the network when the server was started with `--host` (any IP address passed as this machine) could write TypeScript into `src/domain` through the studio door, run the operator's own `claude` through the local door, and spend `ANTHROPIC_API_KEY` and `TYPESAFE_API_KEY` through the model and decision doors. Now every door also asks for a key (`fromThisApp` in `@graview/ship/dev`): kept in `~/.graview/door-key`, mode 0600, made the first time and taken again by the next server (`GRAVIEW_DOOR_KEY` sets one outright), said only in the terminal as the address to open (`Graview's doors: open http://localhost:5173/?graview_door=<key>`), and traded there once for an `HttpOnly`, `SameSite=Strict` cookie, the address tidied (`doorLogin`, which every door's plugin installs through `openDoors`). The key is never written into anything the server serves. Without it a door answers 403 with where the key is, and the page reads the door as closed. A door now takes only this machine's loopback as where its page is (`localhost`, `*.localhost`, `127.x.x.x`, `[::1]`, `loopbackHost`); an address on the network answers only when `GRAVIEW_DOOR_HOSTS` lists it. `mcpDoor` takes `admit`, asked of every request beside its origin — on a dev server, `fromThisApp`. Ship's new door test holds that a request with no Origin and no key is refused on a loopback and a network Host and writes no file, that the printed address lets the page in and the key appears in no response, the page's included, that a wrong key sets nothing, and that the key file is kept 0600 and read again; core's sync test that `mcpDoor` asks `admit`; the door tests send the cookie a page holds. `verify-files` opens its page from the address with the key, as a person would. The graview-desk and graview-sync skills say how.

Compatibility: ops and primitives, stored formats, the wire, the declaration and derived tool names and input schemas — unchanged; `sameOrigin` answers as it did, so `graview preview` and a served store are as they were. A dev door refuses a page not opened from the printed address, and one reached by a network address `GRAVIEW_DOOR_HOSTS` does not list.
