An add keeps only the record times its own op stamps. Since 0.2.10 every record keeps when it was made and last touched, and by whom (`createdAt`, `createdBy`, `updatedAt`, `updatedBy`), and the op that adds a record stamps it with its own time and author whatever the add's payload said. The op as kept now says the same: from this version, a record an op adds is kept without the four its payload carried, on every way an op enters a store (`receive`, a rebase's confirmed ops, `applyPrimitives`, as acts, a host's own ops and an import already were), so the log, a seat's log, the history, an export and a push say only what this store stamped. An undo that puts a record back keeps what its payload says, as the fold already did, and an op that removes a record and adds it again is kept saying when and by whom its removal says the record was made, which is what the fold makes it. A log kept before this version is read as it was. Held by a new unit test of core (`an-add-keeps-only-the-record-times-its-own-op-stamps`).

Compatibility: ops and primitives — an op's format is unchanged, but the payload of an `add-node` in an op with no `undoes` is kept without `createdAt`, `createdBy`, `updatedAt` and `updatedBy`, and one the same op removes says only the `createdAt` and `createdBy` its removal carried; a host that reads the log reads a record's four from the record, as it already could. The graph each op folds to is unchanged. Stored formats, the wire, the declaration and check finding codes, the JavaScript API, and derived tool names and input schemas — unchanged. What Graview Cloud does: nothing; a remix seed it receives is kept without the source's record times.
