An agent that opens a new product cold finds what to read at the root. Graview Cloud scaffolded "Field Notes" the way a stranger would and found fifteen skills installed, a `docs/agents.md` that `graview docs` writes and `.gitignore` ignored, and nothing at the root but README.md, so the loop and the skills had to be discovered. `graview create` now writes `AGENTS.md` at the root (the loop, `check` then `verify`; the three rules; and the skills, a line each) and a one-line `CLAUDE.md` that imports it (`@AGENTS.md`). The three rules are said by one function that `graview docs` uses for `docs/agents.md` too, so the two cannot drift. `docs/agents.md` and `docs/llms.txt` are no longer ignored: `create` writes them after installing, and the project's `verify` writes them again from the declaration as it now is, so they go into the commit beside the change they describe. `graview skills install` rewrites the skills list in `AGENTS.md`, between the markers `create` leaves for it, with what it just installed, and leaves a file without them alone. And `create` makes the first commit, "Field Notes, on Graview", with everything in it, where it initialized a repository and committed nothing (`git status` showed `.agents/`, `.claude/` and `.github/` untracked and the rest staged). When git has no `user.name` or `user.email`, everything is staged and one line says so. The README says so too.

Compatibility: ops, stored formats, wire messages, the document format, the compiled format, check finding codes and tool schemas are unchanged. Changed: what `graview create` writes (`AGENTS.md`, `CLAUDE.md`, `.gitignore` without the two docs, `verify` ending in `graview docs`) and does (writes the agent docs, makes the first commit); `CreateIo` gains `ask`, the quiet half that reads git's identity; `graview skills install` writes into an `AGENTS.md` that has the markers.
