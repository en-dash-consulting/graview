A frame guest kept out of sight is told so, and what it plays stops. A frame its host said may be kept for a return (`guestView({ keeps: true })`) is moved, still running, to a shelf off the page as its page is left, and a `<video>` or a sound of the guest's own, once played, went on playing there, heard from a page the person had left; a worker view's videos already stopped. The host now tells the frame `{ type: "away", away: true }` over its port as it is put on the shelf and `{ type: "away", away: false }` as it is put back. The frame's client pauses every `<video>` and `<audio>` in the guest's document that is playing on the first, and plays again on the second what it paused that still stands paused. The guest's own code hears both, after the client, for a sound of its own making (Web Audio, a `new Audio()` never put in the document, media in a shadow root): `guest.onAway((away) => …)` returns its stop, and `guest.away` says which it is now. Held by `a-kept-frame-guest-is-told-it-is-off-the-page`.

Compatibility: ops and primitives, stored formats, the declaration and check finding codes, and derived tool names and input schemas are unchanged. The wire gains one message from host to guest, `{ type: "away", away }`, on the frame protocol; the protocol's version is unchanged, and a guest that does not know it drops it unread. The JavaScript API is additive: `away` and `onAway` on `Guest`. The inlined guest client changed, so a host that pins its hash takes the new `GUEST_CLIENT_SHA256`. What Graview Cloud does: serve the new client (or name the new hash in a frame's policy); nothing else.
