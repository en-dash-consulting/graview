The app's own actor never makes again what a person took back (Roadmap f-declines-a-person-meant). Seen on Threat Watch, where a link the owner undid was made again three nights later, and on Staffing Placement, where four placements were merged because their labels all drew "—". A decline was only an undo of a suggestion or of a change carrying lineage; now a person's live undo of any change, whoever made it, is one, and so is a person breaking a link (a disconnect, or any change of theirs that removes one), which declines that link until a person makes it again (`declinesIn` on `@graview/core/tidying`). A checkpoint keeps the declines behind it (`Epoch.declines`, each a `KeptDecline`: the id, time and author of the op that said it), so a compaction that archives an undo with the change it took back no longer lets the next night make it again; `declined(store, calls)` answers a `Decline`, the op or what the checkpoint kept of it. What a person declined, and what a call means, are judged off the page now (`ops/declines.ts`), taught to the store by `@graview/core/tidying` as it loads (`DECLINES`), as every host that runs the actor does — `dream`, `suggest`, a workflow, `@graview/ship`'s server: a hosted page carries 734 B less up front, and the scene, which fetches that entry for Activity's digest before it draws, 1_168 B more (its before-drawn bound is 1087 KB, and three raises in `scripts/budget-raises/` say the rest). The duplicates judge and pair blocking (`@graview/tools/tidy`) treat a placeholder name — blank, dashes, punctuation alone, "Untitled", "TBD", "N/A", "New" (`placeholderName`) — as no evidence, and never pair two records whose one-link relation points at different records (`linkedApart`). Tests: `a-change-a-person-took-back-is-never-made-again`, `a-blank-name-or-a-different-link-is-no-duplicate`.

Tidying says each change and its one reason, short (Nick, from En Dash Org: "language in tidying suggestion is clumsy and bloated"). `lineageWords` is the basis, how sure and the model — "Same name · 90% sure" where it said "based on “Same name as “Acme Supply” (another vendor)” · 90% sure"; a provisional link "Not yet kept by a person. Graview, tidying made it: Both name 12 Harbor Street · 60% sure." The floor's bases are "Same email: hi@bloom.example", "Same name", "Same name, punctuation aside", "Its supplier is “Harbor Catering”", "“Harbor Catering” appears in its notes" and "Its status is “done”, unchanged for 116 days"; a model's no longer repeat the model and the number the lineage already carries: "Same vendor, entered twice, with the same email" for "Jev: 0.96 that “ACME Corporation” and “Acme Corp” are the same vendor (the same email)", "Reads as “backup”", "Reads as spam".

Compatibility: ops and primitives — unchanged; an op is written as it was, and a log folds the same. Which ops count as declines widens: a person's undo of any change and a person's removal of a link now decline it to the app's own actor, so an `automated` author is refused some changes it was allowed before; a person is never refused by them. What people declined is judged where `@graview/core/tidying` is loaded — `dream`, `suggest`, a workflow and `@graview/ship`'s server all load it; a host that applies an `automated` author's change in a process that loads only the main entry imports `@graview/core/tidying` once to be held to declines. A checkpoint made without it carries the declines the one before it kept. Stored formats — `Epoch.declines` is optional and additive within format 1 (docs/stability.md); a checkpoint without it opens as before. The wire — unchanged; epochs served to a seat never carry `declines`. The declaration and check finding codes — unchanged. Derived tool names and input schemas — unchanged. The words of a lineage, a provisional link and every tidying basis change, as above.

What Graview Cloud does: drop the `it.fails` pins in workers/cloud/tests/dreaming.test.ts for the three decline gaps and the "—" duplicates, and drop its `TIDYING_JUDGES` filter that kept the duplicates judge off placeholder names; a test asserting a basis or `lineageWords` by its old words reads the new ones.
