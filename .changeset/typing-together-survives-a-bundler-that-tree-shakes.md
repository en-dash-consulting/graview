Text typed together survives a bundler that tree-shakes (FR-209). `@graview/ship`'s runtime, its handler and its main entry load `@graview/core/typing` for its effect alone — it teaches every store the `type-text` act — with a bare import, and core's `sideEffects` named field sight and publishing but not typing, so esbuild under wrangler dropped the import, and a room Graview Cloud deployed refused every keystroke as `"type-text" is not something this app can do.` vitest, which bundles nothing, passed. Core's `sideEffects` names `./dist/typing.js` and `./src/typing.ts` now; no other file any package imports only for its effect was missing (field sight, publishing and `@remote-dom/core/polyfill` are named by their packages; the imports marked as doors tie chunks and are not for an effect). The measures that resolve `@graview/*` themselves read a package's `sideEffects` the way a bundler does (`scripts/lib/side-effects.mjs`): the worker's import cost answered every entry as kept whole, so it had counted typing all along and never saw it dropped; the hosted page's read any list as "everything has effects". Neither budget moves: typing is in the worker as it was measured, and the hosted page fetches typing only when a field typed together is focused. A test bundles `@graview/ship/runtime` and `@graview/core` from their published files the way a Worker is bundled, resolved by esbuild and nothing of ours, and has the handler that bundle serves apply a keystroke; another holds that every file a package imports only for its effect is one its package's `sideEffects` names.

Compatibility: ops and primitives, stored formats, the wire, the declaration and check finding codes, derived tool names and input schemas — unchanged. A host that bundles `@graview/ship/runtime` keeps `@graview/core/typing` and so takes keystrokes; one that loaded `@graview/core/typing` again itself to work around it can stop. `capabilities().shipped` gains FR-209.
