A worker view needs no build and no copy of the protocol (FR-96). A guest in a worker had to be bundled with esbuild against `@graview/guest/worker`, so a chat on a phone, with no tooling, could not write one. `mountWorkerView`, `registerWorkerView` and `workerHome` now take `worker: { source }`: one plain script against the `graview` global, with no imports and no bundler. The host puts the view's runtime in front of it and runs the two as one strict classic worker. A module worker is refused from a `blob:` URL in an opaque origin, which is where a chat's widget runs, so a classic one it is. The runtime is Remote DOM's polyfill, the hardening, the channel and the global. The host holds it as one classic script, `view-runtime.generated.ts`, built from `src/worker/view.ts` by `pnpm guest:runtime` and fetched only when the host first starts a view from its source. A test builds it again and fails when the file is not current. The hardened worker has no `eval`, no function constructor and no `importScripts`, so the one way left to load code is `import()`. That is syntax, and a keyword cannot be spelled with an escape, so a source whose text says `import` anywhere, even in a string or a comment, is refused before it runs. So is one that exports, names `importScripts` or calls `require()`. `checkViewSource` in `@graview/guest/host` says why, and `onFailure` hears `source` with the same sentence. `maxSourceBytes` counts the view's own source. `{ script }` still takes a whole worker script built against `@graview/guest/worker/view`.

`@graview/skills` gains `graview-worker-view`, the authoring guide. It covers the manifest, the global, what may be drawn and what never is, the theme's tokens, links, the write rules and the limits. Two worked examples sit beside it: `examples/offers-list.js`, a list lens whose rows link to their records and which takes a note the person types and presses, and `examples/front-page.js`, a home that leads with a headline, a figure and an SVG ring and links its cards to a place. Each opens with its manifest. Like every skill, it ends in `graview check` and says what the check cannot see.

A unit test holds the runtime current and a classic script that loads nothing. It finds the skill's examples and the fixture views runnable as written, and refuses eight sources, each with a sentence. `guest-sandbox` gains `--transport=plain`, which hands the skill's two examples and LifeLogics' package lens to the host as plain source over the offers fixture. The list lens draws Lin's three offers, cheapest first, and takes her typed note, as her, through the view. The home leads with the recommended package and its total and links its cards to the place. The package lens draws its three packages. A source that hides `import()` behind a string is refused before it runs, and the page makes no request but its own. All ten claims hold in Chromium, WebKit and Firefox. The place transport now runs both of its views as plain source too. Three bundle budgets are raised, each saying why. `@graview/guest/host` registers and judges worker views (13 kB, 6 kB gzipped). `mountGuestWorker`'s first load carries `mountWorkerView`'s manifest, write rules, links and limits (18 kB, 7 kB). The open kit's host carries the view's runtime as text (122 kB, 44 kB).

Compatibility: the wire — unchanged. A view started from its source speaks the same protocol as one built against `@graview/guest/worker/view`. Ops, stored formats, check codes and tool schemas are unchanged.
