A drawn view's accessibility is audited (Roadmap f-view-a11y-audit). `auditView(root)` from `@graview/guest/audit`, a new entry no page loads, holds what a worker view drew — its shadow root on a page, or a headless run's tree — to what a person on a keyboard or with a screen reader meets, and says each problem as a repair: the rule, its WCAG 2.2 criterion, how bad, where (a selector from the nearest `data-key`), a one-line fix, and `automatic` when the framework is the one to fix it rather than the view. It judges the drawing as the host draws it, so a link, a press and a control the view drew itself, which the host gives the keyboard, are no problem, and a `<div>` the view only hears a click on is. Eight rules run wherever the drawing is: `keyboard` (2.1.1), `role`, `name`, `toggle-state` and `nested-interactive` (4.1.2), `img-alt` and `svg-name` (1.1.1), and `scroll-region` (2.1.1). The ring the keyboard shows (`focus-visible`, 2.4.7 and 1.4.11) and text `contrast` (1.4.3) run only in a browser that lays the page out, and say how many elements they measured; anywhere else they are listed as skipped with why, never as passed, as is a keyboard trap (2.1.2), which needs keys pressed. `runWorkerViewHeadless(…, { audit: true })` audits what a run drew, with the elements its view listens on for a click — the view's runtime now says which those are — and `graview view check … --audit` prints it and fails on a problem the view must fix.

A place's frame that scrolls its picture inside it (a lens, or a view with `flows: false`), and a draft view's frame, now take the keyboard and are named for the place: `role="group"` with the place's title, so the arrows scroll it and a screen reader says what it holds. A group rather than a region, because the view drawn in it is a region of that name already, and two landmarks of one name fail axe's `landmark-unique`.

`guest`'s tests flag a `<div>` with only a click handler and pass one that says `role="button"`, pass an `<a data-record>` and a card bound to a record, flag a button with no name, a field with no label, a toggle with no state, a control inside another and a card that holds a button, an image with no alt and an SVG that is `role="img"` with no name, say which rules ran and which did not, audit Threat Watch headless with the clicks its view hears, and run `graview view check --audit` to its exit code. `pnpm verify a11y` draws Threat Watch's home and the guest sandbox's offers views on the pages face and audits each in the browser, light and dark: the host's ring and the views' words measure (15 rings and 23 words on Threat Watch), faint words and a ring taken away laid on the same page are found, the audit on the page says what the headless run says, the framework's markup around each view passes the audit, a framed place is a box named for it that Tab reaches, Tab goes into each view and out again, and what axe finds inside a view the audit finds too. `graview-view-links` says how to run it. The view's runtime is 162 bytes larger (48 gzipped), under raises of its budget and of the guest host's that inlines it (`scripts/budget-raises/a-drawn-views-accessibility-is-audited-runtime.json`, `…-open-kit.json`); nothing a hosted page loads up front grew.

Compatibility: additive for a host — `@graview/guest/audit` is a new entry, `runWorkerViewHeadless`'s `audit` and `graview view check`'s `--audit` are optional, and a headless run's transcript may carry `clicks`; a framed place's scrolling box is now a tab stop named for the place. The wire, the stored formats, the declaration and the derived tools are unchanged.
