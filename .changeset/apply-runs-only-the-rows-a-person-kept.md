A plan's review applies only the rows a person kept, and a plan's name means only what the plan made. `PlanReview` filed a call on a standing record under a row the plan was making whenever the plan gave the new thing that record's id as its name (`as: "b_herbs"`), so the review read "New Tomatoes" while the calls under it renamed and dug up Herb Bed; declining the row drew it struck through and still ran them, and Apply stayed pressable under "0 of 1 to run". A call waiting on one the seat may not make stayed ready, and `applyPlan` handed a `{ $plan }` name that made nothing on as the literal id, so it acted on whatever record had it. Now a plan's names are its own — `planFrom` refuses a name that is already a record's id, and refuses a call that waits for one it cannot make ("Waits for "seedlings", which this plan cannot make.") — and `applyPlan` stops and takes back what ran when a name it needs made nothing ("Refers to "fresh", which nothing earlier in this plan made."). In the review, a call on a standing record is its own row, named by that record; the press runs only the calls of rows drawn live, planned again so nothing runs without what it waits for, and is not offered when no row is live. `a-plan-name-means-only-what-the-plan-made.test.ts` holds the name refused, the dependent refused, the stop and the undo; `apply-runs-only-the-rows-a-person-kept.test.tsx` holds the standing record named in its own row, a declined row and a refused one running nothing, and a kept row beside a declined one running alone.

Compatibility: ops and primitives, stored formats, the wire, the declaration and check finding codes, derived tool names and input schemas — unchanged. A plan whose name is a record's id, or whose call waits on a refused one, is refused where it ran before.
