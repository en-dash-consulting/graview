A worker view chooses the pictures it draws (FR-220), Roadmap f-view-pictures-chosen. A view of a season's 818 drivers that read its circuits too asked for `pictures: true`, and the drivers' 73 photos came to more than the 12,000,000 bytes of pictures a view is handed before the circuits' maps it drew were reached. A manifest's `pictures` now also says which it draws: the kinds, `["circuit"]`, or the fields by kind beside `width`, `{ "circuit": "photo" }` (`{ "width": 600, "circuit": ["map", "photo"] }`). A picture it did not choose is handed by its facts alone (name, type, size, width, height): never fetched, never reckoned against the budget, never handed an address; an object that chooses no kind still hands every picture. `checkManifest` refuses, in a sentence, a kind that is none (`The view's pictures chooses "track", which is no kind of this app.`), a kind whose records the view is not handed (`… add "circuit" to its reads.kinds.`), a field that holds no picture (`The view's pictures chooses circuit's "logo", which holds no picture.`) or holds videos, and a value that names no field. What is left out past the budget is now the same on every push and in a headless run: the pictures are reckoned in the order the view is handed its records, each at what the record says it weighs drawn as wide as the view draws one, where before a picture fetched lighter than reckoned let a later one in on the next push; the sentence says so and how to choose (`… and the pictures before it, in the order its records are handed, took them. A view that draws only some kinds' pictures says which ("pictures": ["<kind>"]).`). Guest's test hands a view that chose `circuit` only the circuits' pictures, fetching none of the drivers', and one that chose `{ circuit: "map" }` only the maps; leaves out the same pictures on two pushes; and refuses a kind and a field that are none. `capabilities().shipped` gains FR-220.

Compatibility: ops and primitives, stored formats, the declaration and derived tool names and input schemas — unchanged. The wire — additive: a worker view's manifest `pictures` may be a list of kinds or name fields by kind, which an earlier build refuses; `capabilities().shipped` gains FR-220. The JavaScript API: `GuestPictures` widens; `handFiles` hands its callback the field a file is in. What Graview Cloud does: passes a view's `pictures` through `propose_view` as the agent wrote it (a list or an object, not only `true`), shows `checkManifest`'s sentences when it is refused, and once `capabilities().shipped` has FR-220 tells its agents to choose the kinds a view draws pictures of.
