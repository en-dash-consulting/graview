A store too large for the browser's localStorage is kept, in IndexedDB. WebKit keeps 5 MB of localStorage an origin and counts each character twice, so the gauntlet's 2.8 MB seed did not fit in Safari: since the last release the store opened and reported the write that failed, and a reload had forgotten every edit. `createBrowserAdapter()` now keeps the snapshot, the log and the meta in IndexedDB (the `entries` store of the `graview` database, under the keys localStorage used), and the log in pieces, one per write, so an edit appends what it did rather than writing the whole log again; a log read in more than 32 pieces is put back together into one. It is the default rather than a place a full store spills into, so where a store is kept never depends on how large it once grew. The database opens on the first read, not when the adapter is made, and nothing of it is in a hosted page. The gauntlet in WebKit, Chromium and Firefox now reloads with an edit it was given (`aLargeStoreReloadsWithItsEdit`, in `pnpm engines`). The `graview-ship` skill says where the page keeps its store.

Compatibility: ops, the wire, the declaration and derived tools are unchanged. Stored formats: a page's store moves from localStorage to IndexedDB, and an existing one is carried forward, not lost — the first time a scope is read, what localStorage holds for it is written into IndexedDB in one transaction, and only after that transaction commits is it removed from localStorage. When IndexedDB will not take it, it stays in localStorage and the adapter keeps it there; where IndexedDB will not open at all, the adapter is localStorage as before. A build from before this one, opened after it, finds localStorage empty and starts from the seed; when this build opens again, the store IndexedDB holds stands and what the older build wrote in localStorage is left there untouched. Changed: `BrowserAdapter`'s `loadMeta` and `saveMeta` answer promises (`openStore` awaits either kind), it gains `keptIn()`, and `createBrowserAdapter` takes `indexedDB`; passed `storage` alone, it is that storage only, as a test or a node rehearsal wants. What Graview Cloud does: nothing; a hosted page persists through its server, not this adapter.
