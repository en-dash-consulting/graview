Better UI makes a small change as an edit, and a style it refuses is named by its rule. On 0.1.66, on a home view of some 15 KB that a chat wrote, "fix the En Dash logo in this hero to not have rounded corners" is one declaration (`.home .lg{border-radius:10px}` to 0). The agent could only answer with the whole script, and every byte of it was judged. It drafted three times: twice it was told "styles the page won't keep", once "it didn't draw, 9 records missing, headings missing". It ended with "I haven't got it right yet", and nothing was kept. Three things were wrong. The agent was shown only the first 9 KB of the script it rewrote. A property the page's own script already had and the host had always left out (`image-rendering`) refused every draft that kept it. And a refusal never said which rule.

The agent has a new move, `edit`: one or more exact `find`/`replace` pairs. The framework applies them (`applyEdits`), never the model, to the script on the page, or with `"in": "draft"` to the agent's own last draft this turn. The result is drawn and judged exactly as a whole draft is. A find that is not there, or is there more than once, is handed back in words, and nothing is drawn: "Edit 1: “border-radius:10px” appears 3 times in the script on the page: quote more of the text around the place you mean, so it appears once." The panel says it by its kind, `edit-missed` ("an edit's text appears 3 times"). Such a miss is not counted as a failed draft. The agent is taught to answer a small change (a color, a corner, a size, a word, one rule, one part) with an edit, and to draft the whole script only for a redesign or where there is no script on the page yet. It is shown the script on the page whole, up to 64,000 characters, and its last draft whole where that draft did not pass. The move set is `DESIGN_AGENT_MOVES`. `DesignAgentMove` is read from it, `readAgentReply` reads an edit's changes (`AgentReply`, `ScriptEdit`), a step carries the `edits` it asked for, and `DesignAgentEvent.kind` gains `"edit"` ("Changing: …").

A refused style says which rule, what of the rule was kept, and why the rest was not: "In “.home .lg”, the property “image-rendering” is not allowed and is removed (border-radius is kept): …". On the panel that reads "“.home .lg” keeps border-radius; image-rendering isn't allowed". `cssFindings(source, { already })` leaves out a refusal that the script on the page had too, because the page already draws without it. A new design's drawing no longer adds a second "Refused a rule of the stylesheet (css)." for a stylesheet that was judged before it was drawn. Tests: `a-small-change-is-an-edit-not-a-whole-new-script` (tools), which holds that on a 15 KB home view a fixed reply for "no rounded corners on the logo" is kept from the first step as one changed declaration, and new `section` harness claims `aSmallChangeIsOneEditOnThePageFromTheFirstStep` and `aRefusedStyleIsSaidByItsRule`. Every face grows by 6.5 KB (2.2 KB gzipped), under a raise of its budget (`scripts/budget-raises/better-ui-small-edits-every-face.json`). A hosted page's first load is unchanged.

Compatibility: ops and primitives — unchanged. Stored formats — unchanged. The wire — unchanged. The declaration and check finding codes — unchanged. Derived tool names and input schemas — unchanged. The JavaScript API is additive: `applyEdits`, `DESIGN_AGENT_MOVES`, `AgentReply` and `ScriptEdit` on `@graview/tools/section`; `DesignAgentMove` gains `"edit"`; `DesignAgentEvent.kind` gains `"edit"`; `FindingKind` gains `"edit-missed"`; `DesignAgentStep.edits` is optional; `cssFindings` takes an optional second argument. The words of a style-refused finding change, and a host that matches on "The property “…” is not allowed" should match on "is not allowed and is removed" instead.

What Graview Cloud does: nothing to adopt. A Better UI turn asked for a small change on a view it hosts now offers the change from the first step, and its logged findings (`onDraftChecked`) name the refused rule.
