A worker view hears a wheel, a drag and a pinch. TrueNorth's recon app ran its architecture map as a worker view, and it could select and open a zone but never pan or zoom: only clicks, typing, choices and a drop crossed into the worker. A view whose manifest says `gestures: true` now hears `graview.on("wheel" | "drag" | "pinch", selector, (e) => …)` over what the selector matches. Every gesture carries `x` and `y`, where the pointer is in CSS pixels from the top left of the matched element, and that element's `width` and `height`, since a worker has no layout to ask. A `wheel` carries `deltaX`, `deltaY`, `deltaMode`, `ctrlKey` and `metaKey`. A `drag`, from `pointerdown`, `pointermove` and `pointerup` with the pointer captured, carries `phase` (`start`, `move`, `end`), `pointerId`, `button`, `pressure`, and `dx` and `dy` since the view last heard of that pointer. A `pinch` carries `phase`, `scale` (the factor since the view last heard) and `rotation`; it comes from Safari's `gesturestart`, `gesturechange` and `gestureend`, or from a trackpad's pinch, which is a wheel with Control held. The host sends at most one of each an animation frame with the deltas between summed, and a drag's start and end at once. It calls `preventDefault` on a wheel or a gesture only over an element a view that opted in listens on, so the page still scrolls and zooms everywhere else. A view that listens for a gesture without the flag is told in its console, and `graview view check` (`runWorkerViewHeadless`) says so too, as it does a flag with nothing to hear. `checkManifest` refuses a `gestures` that is not true or false. The graview-worker-view skill teaches it, with `examples/a-map-that-pans-and-zooms.js`, an SVG map whose viewBox a wheel and a pinch zoom around the pointer and a drag pans. `pnpm verify guest` now drives that map through `--transport=gestures` in Chromium, WebKit and Firefox. The host's gestures are a chunk of their own, 5.9 KB (2.4 KB gzipped), fetched only for a view that opted in and listens for one. The guest host carries about 0.2 KB more up front, the session handing on where a view listens, and a worker view's runtime 0.3 KB more. A hosted page's first load is unchanged.

Compatibility: ops, stored formats, the declaration and derived tools are unchanged. The wire: a worker view's runtime sends `{ type: "gestures", nonce, bound: [{ event, selector }, …] }` whenever where it listens for a wheel, a drag or a pinch moves, and a view whose manifest says `gestures: true` is sent `dom-event`s whose `event` is `wheel`, `drag` or `pinch`, carrying the fields above. A host of an earlier version drops `gestures` unread, and a view that does not listen hears nothing new. The manifest: `gestures` is new and optional. A manifest without it is read as before, and its view hears no gesture. What Graview Cloud does: accept `gestures: true` in a proposed view's manifest and teach it in its views guide; nothing changes in how it mounts a view.
