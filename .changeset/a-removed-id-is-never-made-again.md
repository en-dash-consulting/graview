An id the log once held is never made again. Who made a record is read from the log, by the first add of its id, and removing a record freed its id: the next act to make one could take it again, by minting the same slug from the same name or by asking for it, and the log still named the first maker. So a seat that made a task and removed it was taken for the maker of the task somebody else made later at that id. It could remove, archive or merge that task ("only on what you made"), edit it where every role may make the kind, and see it by an `own` sight, while the task's real maker could do none of those. Now an act's `freshId`, an id it is asked for, a client's hint and an import's mint all treat every id the log ever held as taken. A name minted again steps past the removed one (`task:plan-2`), an id asked for that a removed record held is refused as already taken, and a hint at one is minted past as a held one is. Undoing a removal still puts the record back at its own id, credited to its maker. Core's tests hold it (`a-removed-id-is-never-made-again.test.ts`). The store is on every page, so a hosted page carries 0.1 KB more up front (103 bytes minified, 43 gzipped; 103 / 19 handed a compiled app), under raises naming this changeset.

Compatibility: ops and primitives, stored formats, the wire, the declaration and check finding codes, and derived tool names and input schemas — unchanged. An act asked for an id a removed record held is refused where it made the record; a host that re-made records at their old ids makes them under ids of their own.
