A field says it is cited. A value somebody looked up, like a population, a quote or a founding date, should say where it came from, and a declaration had no way to say so. A document's field now takes `cites`, naming the field or the relation of the same kind that holds its citation (`"population": { "type": "integer", "cites": "source" }`); in code, `markCites(z.number(), "source")`. `citedFieldsOf(schema, kind)` reads a kind's, `citesOf(schema, kind, field)` on `@graview/core/check` one field's, and `toDocument` writes it back. The edits keep it: `rename-field` and `rename-relation` rewrite a `cites` naming the old name, `remove-field` and `remove-relation` drop it and say so, and a new `set-cites` edit sets or clears it. From that:

- `graview check` refuses a `cites` that names no field or relation of the kind, or the field itself (`field-cites`, an error, at `kinds.<kind>.fields.<field>.cites`). It warns of each example in a template's seed that holds a cited value with nothing cited (`field-uncited`), and, with the new `--seed <snapshot.json>`, of each record in a seed; a seed it cannot read, or a `--seed` naming no file, is said in words. Installing a template is not refused for it. A record set aside, or a link to one, counts for nothing.
- `uncitedIn(store, seat?)` and `uncitedValues(schema, records, linked)` on `@graview/core/tidying` and `@graview/core/check` list each uncited value with its words ("Lagos's population cites no source"). A relation cites a record when it links a current record out of it; an empty value is no claim; a citing field some sight may keep from the seat is not judged for that seat (`sightMayKeep`).
- The app's own actor's `dream` report carries `uncited` and says them at the end of `said` ("One value says nowhere where it came from, which only a person can add: …"). It suggests nothing for them, since only a person knows a source, and no row is drawn in the Suggested tray for them yet.
- The rule language gains `uncited('population')`, whether a cited field holds a value with no citation, and `uncited()`, whether any of the record's cited fields does, so a declared view's block flags one with `when` and a rule can require a source. This is the declared views' helper; there is no template formatter for it.
- A worker view is handed `cites` (kind → cited field → what cites it) and `uncited` (record id → its uncited fields), judged over the viewer's graph, and reads them with `graview.cite(node, field)`, which gives `{ by, relation, cited, source | sources }`, and `graview.uncited(node)`.

The `graview-node-kind`, `graview-view-specs`, `graview-invariant` and `graview-worker-view` skills say how. Held by new unit tests of core (`a-field-says-it-is-cited`), tools (`the-apps-own-actor-says-what-is-uncited`) and guest (`a-view-says-where-a-cited-value-came-from`).

Compatibility: the declaration and check finding codes — additive: a field may say `cites`, a document without it compiles as before; two new codes, `field-cites` (an error, only where `cites` is said) and `field-uncited` (a warning); a new edit, `set-cites`; a new rule-language function, `uncited`, which a build that predates it refuses as `unknown-function`. The wire — additive: a worker view's props may carry `cites` and `uncited`; a view that reads neither is drawn as before. Ops and primitives, stored formats, and derived tool names and input schemas — unchanged. The JavaScript API is additive (`markCites`, `citedFieldsOf`, `holdsValue` and `sightMayKeep` on `@graview/core`; `citesOf`, `seedLinks`, `uncitedIn`, `uncitedValues` and `UncitedValue` on `@graview/core/check`, the last three on `/tidying` too; `DreamReport.uncited`; `graview.cite` and `graview.uncited` in a worker view). What Graview Cloud does: nothing to keep working; to use it, let an app's fields say `cites`, and show `field-uncited` or `dream`'s `uncited` where it shows the app's other suggestions.
