Typing into a field rides a TypeScript act that writes it only where that act would run on the record. A keystroke (`type-text`) rode an act only while its declared rule (`allowedWhen`, `allowedOn`) held, but a TypeScript act whose rule lives in its `apply` — it throws `ActRefusal` for a published note — said nothing against it, so a seat refused "Revise" on a published note typed the body over all the same. Such an act is now asked: it is run on the record with the field's own value, against a context that writes nothing, and a refusal by its own rule (an `ActRefusal` whose reason is not `invalid`) keeps typing out; an `invalid` one ("nothing to change"), or an argument the record does not hold, does not. An act whose rule reads an argument a keystroke never hands it says its rule about the record as `allowedOn`, which is believed and the act not run. The same question (`wouldRun`, on `@graview/core`) decides what a record offers to change in place: `editableFields` leaves out a field whose act would refuse the record now, and a field typed together offers Edit only where the store would take a keystroke, so a published note shows no Edit; the live editor asks again before each keystroke and is read only, saying so, where a lock lands while it is open. `graview check` warns `typing-act-without-allowed-on` where a TypeScript act that writes a field typed together needs an argument a keystroke never gives it and declares no `allowedOn`, since a rule that reads that argument is never asked. `a-keystroke-rides-a-typescript-act-only-where-it-would-run.test.ts`, `an-edit-is-not-offered-on-a-record-its-act-refuses.test.ts` and `check-says-a-typing-act-it-cannot-ask.test.ts` hold it. A hosted page carries 0.6 KB more up front, handed a compiled app or not: `wouldRun`, which the fields offered to edit ask.

Compatibility: ops and primitives, stored formats, the wire, the declaration, and derived tool names and input schemas — unchanged. Check finding codes — one new warning, `typing-act-without-allowed-on`, judging only a TypeScript act's `allowedOn`; no code changes meaning and no new error. A seat that typed into a record through a TypeScript act whose `apply` refuses that record is now refused the keystroke, as it was refused the act, and is offered no Edit there.
