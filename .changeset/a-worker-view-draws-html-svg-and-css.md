A worker view can draw HTML, SVG and CSS, and nothing it draws can fetch or leave its region (FR-90). A worker guest could draw only the kit's eleven `gv-*` components, so a card grid, a chart or an animated ring could not be drawn at all, and a chat that wanted one wrote an HTML frame instead. `mountWorkerView` in `@graview/guest/host/worker` starts a view in the same hardened classic worker and draws what it says into a shadow root inside a region the host owns, with `contain: layout paint style`, `isolation: isolate` and `overflow: clip`. In the worker, the view's runtime (`@graview/guest/worker/view`) gives it one global, `graview`, with `render`, `style`, `onProps`, `props`, `on`, `act`, `navigate` and `html`, an escaping template tag. `render` keeps what is already drawn where it can, so a field the viewer is typing in keeps its text and its focus across a push.

What a view may draw is one declaration, `open-kit.ts`, read by the host's judge and by the runtime, which tells an author at once what the host will not draw. It allows most of HTML's sectioning, text, lists, tables, `details`, buttons, fields and `img`. It allows SVG's shapes, paths, text, gradients, clip paths, masks, markers and `use` of `#id`. CSS covers layout, grid, flex, colour, type, transitions, keyframes, and media and container queries, and the app's `--graview-*` tokens reach the view by inheritance, light or dark as the app is. The stylesheet, every `style` attribute and every SVG paint are read with a CSS Syntax Level 3 tokenizer and parser, so escapes are decoded and comments dropped before anything is judged. What is kept is written afresh from its tokens. `url()` stays only as `url(#id)` on a paint. Only `@media`, `@supports`, `@container` and `@keyframes` stay; `@import`, `@font-face`, `@namespace` and every other at-rule go. Only the functions on a list stay, so `image-set()`, `cross-fade()`, `element()`, `paint()`, `attr()` and `expression()` go. Only allowlisted properties stay, and `position` may be only static, relative or absolute. A selector with `:host`, `::slotted` or `::part` takes its rule with it. An image may be a `data:` image or a `blob:` of the page's own origin; an SVG image in an `img` runs no script and loads nothing. `<script>`, `<iframe>`, `<object>`, `<embed>`, `<link>`, `<meta>`, `<base>`, `<style>`, `<form>`, SVG `<image>`, `<foreignObject>`, SMIL and every `src`, `href`, `srcset`, `formaction`, `popover`, `autofocus` and `on*` attribute are not drawn, and a link has no address. Everything refused is in `refused`, with why.

Three unit tests hold it. One tries a `url()` in every property that takes one, escaped, uppercased, broken by a comment, inside custom properties, `@supports`, nested at-rules, keyframes and CSS nesting, plus `@import`, `@font-face` and the forbidden functions, and reads back what was kept with the same tokenizer. Another sends raw records for every element and attribute the kit refuses. The third joins the runtime to a host's shadow root over a real channel. `guest-sandbox` gains `--transport=open`, which serves the views on a page with no content security policy and records every request the browser makes. A showcase view draws a styled card grid, an SVG bar chart and a CSS-animated progress ring that take the app's panel, edge and accent in light, and again after the app's toggle to dark. An escapes view tries each way out, each to its own path on an attacker's server: a `url()` in nineteen properties, `@import`, `@font-face`, an escaped url, `image-set()`, SVG `<image href>` and `<use>` of another document, `<a href="https:">`, `srcset`, an `<img>` with an address, a `<link rel=preconnect>` built in code, inline handlers, `<iframe>`, `<object>`, `<embed>`, `<form>` and a fixed overlay. Each is its own claim, and all 42 hold in Chromium, WebKit and Firefox and in Claude's widget frame, with no request leaving the page and no connection to the attacker's server. `mountGuestWorker` and the new view share one start and watchdog (`worker-start.ts`), and the open kit's sanitiser is a chunk fetched the first time a view draws: `mountGuestWorker`'s first load stays within its 16 kB budget, and two new budgets hold the open kit's host at 46 kB (16 kB gzipped) and the view's runtime at 64 kB (22 kB gzipped).

Compatibility: the wire — additive: the guest-view protocol gains `style` and `pushed` from guest to host and `dom-event` from host to guest, and a `props` push carries a `push` number; `GUEST_PROTOCOL` stays 1 and a frame or kit guest neither sends nor needs them. Ops, stored formats, check codes and tool schemas are unchanged.
