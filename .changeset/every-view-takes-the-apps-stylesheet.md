Every view takes the app's stylesheet (Roadmap f-app-wide-view-theme). Each custom view carried its own copy of the stylesheet, so a polished home and the record pages drifted apart, and a brand change reached the view's tokens but never its rules. A document's brand now names what every worker view inherits: `brand.views.css`, a stylesheet the host draws in each view's region before the view's own — a `<style>` of the host's between the region's rules and the view's sheet, so the view's rule wins wherever both say one — and `brand.views.motion: "fade"`, under which the host fades a view's drawing out when the record it shows changes and in again once the view has drawn the new one (nothing moves where the person asked for less motion; a shared-element transition between records is not this, and is not promised). The brand's typeface and scheme tokens reach a view as they always did; the view is told nothing of either, and is dressed again when the brand changes (`handle.setBrand`). The sheet is held to exactly what a view's own is — nothing that fetches, no `@import`, no `:host`, 64,000 characters — by the same code: the CSS sanitizer and its tables moved from the guest's open kit to `@graview/core/css` (a subpath on no page: `sanitizeStylesheet`, `sanitizeStylesheets`, `sanitizeDeclarations`, `sanitizeValue`, the `CSS_*` tables, `OPEN_MAX_STYLESHEET`), `@graview/guest`'s host and headless run draw through it, and `graview check` and `compileDocument` hold `brand.views.css` to it, saying what the open kit leaves out as a warning, `brand-views-css` ("url() in background, @import"), and a sheet too long for a stylesheet as an error. `set-brand` takes `views` — `css` and `motion`, `null` clearing either or all of it — says what it did ("Every view is drawn with the app's own stylesheet before its own.", "A view fades when the record it shows changes."), as `diffDocuments` says it, and refuses a sheet the page would draw only part of, naming the part, so an agent learns at once rather than from a view that drew without it. A headless run (`runWorkerViewHeadless`) takes `brand` and answers `css`, its stylesheets as a page draws them with the app's first, so a picture of a proposed view is dressed as the page dresses it; `graview view check --browser` audits with that. The `graview-brand` and `graview-view-drawing` skills say it; `guest-sandbox --transport=brand` holds that the view's heading takes the brand's sheet and keeps its own rule where both say one, fades where the brand asks, and loses both when the brand does.

Reading the brand's key and carrying it to the Brand a page draws from costs a hosted page 0.2 KB more up front (192 bytes minified, 62 gzipped), and a page handed a compiled app 0.1 KB (136, 44), under raises naming this changeset; a visitor's form handed a compiled app 136 / 44 more, every face 3_916 / 1_840, the guest host drawing a worker view on the open kit 1_145 / 394 (the host's theme sheet and the fade), Cloud's worker 9_034 bytes, and the embed with the studio handed in 24_744 / 7_930 — the sanitizer, which that page fetched only as a view first drew, now comes with the editor's first load, since `editDocument` judges a brand's sheet as the page draws it — each under a raise of its own. The shape a page reads up front names the sanitizer's limit nowhere, so the two share no module and the page loads the chunks it loaded.

Compatibility: ops and primitives — unchanged. Stored formats — unchanged; a compiled app carries `views` within its `brand` in `graview-compiled@1`, and a page that predates it draws the brand it knows. The wire — unchanged; nothing of the theme is handed to a view. The declaration and check finding codes — `brand.views` is new, refused by path by a build that predates it; `brand-views-css` is a new code, a warning about a key no declaration could hold before, and an error only where the sheet is longer than a stylesheet may be; the edit vocabulary's `set-brand` gains `views`. Derived tool names and input schemas — unchanged. The CSS tables (`CSS_PROPERTIES`, `CSS_FUNCTIONS`, `CSS_AT_RULES`, `CSS_KEYWORD_PROPERTIES`, `CSS_FRAGMENT_PROPERTIES`, `CSS_REFUSED_SELECTORS`, `CSS_PREFIXED_SELECTORS`) and `OPEN_MAX_STYLESHEET` are `@graview/core/css`'s and no longer the guest's open kit's, which was never an entry of the package. What Graview Cloud does: store an app's theme as `brand.views` through `propose_change` with `set-brand`, pass `brand: app.brand` to `runWorkerViewHeadless` so `propose_view`'s pictures are dressed, and show `brand-views-css` where it shows the brand's other findings.
