`graview view check --audit --browser` runs every accessibility rule, in a browser. The ring the keyboard shows, text contrast and a keyboard trap — the three rules of `auditView` that need a page laid out or Tab pressed — ran only inside the framework's own harness, so a view's author could check the structure of a view and nothing a person would see. With `--browser` the command lays what the view drew out in Chromium — its markup with the host's marks, its stylesheets as the host keeps them, the app's tokens, the host's region rules — between a control before it and one after, runs the audit there with what the view hears a click on, and presses Tab from before the view until the keyboard is past it, and Shift+Tab back; every request the page makes is refused, and the view's script does not run in it (a view hears no Tab and no focus, so the order Tab walks is the order its drawing gives). It says every rule it ran ("— every rule") and fails on a problem the view must fix, as `--audit` does; `--browser` implies `--audit`. It uses the project's own Playwright, now an optional peer of `@graview/guest` asked for only by this flag, and where there is none — or no Chromium — it exits 1 saying what to install. The audit reaches the page as one classic script built from its source (`pnpm guest:runtime`), which no app's page loads. `graview-view-links` says to add `--browser` for contrast, the ring and a trap. Guest's tests find the drawing handed to the page escaped and marked, the page's tokens and its controls around the view, the script current with its source and loading nothing, and the command saying what to install without Playwright while `--audit` alone still runs; `pnpm verify a11y` runs the command on a view with faint words and a `<div>` heard only by a click and finds every rule ran, the ring and Tab measured on its two buttons, and both problems found ("graviewViewCheckBrowserRunsEveryRule").

Compatibility: new on the command line: `graview view check --browser`. `@graview/guest` gains `playwright` (>=1.40) as an optional peer dependency; nothing installs it, and nothing else asks for it. `runWorkerViewHeadless` takes `drawing: true` beside `audit: true` and answers with `drawing` (the tree it drew, with the host's marks, and the elements it hears a click on); a worker that imports `@graview/guest/headless` carries nothing more for it. The declaration, the wire, the stored formats, check findings and derived tools are unchanged. What Graview Cloud does: nothing — its audit runs on its own pages.
