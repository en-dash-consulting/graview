A kind's list page draws the view of many that replaces it, whatever registered after it (FR-238), HQ feature:f-list-page-draws-the-replacing-view; `capabilities().shipped` gains FR-238. On a Graview Cloud app the view `deliverables-board` — of many deliverables, titled "Deliverables", its manifest saying `replaces: "page"` — was not drawn at `/deliverables`, and the plain list was: the list page asked only the view that won the kind's default cell, the last registered, and a second titled view of many on the kind, "Status", registered after it. The list page now draws the last view of many over the kind that says it replaces the page and is still registered — not kept beside the kind's pictures or off the lists, not replaced since under its title or in its cell, and not deleted or hidden by the host's tidying — whatever won the cell; with none, the list is the app's own, and `?drawn=built-in` still reaches it. A place that is its kind's list page offers no way to the list it already is by the same answer. `listPageViewOf(registry, kind)`, on `@graview/react` (and `/provider`) and `@graview/pages`, says which registration a kind's list page draws, or none, so a host can say so too; a registry the host's tidying leaves answers `tidied(registration)`, which `ViewRegistry` gains as an optional member. Unit tests in `@graview/react` and `@graview/pages` hold it in every registration order, with several that replace the page, a view tidied away and a view replaced since, and `verify-address` holds `aKindsListPageDrawsTheViewThatReplacesItThoughAnotherViewOfManyRegisteredAfter` on a hosted app whose host keeps its views. A hosted page carries 0.4 KB more up front (338 bytes minified, 159 gzipped; handed a compiled app, 338 and 146), its budget raised under raises named `a-kinds-list-page-draws-the-view-that-replaces-it-*` in `scripts/budget-raises/`, with the pages face alone and the studio handed in raised beside it.

Compatibility: the look — a kind's list page may now draw a view that replaces it where a later view of many won the kind's cell. The JavaScript API — `listPageViewOf` is new, and `ViewRegistry` gains the optional `tidied`. Ops and primitives — unchanged. Stored formats — unchanged. The wire — unchanged. The declaration and check finding codes — unchanged. Derived tool names and input schemas — unchanged.
