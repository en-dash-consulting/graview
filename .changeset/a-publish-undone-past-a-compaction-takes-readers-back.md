Undoing a publish after a compaction takes readers back to the publish before it, as it does in a store never compacted. How far readers are served was read only from the publish ops in the log's tail, and a compaction was held back only by the latest one: it could archive the publish before it, and undoing the latest then served readers the horizon — the very changes the publisher meant to withdraw. And once the last publish op was archived the store knew of no publish at all, so `store.checkpoint` pinned readers at seq 0 and never compacted again. Now a checkpoint keeps what stood published at its seq (`Epoch.publishedThrough`), `publishedSeqOf` reads it when no publish in the tail stands, a compaction stops at the publish an undo of the latest goes back to as well as at the latest, and an undo that would still send readers behind the horizon — over a checkpoint written before it kept this — is refused ("Cannot undo this publish: what was published before it is behind the undo horizon …"), naming a publish through an earlier change instead. `a-publish-undone-past-a-compaction-takes-readers-back.test.ts` holds it: the reader's view after the undo is the uncompacted one, a store opened on the checkpoint knows what was published and compacts again after the next publish, and the refusal.

Keeping the modules on and what stood published in a checkpoint, and reading them there, costs a hosted page 0.5 KB more up front (495 bytes minified, 122 gzipped), and a page handed a compiled app the same 0.5 KB (495, 98), under raises naming this changeset; the pages face alone 489 / 67 more, a visitor's form handed a compiled app 495 minified and every face 512 gzipped, each under a raise of its own.

Compatibility: ops and primitives — unchanged; a publish op is the one it was. Stored formats — additive: a checkpoint may carry `publishedThrough`, which a build that predates it ignores; a checkpoint written before it carries none, and a store opened on one knows only the publishes in its tail, as it did. Undo — an undo of the publish standing now is refused when the publish before it is behind the undo horizon, where it was accepted and served readers the horizon. The wire — unchanged. The declaration and check finding codes — unchanged. Derived tool names and input schemas — unchanged. What Graview Cloud does: nothing; a host compacting an app that publishes keeps the one publish before the latest in its log.
