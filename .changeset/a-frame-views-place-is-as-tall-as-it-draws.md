A frame view of many at its own place is as tall as it draws at every width. The frame took every height its guest asked for (`autoSize`), but its place drew it inside a frame most of the window tall, at most 760px, that scrolled inside itself: a view that fit on a phone was cut at that frame's foot on a desk, and nothing was said. A frame view's place now flows with the page, as a worker view's has since its manifest's `flows`; `guestView({ flows: false })` keeps the place's frame for a fixed canvas. As for a worker view's place that flows, a frame view's place narrowed by `?filter=` no longer says so above the view, and a kind's list that opens as that place draws the built-in list where its address carries `?filter=`. A guest that asks to be taller than `limits.maxHeight` is still given that most, and is no longer cut unsaid: the host's `onProblem` is told once, with a new code, `taller-than-allowed` (`VIEW_PROBLEM_CODES`), and `createGuestHost` takes `onProblem` for it. The guest client is unchanged, and so is `GUEST_CLIENT_SHA256`.

Compatibility: ops and primitives, stored formats, the wire, derived tool names and input schemas, and the declaration and check finding codes — unchanged. What Graview Cloud does: nothing to call. With this version a frame view of many at `/places/<name>` flows with the page; a frame whose manifest asks to keep a fixed frame is passed `flows: false` by its host. A host that counts view problems by code gains `taller-than-allowed`, said when a frame asks for more than the `FRAME_MAX_HEIGHT` it was given.
