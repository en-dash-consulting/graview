Five things that tripped a chat writing worker views for a children's rocks-and-minerals app now work as an author expects (Roadmap f-view-authoring-friction-2026-11).

A view of one record reads its own kind across a relation back to it. A rock's page that read `becomes` (rock → rock) was handed no linked rock until `rock` was added to `reads.kinds`, and nothing said why. Now a view of one is handed the records of its own kind that a relation it reads links to its record, in both directions, and only those; `reads.kinds` naming the kind still hands every record of it. A relation in `reads.edges` with an end the view is never handed is said, with the kind to add ("\"rock-page\" reads the relation \"foundIn\", from rock to place, and is handed no place, so no link of it reaches the view: add \"place\" to its manifest's reads.kinds."), among a headless run's problems (`graview view check`) and to the page host's `onProblem`. `ownKindRelations`, `edgesReadWithoutTheirKinds` and `edgesReadWithoutTheirKindsSaid` are on `@graview/guest/host/views`.

The press check passes a control already in its state. An "All" chip pressed while nothing is filtered changes nothing, rightly, and was refused as a control that does nothing. A press that changes nothing on a control that says its state (`aria-pressed="true"`, `aria-selected="true"`, `aria-checked="true"`, `aria-current`) passes and says so; one that says no state still fails.

A view may lay its cards in CSS columns and keep each whole in one. `columns` and its family were kept already; `break-inside`, `break-before`, `break-after`, their `page-break-*` forms, `orphans`, `widows` and `box-decoration-break` are now the open kit's too. The whole list a view's CSS is held to is `CSS_PROPERTIES` (with `CSS_FUNCTIONS` and `CSS_AT_RULES`) on `@graview/core/css`, which the `graview-view-drawing` skill now points to.

A brand lends its views web faces. A view's stylesheet still loads nothing, `@font-face` included. `brand.views.fonts` names a face and its one file (`{ "family": "Baloo 2", "src": "/graview/assets/<sha256>.woff2", "weight": "400 800" }`), and the view's host loads it into the page as a `FontFace`, only from where it already lets a view's images come from: a file the app holds, where the host says those are served (`asset`), or an `https:` address on an origin it lists (`images.origins`). Anything else is said and not fetched. A view's sheet and the app's sheet for views then name it as any face. `graview check` holds each face to the rule the host loads it by (`brand-views-font`: a plain family name, a WOFF2, WOFF, TTF or OTF file at one of those addresses, a weight and style, at most eight), `set-brand` takes `views.fonts` whole and says "Views may draw in Baloo 2.", and the diff says the same. `viewFontProblem` and `viewFontSource` are on `@graview/core/css`.

The app's theme wins. The brand's `views.css` was drawn before each view's own sheet, both unlayered, so any rule a view wrote beat it and a design system could not hold. Every sheet in a view's region is now in a cascade layer of the host's: `graview-motion`, `graview-region`, `graview-view`, `graview-theme`, in that order. Where the theme and a view style the same element the theme's rule wins whatever the view's specificity, and a view's `!important` is the one way past it. The host's own `!important` rules (the focus ring, less motion, a drop target) are in the first layers, so nothing a view writes takes them away. Neither sheet can write `@layer`. A headless run's `css` is drawn in the same layers, so a picture of the view is dressed as the page dresses it. `set-brand` now says "Every view is drawn with the app's own stylesheet, whose rules win over its own."

Tests: `a-view-of-one-reads-its-own-kind-across-a-relation-back-to-it`, `a-press-on-a-control-already-in-its-state-passes-the-check`, `a-view-lays-its-cards-in-css-columns`, `a-view-draws-in-a-face-its-app-lends-it` and `the-apps-theme-wins-over-a-views-own-rule` (guest), and `a-brand-lends-its-views-faces-it-declares` (core). guest-sandbox's brand and presses transports prove the theme winning, the lent face loaded and drawn, an "All" chip passing the press check run in the page's own worker, and cards kept whole in three columns, in a real browser.

A hosted page's first load grows by 0.2 KB more up front, for the shape of `brand.views.fonts` in the document schema (`scripts/budget-raises/view-authoring-friction-hosted-page.json`). Every face grows by 7.0 KB (2.9 KB gzipped), the guest host drawing a worker view on the open kit by 4.5 KB (2.5 KB gzipped), registering one by 1.1 KB (0.4 KB gzipped), and the embed with the studio handed in by 3.1 KB (1.3 KB gzipped), each under a raise of its budget.

Compatibility: ops and primitives — unchanged. Stored formats — unchanged. The wire — unchanged. The declaration and check finding codes — additive: `brand.views.fonts`, and the finding `brand-views-font`. Derived tool names and input schemas — `set-brand`'s `views` takes `fonts`. Changed: a brand's `views.css` now wins over a view's own rule on the same element, where the view's used to win; a view of one that reads a relation from its kind to its kind is handed the records it links to.

What Graview Cloud does: `propose_view` and `get_problems` may now show a view's unreachable relation among its problems. A page that lends faces from an `https:` origin needs that origin in its `font-src` and in the view's `images.origins`; one that lends a file the app holds needs `font-src` to allow where `/graview/assets/` is served.
