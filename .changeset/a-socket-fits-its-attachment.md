A socket's state fits a Durable Object's attachment. A hibernating host keeps each socket's `LiveSocketState` in `serializeAttachment`, which Cloudflare refuses over 2,048 bytes, and the state held the whole seat — a person with fifty roles is about 1.9 kB of it on their own — and a `cid` of any length, kept in `held` while a call is busy. Now `seat` may be a host's key, a string — `live.open("user:6b3f…", "web")` — and `liveProtocol({ seatOf: (key) => principal })` resolves it on every message, so the socket is judged as the principal the key names now; a key the host no longer knows is answered `error` ("This socket's seat is no longer known to this app: open it again to be served.") and served nothing, pushes and presence included. A call's or undo's `cid` is at most 64 characters, and a longer one is refused `invalid` in words, before it is kept anywhere. The budget, held by a test: with a seat key, a busy call held and the host's own presence beside it, a socket's state stays within 1 KB — measured, 350 bytes of state and 692 with a presence, where the same state with a fifty-role seat held whole was 1,895 and 2,237. `ServedSocket` — the socket a host's `build` and `viaOf` are handed, with its seat resolved — is exported from `@graview/ship` and `@graview/ship/runtime`.

Compatibility: the live protocol — additive for a host: `LiveSocketState.seat` may now be a string, `open` takes one, and `LiveProtocolOptions` gains `seatOf`; a host that keeps principals is served as before. Code that reads `state.seat` as a `Principal` should narrow it. A socket whose `cid` is over 64 characters is now refused `invalid` where it was served: `openRemote`'s are far shorter. `WIRE_PROTOCOL`, `REFUSAL_REASONS`, ops, stored formats and check codes are unchanged.
