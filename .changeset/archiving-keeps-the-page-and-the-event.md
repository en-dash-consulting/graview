Archiving a record keeps its Notion page or its Google Calendar event. A record set aside, or merged into another, had its page put in the trash and its event deleted, with its guests told when the connection notifies them, and a new one made when it was brought back. Now nothing is sent for it: the page or event stays as it is, stays linked through a restart, and is the same record's when it is brought back; what changes there meanwhile is taken, links to a record set aside included; only `remove-<kind>` deletes. A page or event deleted there while its record is aside leaves the record here, said once; a new one is made, and said, if it is brought back. One that only left the connection's filter or data source stays linked while its record is aside; if it is still out when the record is brought back, the record is kept, said, and not in step until it is in again. A record already aside whose page or event an earlier version deleted is sent nothing until it is brought back; a new one is then made, and said, and a connection that notifies its guests invites them again. A person set aside stays a guest of the events they are on, and of no other. A Notion relation that did not change is not written again with the rest of its page. (hq:feature:f-archive-keeps-synced-counterpart)

Compatibility: BEHAVIOR CHANGES for a host with a Notion or Google Calendar connection, declared or wired through `googleCalendarMapping`: an archive or a merge no longer trashes the page or deletes the event, so a host or a person who relied on that to clear them out runs `remove-<kind>` instead, and a merge leaves two there. A page or event deleted there while its record is archived no longer removes the record of a declared connection kept both ways (one that only reads still removes it; one wired by hand does as its `removeInbound` says, and says nothing, unless it hands `setAside`). The look — unchanged. The JavaScript API — additive: an optional `setAside` on `SyncOptions`, `alone` and `aside` on `SyncState`, `left` on `RemoteChange`, and a second argument `RemoteSystem.pull` may read; `GuestGraph.allNodes` takes an option, and one that ignores it is read as before. Ops and primitives — unchanged; a link to an archived record taken away in Notion or Calendar brings the record back and archives it again in the same batch, as Todoist's does. Stored formats — a sync state may carry `alone` and `aside`, optional; an earlier version run on it deletes the page or event of an archived record again. The wire — unchanged. The declaration and check finding codes — unchanged. Derived tool names and input schemas — unchanged.
