A host can refuse a view's own faces while the faces the app lends still draw. Graview Cloud lends its views only the web fonts it lists, and keeps no font files of an app's own, so it wants none of a view's own faces drawn either. `mountWorkerView` and a registered worker view's definition (a draft's too) now take `ownFaces: false`, and so does `runWorkerViewHeadless`. With it, each `@font-face` a view's stylesheet declares is refused, nothing of it is loaded, and the rest of the sheet is drawn as before. The view's console and the host's `onProblem` are told once per face, by its family: "This host draws no face a view's own stylesheet declares: a view is drawn in the faces the app lends its views (brand.views.fonts), or in a system stack (view-font-face-host)." The open kit's half is `sanitizeStylesheets(…, { faces: { refused: true } })`: each face is refused as `{ reason: "font-face", name: "host" }`, none is kept, and a face that would have been kept counts toward no budget, so a large one does not refuse the sheet for its length. Without the option, a view's own faces draw as they did. The `graview-view-drawing` skill says a host may refuse a view's own faces. Held by a unit test of the guest (`a-host-refuses-a-views-own-faces-and-lent-faces-still-draw`): faces refused on the page and in a headless run, the lent face still loaded and drawn, and the default unchanged. A hosted page stays within its budget; registering a worker view loads 36 bytes more up front, drawing one on the open kit 523 / 169 more, and every face 1_192 / 313, under raises named `a-host-refuses-a-views-own-faces-*` in `scripts/budget-raises/`.

Compatibility: ops and primitives, stored formats, the wire, the declaration and check finding codes, and derived tool names and input schemas — unchanged. The JavaScript API is additive (`ownFaces`, `SanitizeOptions.faces.refused`, the `"host"` face refusal). What Graview Cloud does: pass `ownFaces: false` on each worker view's definition and to its headless runs.
