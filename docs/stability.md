# What a version may change

A host runs thousands of stored apps on one build of `@graview/*`. Before it takes a new version it needs to know three things: whether stored data folds the same, whether a declaration that compiled still compiles, and whether the tools a model calls moved. This page is the promise, and `capabilities()` is how a host reads what a build ships instead of guessing from a number.

Every `@graview/*` package shares one version (a changesets `fixed` group). Before 1.0, a minor may break what this page allows a major to break; each break is still said in a `Compatibility:` line. From 1.0 on, the rules below hold within a major.

## The five surfaces

### 1. Ops and primitives: the stable contract

An `Operation` and its `Primitive`s are history, and history is never rewritten. Within a major:

- Never changed incompatibly. A field may be added if it is optional, and an op without it reads as before (`via`, `author.name`, `author.onBehalfOf` arrived this way).
- No field is removed or changes meaning. No primitive is removed.
- A fold of the same log gives the same graph on every version of the major.

- An op may say what it was based on (FR-172): `lineage: { basis, confidence?, model? }`, a basis of 1–500 characters, a confidence from 0 to 1 and a model name of 1–120, given as `ApplyOptions.lineage` (or on `AppendOp`) and checked before anything is kept; a store refuses one that is not a lineage with a `GraphError`. An undo of an op that carried one keeps it as `undoneLineage`, so a host reading the log can tell a suggestion was declined without the op it took back. `Batch.lineage` is its first op's. Both fields are optional and additive within op format 1: an op without them reads and folds as before, and a build that predates them keeps them on an op it receives and draws nothing of them. A link whose making op carried a confidence below 1, by any author but a person, is PROVISIONAL until a person's op takes it away and puts it back — `keep-link` (`KEEP_LINK`, `{ kind, from, to }`), an act every store answers to and no list of acts offers, permitted to whoever may run an act that makes or breaks links or makes records, and refused as `missing` to a seat that may not see either end, alike whether the link is there or not (FR-55) — or the link is taken away; an undo of that keep makes it provisional again. `linkProvenance(store, edge)`, `isProvisional`, `provisionalLinks` and `provenanceWords` (`@graview/core/provenance`) are the one answer every face and host reads; nothing in the framework decides what to link.

A major that must change them ships `upgradeOp` steps (below).

FR-173 added one optional field and no primitive. An archived record is said on the record itself, `$archived: true` (a key no declared field can take), written and taken off by an ordinary `patch-node`, so archive and unarchive fold, undo and travel through every adapter as any patch does. The op of a merge carries `mergedInto`, the id of the record the duplicate went into; an op without it reads as before. A version before FR-173 folds the same log to the same graph, and reads an archived record as a live one with one more key.

### 2. Snapshot and log formats: versioned

What is stored carries the format it was written in (FR-31). `FORMATS` names the current formats (`snapshot`, `op`), and `formatStamp()` gives `{ framework, formats }`. A store's meta and every bundle are stamped with it.

- A reader meeting a newer format says so with `NewerFormatError` and does not fold it. The host refolds from the log or rolls forward. Rollback is therefore always safe: the previous version never misreads what the next one wrote.
- An older format is brought up by `upgradeSnapshot(snapshot, from)` and `upgradeOp(op, from)`, one step per format change. Each step ships with a test over a fixture of the format before it (`packages/core/tests/fixtures/formats/`).
- Anything written before stamps existed (0.1.0) is format 1.
- A log compacted behind an undo horizon (FR-23) is not a new format. Its ops are ops, its checkpoint is an epoch marked `horizon`, and the archive sits beside it. A build before compaction refuses such a store on open, because its log no longer begins at seq 0. It never misreads one.
- A checkpoint keeps who made each record behind it (`Epoch.creators`, record id to seat id), so an `own` sight knows them after a restart without the archive. The field is optional and additive within format 1: a checkpoint without it opens as before and knows its makers from the horizon on, and a build that predates it ignores it, folds the same graph and judges sights as it always did. A build that predates it and compacts again writes its next checkpoint without the field. Epochs are never served to a seat, so the ids it names stay with the host.
- A snapshot file — a seed, a projection a product emits, what `graview serve --seed` and `graview sync-seed --seed` read — is `@graview/core/snapshot`'s line format, `"format": 2` in its header line: when it was made (`generatedAt`), records per kind, links per kind and where each kind's lines are, then one record per line, each kind's together, then the links. A header key may be added when it is optional; anything a reader needs to find a kind's lines moves the format, and `readSnapshot` refuses a newer one by its number. An old `{ nodes, edges }` file is format 1 and reads on every build of the major (`readSnapshot`, `fetchSnapshot`, `--seed`). What an adapter stores (`snapshot.json`, a browser's `localStorage`) is not this file and is unchanged.

### 3. The wire and live protocols: additive within a major

`WIRE` (in `@graview/ship`) lists every route `serveStore` answers, and `createStoreHandler` answers the same routes in any runtime (FR-09). `WIRE_PROTOCOL` numbers the protocol. The guest-view protocol (`@graview/guest`, FR-04) is held to the same rules, and `GUEST_PROTOCOL` numbers it.

- Within a major, a route or a response field may be added. None is removed, renamed or changed in meaning.
- A request field the server does not know is ignored, never refused.
- A `call` or an `undo`, on the socket and over `POST /graview/ops`, may carry `lineage` (FR-172); the store checks it, a change whose lineage is not one is refused as `invalid` with nothing kept, and the ops every client is sent carry it. `openRemote` sends the lineage a call or an undo was applied with, and again when it sends a change again. A server that predates it ignores the field and keeps no lineage, so a host reads `capabilities().shipped` for FR-172 before it relies on one.
- The live socket at `/graview/live` (FR-05) holds to the same rules: a message type or a field may be added, and a message the server does not know is ignored. `hello` and `welcome` carry `WIRE_PROTOCOL`, so either side can tell what the other speaks. Its seqs mean what `/graview/since?seq=N` means.
- A refusal's `reason` (FR-46) is one of `REFUSAL_REASONS` — `forbidden`, `missing`, `invalid`, `limit`, `unavailable`, `refused` — on the socket's `refused`, on every refusing answer of the routes and on an agent tool's refused answer. A code never changes meaning. Before 1.0 a code may be added, and the changelog says so as a change to this surface; from 1.0 none is added within a major, so a program that branches on all six has branched on every refusal. `refused` (FR-119) is an act's own rule saying no to a well-formed call — a document act's `allowedWhen`, a TypeScript mutation's `ActRefusal`, whose reason is `refused` unless it names another; `invalid` is the call as sent — its arguments, one the act does not take (FR-121), a call that changes nothing. A client that predates `refused` treats it as it treats any code but `unavailable`: final, the change taken back. `wouldNeed` is the roles that could, when the policy knows them. A call naming a record the seat may not see is refused exactly as one naming a record that does not exist — `missing`, one sentence that names the act and not the id (FR-55) — and permission is asked of it as if the record were not there, so no refusal tells a guessed id from a real one. An act runs under its caller's sight (FR-55): its body, its condition, its refusal and its sentence read the store as the caller is served it, so a record the caller may not see is to the act what one that does not exist is — whether it runs, what it refuses with and why, what it writes and what problems it answers with are the same for a hidden record as for an absent one, and the page that guessed the outcome from the seat's view is confirmed by the host rather than refused after it. What it writes lands on the whole store, and the store's own bookkeeping reads the whole store — a removed record's links, a patch's prior values, a single source's other links, an id already taken — without telling the seat (FR-55). Ids are unique across the store, so a seat that may not see every record may not ask for the id of one it makes: it is refused alike (`invalid`, "… makes its own id here") whether a hidden record holds that id or nothing does. An id minted from a label for a kind the seat may not see every record of is the seat's own — `room:green.<mark>`, where the mark is `seatMark(<the seat's id>)`: seven letters and digits, the same for the seat on any store, which no other seat's label mints and which does not spell who the seat is, since every seat that sees the record reads its id — stepping only past what it sees, and one that would land on a hidden record anyway (an id somebody asked for) takes a suffix no guess collides with; a seat that sees every record of the kind gets `room:green`, `room:green-2` as before. An act that sets a single-source link and takes a hidden record's link with it is served to the seat whole, with what it may see — the link it took is no part of its op — and the seat may undo it, which puts that link back. A rule that must hold across what a seat may not see — no double booking — is an invariant's, not an act's. `graview check` warns of each act that reads a kind some role allowed to run it may not see (`act-reads-hidden-kind`, FR-105), reading a document's act for itself and a TypeScript act by the kinds it declares it `reads`: run by that role, it judges as though there were none. A seat's problems are judged over what it sees, facts and lines included, wherever it reads them — `seenBy(…).violations()`, a seat's tools, a page served only what its seat sees — so a rule that counts records the seat may not see says the count it sees, and a record it may not see never makes, mends or words one of its problems. An act's answer to a seat (`answerSeenBy`) gives what the act broke, what it mended and what stands after it — a change made or a preview — as the seat judges them over its own world: what it is served, and that world with the change as it is served taken back, or for a preview put on. So whether a rule that reads beyond its subject (a fact, a sweep, a relation) was broken or mended is the seat's own answer, in its own words, and never the whole graph's; the judging is `@graview/core/lines`', which a seat's tools load, and without it an answer to a seat says no problems at all. A fact in a rule's line is said by its `label`, or its name in words. `graview check` warns of each rule whose message says a fact over a kind some role told of it may not see in full (`rule-says-hidden-fact`). A rule is judged on every change and once on load; one that reads the clock — `today()`, `now()`, a computed field that does, a kind whose records retire on a date — is judged again on the day a host ticks the store to (`store.tick(now)`, FR-176), which answers `{ day, was?, appeared, cleared }` and tells every subscriber with an empty diff and no ops, logging nothing. `@graview/ship`'s `openStore` and `openRemote` tick just after each midnight by the clock `today()` reads (UTC) until `close()` (`openStore`'s `tick: false` leaves it to the host); a host that sleeps through timers ticks from its own alarm. A tick holds for the rest of the day the clock read when it was made: once the clock's day moves past it, the store judges on the clock again until it is ticked, so a timer that slept through midnight never leaves a store on yesterday. `clockReaders(schema, rules)` on `@graview/core/check` says which rules and computed fields read the clock, and `graview check` notes them (`rules-read-the-clock`). A store pinned to a day (`invariantOptions.today`) stays on it.
- `busy` (FR-45) is not a refusal: the host asked for the change again after `retryAfter` milliseconds (429 with `Retry-After` over HTTP), nothing was judged, and a client keeps the change. `limit` is a refusal: the change can never succeed as asked, and is taken back. `unavailable` is the one refusal that is not final: the host takes no changes for a while and cannot say how long (503 over HTTP), nothing was judged, and a client keeps the change and sends it again, backing off. A call sent again after it landed is answered with its ops before a host's `limit` is asked, so it is never told busy, `limit` or `unavailable`.
- A field's revision, which a stale write is refused against, is the seq of the op that last wrote it. It is derived from the log and never stored, so it never changes a stored format.
- `WIRE_PROTOCOL` moves only when a client of the previous protocol can no longer be served, and that is a major.
- A host that stops serving an older protocol says so with `reload` (FR-44): `minProtocol` names the lowest it serves, and a client carries its unsent calls across the reload. `hello.wire` and the subprotocol `graview.ship.1` name ship's codec, so a host can serve another beside it on one path. `build` in `hello` and `welcome` is the host's opaque string and is never judged. A host numbers its own half of the wire with `hello.hostProtocol`, which `minHostProtocol` answers with `reload` carrying `hostProtocol`; `hello.protocol` stays `WIRE_PROTOCOL`.
- A client names its batch as a `Store` mints it, `batch:<tag>:<n>` or `undo:<tag>:<n>` (`isClientBatch`); any other is refused `invalid`. A batch sent again is answered only with the asking seat's own ops, and one that holds somebody else's is refused `invalid`. A server mints its own batches outside that shape (`served:…`), and serves another seat's withheld op under an opaque `withheld:<16 hex>` batch. A `via` in a call or a post is a claim, ignored unless the host's `viaOf` accepts it (FR-52).
- The declaration `version` a welcome, a route and a `declaration` push say is the host's own monotonic number for the declaration it serves, the one a client hands `resolveApp`; a push with the number a client already serves is ignored.
- A declaration change is pushed as `declaration` (FR-43), and every welcome says the declaration `version` it serves. Neither moves `WIRE_PROTOCOL`.
- A host that holds the app read-only says so (FR-66): `{ t: "held", sentence }` to every socket that said hello when the hold starts, `sentence: null` when it ends, `held` in every welcome and on every answer a poll reads while it stands, and every change meanwhile refused `unavailable` in that sentence. Additive to protocol 1, so it does not move `WIRE_PROTOCOL` or the codec's name: a client that does not know the message ignores it.
- What a seat is served holds no id of a record it may not see (FR-55): not in the snapshot, the log, an op's primitives, inverse, reads, writes, call or sentence, a presence, a conflict, `/graview/health` or a tool's answer — beyond the seat's own words. A field whose current value this seat wrote (or the person an agent acts for; an undo is never the author of what it puts back) is served as written, whatever it names, and a record withheld only for such a field is served; so is the seat's own call in its own ops, and an argument it sent that an answer says back. A seat that guessed an id and wrote it is then served the same whether the guess was real, and a write of the value a field already holds, when that value names what the seat may not see, is kept in the log as the seat's. An oracle that checks what a seat is served excludes the strings the seat itself wrote. An act's sentence is worded from its author's view: `describe` reads the graph as the author is served it, so a record the author may not see is named only by what the author wrote, as one that does not exist is — and a reader who sees more reads that sentence as the author would have. The seat's own words excuse only what it wrote — values in its primitives and the inverse that puts them back, and its own calls; another author's call, sentence and name are judged by sight alone. An op records which records its sentence read (`described`), and another author's op is served whole only when its reader may see every one of them. An answer's `reads` name only records the seat sees; an id that names no record is left out as a hidden one is. `seatLens` is the judgment, and `seenBy`, `logSeenBy`, the routes, the live socket and the agent tools all read it. A seen record whose field names a hidden one is served with that field cleared when its kind declares the field optional (or does not declare it); when the field is required, clearing it would serve a record that fails its own declaration, so the record is withheld from that seat whole, as if its sight did not reach it — with its links, and with every op that touched it withheld. An op whose only mention of a hidden record is in its `reads` or `writes`, and whose primitives are served as written, is served whole with those trimmed. A link the seat is not served is no part of an op that did anything else: it is left out of the op's primitives and of its inverse, and the op is judged without it — so a removal that takes a record's links to what the seat may not see is served to the seat whole, as it would be had there been no such link, and the seat may undo it (the undo puts the links back, and is served to the seat the same way). An op that did nothing but such links is withheld. Any other op that names a hidden id is withheld, and its primitives are judged by whether each record was served just before and just after them: served to served is the patch as the seat is served the record (a hidden id written into an optional field arrives as that field cleared, `UNSET`); not served to served is an `add-node` of the record as now served, with its links to records the seat is served; served to not served is a `remove-node`; neither is nothing; and a link is served when both its ends are — an end that is not there at its moment, as a dangling link a repair removes has, is judged as `seesId` judges its id, so one that names no record is served and one that names a record the seat may not see, removed before, after or with the link, is not (FR-67). A seat from whom nothing is kept (`hidesFrom` false) is served every op as it is. So the log a seat is served folds — from nothing, from any cursor, or from the epoch base its view serves after a compaction — to exactly the snapshot it is served. `/graview/health` keeps `ok` and every count the whole store's — a poller asks whether the store is well, a count names no record, and a count of only what the asker sees would call a broken store well — and its `danglingEdges` names only the links whose ends the asking seat may be told of; a caller the host cannot tell is judged as a seat with no id and no roles. This narrows what a seat is sent and never adds a field, so it does not move `WIRE_PROTOCOL`.
- A sight may keep fields as well as records (Roadmap f-field-sight): `policy.sees[].hide` (field names it keeps) and `policy.sees[].fields` (the only field names it shows), both optional. A field of a record is shown to a seat when ANY sight that shows the seat that record shows the field — sights add up, `own` and `via` judged as for the record — so a sight with neither key shows every field. A field kept from a seat is never in anything it is served: the record (cleared, or the record withheld whole when its kind requires the field, as for a required reference), its log (an op that adds or removes a record with a kept field, writes one, or whose sentence read one is withheld whole whatever the field held, its primitives served as the seat is served the record; its own ops are served as it wrote them), an answer's diff and primitives, a conflict (a revision of a kept field is not compared or said), a search hit, a name a call resolves (a label is worked out from the served record), a form, an edit offered in place, a static page, a computed field (worked out over the served record) and a rule (judged over what the seat is served, so a kept field reads as none) — and nothing a seat reads differs between a kept field that holds a value and one that holds none. A seat may not write a field kept from it: an act that would is refused `invalid` as an argument it does not take ("does not take "phone"; it takes …"), asked before a write of the value the field holds is let go as no change, so the refusal is the same whatever it held and whatever was written; a kept field an act leaves unset is no write. An import refuses a column that goes to a kept field exactly as one that goes to no field. An op's `described` may name `<id>#<field>` for each field of a record of a kind some sight keeps fields of that its sentence read. Judging fields is `@graview/core/field-sight`'s; until it is loaded, a sight with `hide` or `fields` shows nothing — the store keeps the record rather than serve a field it cannot judge — except in a store `openRemote` opened, which shows what its host served it. `@graview/ship` loads it (its `openStore`, in a page as on a server, and its server routes); a host that makes a `Store` of its own imports it. A build before 0.1.29 ignores both keys and shows the field: a host serves a declaration that says either only on a build that exports `FIELD_SIGHT` from `@graview/core`.
- An act may touch what its seat cannot see (FR-55), and `replaces` (FR-115) is such an act by design. Before it connects, it severs the subject's links of the relations it names, all but the one it makes — whatever record is on the far end, seen or not — exactly as connecting a cardinality-one relation severs the link it displaces. A seat that moves a component to a new owner may so cut its link to an owner it may not see. That is the policy, not a leak: the seat is served the severed link as nothing (a link is served only when both its ends are), the op as its primitives are judged above, and an agent tool's answer the same way, so the act changes what the seat cannot see without telling it what was there. An installation that must not let a seat displace a hidden record says so in the act's condition or its grants, not by relying on sight.
- A status board's moves (FR-108) are judged against the graph the page holds, and the host judges them under the seat's sight. On a served app the page holds the seat's view, so a named step whose condition reads a record the seat may not see is judged without it on the page and at the host alike: a step is offered exactly when the host would run it, and run when offered. Nothing tells the seat what it cannot see, and nothing moves `WIRE_PROTOCOL`.
- A host's files (FR-163) are a seam on the page, `files: { upload(file, name), maxBytes, kinds }` on `mount`, `<Embed>`, `GraviewProvider`, the Shell and the routed face's context, and the route that serves them is the host's own; within a major the seam's three members keep their meaning, and the value `upload` answers is a `FileValue` (FR-162) the record keeps as it is. What the route serves is part of the app's origin, and the page draws it as such: a picture in an `<img>`, which never runs a script, an SVG's included; a PDF in an `<object>`, which draws whatever type the route answers with; anything else as a link with `download`. So a host's files route: serves each file as the type the host decided from its bytes, never the type the uploader said, with `X-Content-Type-Options: nosniff`; sends `Content-Security-Policy: sandbox` with everything but a PDF (an SVG or an HTML file opened from it, in a tab or in that `<object>`, runs as the app otherwise), and with a PDF where its readers' browsers draw one sandboxed; says `Content-Disposition: attachment` for anything that is not a picture, a PDF or plain text; and serves a file only to a seat that sees a record holding it, the framework's sight being per record (`seesId(store, principal)` over the records whose fields hold the `href`, by `filesOf`). The dev door (`devFiles`, `@graview/ship/dev`) does the rest but the first and the last: it keeps the type it was sent, which under `nosniff` and the sandbox runs nothing, and every seat on a dev server is its one person.
- A host's way to name another app (FR-171) is a seam on the page, `resolveApp(address, viewer)` on `mount`, `<Embed>`, `GraviewProvider` and the routed face's context, answering `{ name, icon?, headline?, href }`, `{ denied: true }` or `null`; within a major those three answers keep their meaning. The page asks once per address and viewer and remembers the answer for as long as it holds that resolver; a throw is taken as `null`. A viewer the host refuses is shown "linked app (no access)" and nothing the host did not answer, so whether another app exists, what it is called and what its home says stay the host's to tell each viewer. Without a resolver the address is drawn as it is kept, a link only when it is an absolute http(s) address, opened apart from the app (`rel="noopener noreferrer"`). `href` is followed only when it is a path on the host or an http(s) address.
- A worker view's manifest and what it is handed are held to the guest protocol's rules: a key may be added when it is optional and a manifest without it means what it meant; a build that predates a key passes it over (one before 0.1.18 draws a view with `replaces` as it drew every view of one: alone). `replaces` arrived this way (FR-149): `"page"` on a view of one record draws it alone in place of the record's own fields, and `checkManifest` refuses any other value and the key on a view of many or of the home. What a view of one record replaces changed without the manifest's text: since FR-149 a view of one is drawn above the record's own editable fields on the scene (on Pages it always was), where it was drawn alone; a host that relied on the record being the view alone adds `replaces: "page"`. `data-prefill` (FR-150) is an attribute a view draws, judged by the host: it fills only an empty `input` or `textarea` whose `name` is the field, from a record the view was shown, read through the viewer's sight, when an act in its `fieldset` named in the manifest writes that field of that record and the viewer may run it there; a press carries the value only back into that field, and any other press carrying it is refused `untyped`. A view's props are as they were: each record's fields on it by name, beside `id`, `kind` and `label` (FR-151 corrected the guide, not the props). `GUEST_PROTOCOL` does not move.

### 4. The declaration, the document format and check finding codes

A declaration that compiled and checked clean on one version compiles on the next version of the major.

- A check finding's `code` never changes meaning. A new code may appear, and a new warning or note is not a break. A new *error* on a declaration that used to pass is a break.
- A code that only ever said again what another code says may be retired, and the changelog says so. `act-without-title` was retired this way: a mutation without a title was reported twice, as that warning and as the error `mutation-untitled`, which names the path and the fix and is the one finding now. A program that matched on the retired code matches on `mutation-untitled`.
- The stored-data finding codes of `validateGraph` (FR-21) hold to the same rule. Each is a record, a link or a rule that no longer fits the declaration, found by id:

  | Code | What it says | `repairPlan` |
  |------|--------------|--------------|
  | `node-shape` | a record's field does not fit its kind (`detail` names the field) | clear an optional field, coerce a required one to its default, else drop the record with its links |
  | `kind-unknown` | a record of a kind the declaration no longer has | drop it, with its links |
  | `edge-dangling` | a link to or from a record that is not there | drop the link |
  | `edge-disallowed` | a link the declaration does not allow between those kinds | drop the link |
  | `rule-error` | a rule threw rather than judged (`could-not-judge`; `detail` names the rule) | none: the declaration's to fix |
  | `rule-budget` | a rule would have read more than its budget (`over-budget`) | none: the declaration's to fix |

- The declaration document format (FR-01) is versioned like a stored format, and `capabilities().documentFormats` lists what a build parses.
- A key may be added to a document format within its version when it is optional and a document without it means what it meant: `kinds.<kind>.computed` (FR-83) arrived in `graview-document@1` this way. Every key is closed, so a build that predates one refuses a document that uses it as `unknown-key`, by path, and never misreads it. A host that keeps documents for more than one build reads `capabilities().shipped` before it writes the key.
- The app's money arrived the same way (FR-100). Its one home is the brand: `brand.currency` (a three-letter code) and `brand.locale` (a language tag) in a document, `Brand.currency` and `Brand.locale` in a declaration, and a document's `brand` may now carry them without an `accent`. A figure or a field shown as money takes `currency` of its own; one that names none, and a template's `{x | money}`, take the brand's, written by `Intl.NumberFormat` in the brand's locale ("en-US" when it names none). A document without them says a sum as it always did: a figure with a currency in that currency, anything else as a number with no symbol. A figure's and a meter's `label` became a template (FR-99): a label without braces says what it said. The rule language gained `out(S, 'edge')`, `in(S, 'edge')` and `&`, `|` and `-` between sets (FR-101); an expression that parsed before means what it meant, except that a `|` inside brackets within a template's braces, which was a formatter and refused, is now a join. A build that predates them refuses `brand.currency`, `brand.locale`, a field's `currency` and a set operator by path, but draws a templated label as its words and a two-argument walk as "—", so a host reads `capabilities().shipped` for FR-99, FR-100 and FR-101 before it writes them.
- A number's range arrived the same way (FR-114): `min`, `max` and `step` on a `number` or `integer` field (and on an act's declared argument), each optional, a field without them taking any number as before. The edit vocabulary gained `set-range`, and `DocumentDiff` gained `narrowedRanges`. A range is judged by the checker (`default-range`, `field-range`), not by `readDocument`. A build that predates them refuses the keys by path, so a host reads `capabilities().shipped` for FR-114 before it writes them.
- An act's `setsOther` and `replaces` arrived the same way (FR-115), each optional, an act without them doing what it did. - A compiled app (FR-123) is versioned like a stored format. It is what a host hands its page so the page need not compile: `serializeCompiled(compileDocument(document))`, plain JSON with every template and expression already parsed, which `appFrom` (from `@graview/core/compiled`) builds into the same app `compileDocument` made. It says `"format": "graview-compiled@1"`. `appFrom` refuses another format as `compiled-format`, by name, and parts that do not match their document as `compiled-shape`, and never misreads either; `appFromOrCompile` then compiles the document in the page, so a compiled app cached from another build costs one request, not a broken page. It does the same for one torn on its way (refused `compiled-shape`, never thrown) and for one compiled from another document than the one handed beside it — two documents are the same when their canonical text is (`canonicalize`), so a host hands the document the compiled app was made from, in the current document format. Within a version the format is additive: a key an older page ignores, and a page that lacks it can do without, may be added. Anything a page would need to build the same app moves the version: a new effect, a new kind of argument, a change to what a parsed expression or template part holds. So the rule language's tree (`Expr`) and `TemplatePart` are part of this format, and a parser change that alters them is a format change. A compiled app is a cache of its document, never its source. A host keeps the document, compiles it at its own build, and may drop a compiled app at any time. It is the host's own data, checked for its format and shape and not judged again.

- A picture or a document on a record arrived the same way (FR-162): the field types `image` and `file`, and `list` with `of: "image"` or `of: "file"`, in a document; `imageField()` and `fileField()` in a declaration, which `toDocument` writes as those types. A view's blocks gained `{ "image": "<field>", "as": "thumb" | "gallery", "label"? }`, judged by the check (`view-image`, an error about a block that could not be written before, and `view-format` for its `as`). `graview types` writes such a field as `FileValue` (or `readonly FileValue[]`). A build that predates them refuses the types and the block by path, so a host reads `capabilities().shipped` for FR-162 before it writes them. A compiled app carries the new field types within `graview-compiled@1`: a page that predates them cannot build such a field, refuses the compiled app as `compiled-shape` and compiles the document, which refuses the type by path. A change that leaves no record holding a file says so: `MigrationPlan.files` lists them, and the plan's words name them; what becomes of their bytes is the host's to decide.
- A link to another app arrived the same way (FR-171): the field type `app-link` in a document, `appLinkField()` in a declaration, which `toDocument` writes as that type. The value is another app's address — `@owner/app`, an id its host knows it by, or an absolute http(s) address, at most 500 characters (`isAppAddress`) — and a store refuses any other value as it refuses any value that does not fit its field. `graview types` writes it as `string`. A build that predates it refuses the type by path, so a host reads `capabilities().shipped` for FR-171 before it writes one; a compiled app carries it within `graview-compiled@1`, and a page that predates it refuses the compiled app as `compiled-shape` and compiles the document, which refuses the type by path. A relation whose `to` is another app's kind, an expression that walks one and the history of the far value are not this, and are left for 0.2.
- What a declaration offers may grow without its text changing. An act that sets a status board's field to a value of its own (`book` setting `status` to `"booked"`) is a move to that value's column (FR-108), where a board offered only a free `set-<field>` act; where a named step reaches a column, the free act no longer does. A TypeScript mutation says the constants it sets as `sets`, optional, and one without it reads as before.
- Who the people are arrived the same way, with no FR id (the Graview Roadmap's f-people-kind, f-act-as-me, f-own-end-grants and "visibility scoped by relation"), each optional: `kinds.<kind>.people` (`true` on one kind: a record of it whose id is a principal's id is that person; the declaration's `people: true`, which the installation's `user` says), `policy.grants[].ownEnd` (`true`: every record the call names at the far end of the link the act connects or severs is the principal's own, and every link the act would make or break has the principal's own record at one end — so a connect on a relation of one that would replace somebody else's link is refused; a seat with no id of its own is never offered one) and `policy.sees[].via` (a relation: a record of the sight's kinds is seen only where that relation joins it, at either end, to the principal's own record; `own` reads every relation and what they made). `$me` in an act's effect is the acting person's own record of the people kind — the person, for an agent acting for one — and never an argument, so a document that used `$me` as an argument's name now means the acting person by it; an act that reaches `$me` for a principal with no such record is refused as `refused`, with a sentence. An op whose act wrote its author's own record where its call never named it — `$me`, or `ctx.me` in TypeScript — is undone only by that person (or their agent, or the system): anybody else is refused with a sentence, since the same call by them would have done something else. A document edit's `rename-relation` carries a sight's `via` with it, and `remove-relation` is refused while a sight reads the relation, as it is while a lens draws by it. A TypeScript act reads the same id as `ctx.me`. The checker's codes for them are `people-ambiguous`, `people-unsaid`, `sight-via-unknown-edge`, `sight-via-misses-people`, `grant-own-end-without-link` and a document's `act-me`; none fires on a declaration that says none of the new keys and no `$me`. A kind's JSON Schema says `"x-graview-people": true` on the people kind.
- The edit vocabulary gained the people and the policy (FR-170): `set-people` (`{ kind, people }`; `true` is refused as `people-ambiguous` while another kind is the people, so a move is `false` on the one, then `true` on the other), `add-grant` and `add-sight` (a grant or a sight as `policy.grants[]` and `policy.sees[]` hold one; a role the document's `roles` does not list joins it; a first sight on a document with no policy comes with a grant to everyone of every act, since a sight alone would take every act away), and `remove-grant` and `remove-sight` (named by what they say: a grant's `roles` and `mutations`, a sight's `roles` and `kinds`, each list in any order, and any other key given must match too; two that match are refused, asking for the key that tells them apart; a grant on no kind, `kinds: []`, gives nothing and is refused). `remove-kind` takes the kind's derived `edit-<kind>` and `remove-<kind>` out of every grant, and a grant left with no act or no kind goes; it is refused while every sight shows only that kind, since the sights gone would show everyone everything, so a change says `remove-sight` first. What the change leaves the people and the policy saying together is judged once it is whole, and refused at its last such edit by the checker's own codes (`people-unsaid`, `sight-via-unknown-edge`, `sight-via-misses-people`, `grant-own-end-without-link`); `grant-act` and `sight-kind` name an act or a kind the document lacks. `DocumentDiff`'s sentences say a grant, a sight, a role and the people kind in the words the edits say them, where a policy changed was "Who may do what changes." (still said of a change those do not cover). The studio says a grant, a sight and the people kind it changed as these ops, where a grant or a sight was a `studio-unsaid` finding and the people kind was not said at all. A build that predates them refuses the ops as an edit it does not know, so a host reads `capabilities().shipped` for FR-170 before it offers them.
- The rule language gained archived records (FR-173), optional within `graview-document@1`: `all('<kind>')` reads the live records as before, `all('<kind>', true)` the archived ones and `all('<kind>', 'all')` both, and `archived()` (or `archived(<record>)`) says whether a record is archived. An archived record is out of every computed field, fact, rule and count that does not ask for it, so a rule over a graph with none archived judges as before. A grant, a rule's repair and `editDocument`'s rename and removal of a kind read `archive-<kind>`, `unarchive-<kind>` and `merge-<kind>` as they read `edit-<kind>` and `remove-<kind>`, and `graview check` knows them, so a grant naming one is no longer `grant-unknown-mutation`.
- The app's locale says more than its money (FR-178), with no new key: `brand.locale` (a document's and a declaration's) is what every day, time and number is said in on every face, through `Intl` — a record's facts and glance, a template's `{due}` and `{due | date}`, a moment's `{at}`, a block's field, a rule's line, the calendar, the timeline's hours, the seat's lines, an arrangement's headings — and it is en-US where it names none: "Sep 10, 2023", "3:30 PM", "1,250", where every day was said day first before ("10 Sep 2023"). A host passes the reader's locale as `locale` on the embed, `GraviewProvider` and a pages `PageContext`, which wins over the brand's. What changes is the order and the punctuation of the words a person reads, never a stored value, an op, a tool schema or a finding code; `editDocument`'s and `diffDocuments`' sentences about a locale say "Days, times, numbers and money are written for …", and `describeApp` says what the locale makes of a day, a time and a figure. A host that matched the old day-first words reads them from its build's `capabilities().shipped`, FR-178.
- What a list offers to filter by arrived the same way, with no FR id (0.1.29, the Roadmap's f-filters-that-scale): `pages.lists`, `{ "<kind>": { "filters": [...] } }`, names in order what a kind's list offers — a field, a relation, `is`, or `<relation>.<field>` (a choice at the far end of a relation); a list a document does not name offers what it offered before. `arrange-pages` takes `filters: { "<kind>": [...] | null }` and refuses a key the kind cannot be filtered by, and a filter's grammar takes `<relation>.<field>:<value>`. A template's formatter `excerpt` (`{summary|excerpt}`, `{summary|excerpt: <20–1000>}`) arrived with it, the same way: a build that predates it refuses the template. The finding codes that came with them are warnings and judge only what is new: `pages-filter-unknown` (a filter the kind cannot be filtered by, passed over), `pages-kind-unknown`, the code it was, which now also says a kind `pages.lists` names that is not there and `view-whole-text` (a card or a row that puts a `text` field whole in a text block, which is clamped).
- No key is taken away from a document format within its version, and none is renamed without the old name still being read. 0.1.16 broke this: its American spelling pass renamed a setting's `honored` (was `honoured`) in the document as well as in the declaration, and its notes said the document format was unchanged, so every document `toDocument` wrote before 0.1.16 that carried settings failed to compile ("Nothing knows how to apply undefined"). Since 0.1.17 (FR-134), a key renamed within a format is a line in `RESPELLED` (`@graview/core/document`): every reader — `readDocument`, `compileDocument`, `appFrom` and `appFromOrCompile` on a compiled app an older build made, `diffDocuments` and `editDocument` — reads the old name as the new one, keeps the new one when a document says both, and never changes the document handed; `toDocument` and an edit write the new name. `respellDocument` does the same for a host and says which paths it respelled. A document stored with the old name is read the same on every later build of the major, so a host need not rewrite it, though its next save writes the new name. `packages/core/tests/document/fixtures/` keeps documents and compiled apps as older builds wrote them, made by those builds from npm, and each must compile; a test records every key path a document has been able to carry and fails when one is no longer read, by either name.

### 5. Derived tool names and input schemas

Tools are derived from the declaration (`createToolRuntime`, `graview mcp`), and a model that listed them before a change sends what it learned then.

- A change to a derived tool's name, description or input schema for an unchanged declaration is called out in a `Compatibility:` line, even when it is a fix.
- A change caused by the declaration (a renamed field renames an argument) is the app's change, not the framework's. The framework's part is saying which tools moved.
- FR-110 is such a change. Every derived `edit-<kind>` says `additionalProperties: false`, so an argument it does not take is refused as `invalid` where it was dropped. A document's act always says its `writes`, read off what its `sets` and effects set on its subject (`[]` when that is nothing), so an argument that only feeds a record the act makes no longer counts as a write of the subject, and `edit-<kind>` offers that field again. The conformance kit announces the two fixtures it moved (`document:vendors`, `document:two-lines`, 0.1.14). A TypeScript mutation that declares no `writes` is read as before.
- FR-121 is such a change. Every act's tool says `additionalProperties: false` — a document's act, a TypeScript mutation whose input is a plain `z.object`, `remove-<kind>` — and a call with an argument the act does not take is refused as `invalid`, naming what it takes, where the argument was dropped and the act ran without it. An act that creates still takes `id`. An input its author made `z.looseObject`, or gave a `catchall`, keeps what it is not told about and its tool says nothing new; one that is not an object's shape is not judged. An argument given as `undefined` is no argument. The conformance kit announces the two fixtures it moved (`document:vendors`, `document:two-lines`, 0.1.15).

- A file field's argument (FR-162) is described as an object of `href`, `name`, `type` and `bytes`, with `width`, `height` and `caption` optional, and a list of them as an array of that object; a seat may set one to a value the host's upload gave, and a value whose `href` is not a path on the host is refused as `invalid`. The derived `edit-<kind>` of a declaration that has no such field is unchanged.

- An app-link field's argument (FR-171) is described as a string of at most 500 characters with the address's `pattern` and `"x-graview-app-link": true`; a seat sets it to another app's address, and anything else is refused as `invalid`. The derived `edit-<kind>` of a declaration that has no such field is unchanged.

- Drawing a view and keeping it as a lens arrived as two tools a host opts into (the seat as a guide, B3): `draft_view`, a read, and `keep_lens`, which hands the host's `drafts.keep` the `add-lens` edit. A runtime lists them only when given `drafts` (`keep_lens` only with `drafts.keep`, and never on a read-only seat), and `toolDefinitions` only when told `drafts: "draw"` or `"keep"`, so a surface that did not ask keeps its tools and its hash. Their names, input schemas and answers are held to this section from now on. A lens either tool takes or returns is a declared lens (`{ title, lens, on, bindings?, options? }`) and is judged as one under the seat's sight; a kind the seat may not see is answered as one that is not there.

- FR-167 moved the read tools' answers and three input schemas. Every read answers at most `READ_CHARS` (8,000) characters of JSON, for a seat's turn and an MCP client alike. `get_graph` takes `offset` and answers a page of at most 25 records, the edges out of them, `total` and, when there are more, `more`; `get_node` takes `offset` and answers its links as `{ kind, id, label }`, 20 each way a page, where it answered whole edges; `get_violations` takes `offset` and answers `{ violations, total, more? }` where it answered an array; `search_graph` answers at most 20 hits whatever `limit` asked, with `more` and without `matched`. A field's text past 600 characters is cut and says its length, and any other read too long to fit answers `{ cut, partial }`. Within a host's turn, a call repeated with the same input is answered `{ already }`.

- FR-173 added three derived acts to every kind, beside `edit-<kind>` and `remove-<kind>`: `archive-<kind>` and `unarchive-<kind>` (`{ id }`, "Bring it back") and `merge-<kind>` (`{ id, into }`: the record `id` is archived and `into` takes its links). None is destructive; each is permitted through the acts that create the kind, as `remove-<kind>` is, and a grant may name each on its own. An app that declares an act of one of these names keeps its own. `search_graph` and `get_graph` take `archived` — `false` when unsaid, `true`, or `"all"` — and reach only the live records unless it is given; `get_node` reads an archived record by its id and says `archived: true`, as its links to one do. A seat that listed the tools before 0.1.29 sees three more per kind.
- The ninth walk (W-201) narrowed who a derived act reaches, and only where a grant to every role is the whole way to it. A kind's derived `edit-`, `remove-`, `archive-`, `unarchive-` and `merge-<kind>` ride the declared acts that make (or, for the edit, write) the kind; riding only a grant with `roles: "*"` that names those acts — "Anybody may join", `{ roles: "*", mutations: ["join"] }` — the derived act now reaches the records that seat made, as the log says who made each, and is refused on any other ("Not permitted: … — only on what you made; a coordinator can."), where it reached every record the seat could see. Nothing else changes: a grant of everything to everybody (`{ roles: "*", mutations: "*" }`, which `add-sight` writes on a document with no policy, FR-170) names every derived act outright and reaches every record a seat may see; a grant that names the derived act, or says `*`, reaches every record; and a role's own grant on the acts it rides (`{ roles: ["member"], mutations: ["join"] }`) reaches every record of the kind, as before. The tool list a seat is handed is unchanged; a call on another's record is refused as `forbidden`.

### Not a surface: the look

The values the theme writes — the shipped palettes, the default faces, weights, radius and spacing, the kit's defaults — are not one of the five, and a patch may move them; the custom properties' names, the `Brand` keys and what each means are kept, and a change to a value is said on the changeset's `Compatibility:` line. A host that wants its look held still declares its own brand (`schemes`, `typography`, `shape`), which the framework never overrides.

The design kit's revision 03 is such a change. The shipped schemes are built on Graview's identity — paper `#f7f7f2`, ink `#18213a`, muted `#586174`, En Dash navy `#001769` as the light accent, `#9aabff` on a navy ground `#0a0f1f` in the dark — and paint no wash (`wash: "none"`); `TYPOGRAPHY.body` names Montserrat first (never fetched: the host loads it, or the system sans stands in), with three new properties for its weights (`--graview-weight-display`, `-body`, `-label`: 550, 450 and 600 on the framework's face, 600, 400 and 600 on a face a brand names); `h1` and `h2` are tracked at −0.025em; the default radius is 8 px (6 small) where it was 12 (9). A brand that names its own schemes, faces and radius draws exactly as before but for the heading weight (`--graview-weight-display`, 600 where the browser's bold was 700), the two largest headings' tracking and buttons' labels at 600. A brand derived with `brandFromAccent` over the shipped schemes takes the new grounds, panels and inks with its own accent. `system-sans` in a document is the system's own stack as it always was.

The routed face's type is the look too. It is one scale written by the theme as four custom properties — `--graview-text-small`, `--graview-text-body`, `--graview-text-heading` and `--graview-text-title` (0.833, 1, 1.2 and 1.728rem, a minor third from the reader's rem) — whose values a patch may move and whose names are kept; an app's own stylesheet that sets one moves that step wherever the face uses it. Headings take the theme's heading rule (`--graview-font-display`, `--graview-weight-display`), so a brand's own face and weight always win. What a host's page or harness reaches in a derived list is kept and said on the `Compatibility:` line when it moves: a row `li.graview-row` (in `ul.graview-rows`) holding its link `a.graview-row-title` and its glance `span.graview-row-glance`, a search hit the same row as `[data-testid="search-hit"]`, and a group's or a section's heading `h2.graview-group-head`. A row's glance leaves off the field its group is by and a choice the list is narrowed to one value of.

How the app bar lays itself out is the look too. Since it fits its box, it reads its own width and never the screen's (a phone's bar below 640 px of its own), Find is a small box that says its shortcut and is drawn wide while it is used, and the switch draws its icons alone when its words do not fit. What a host's page or harness reaches is kept as it was and said on the `Compatibility:` line when it moves: the test ids (`app-faces`, `app-face-scene`, `app-face-pages`, `app-find`, `app-find-open`, `find-box`, `nav-find`, `app-places-open`, `app-place-current`), the embed's `switch` option (`"words"`, the default, or `"icons"`), and the switch's `data-switch` (what was asked) and `data-switch-drawn` (what is drawn). A host that wants the switch held to its icons asks for `switch: "icons"`; nothing holds it to its words at every width, because a bar too narrow for them would run out of its box.

Where the places stand is the look as well (FR-145): on a bar with room after the name, the switch and the tools, the app's primary places stand on the row as words, in their order and never more than six with Home — the one the reader is on always among them — and the rest fold into "More"; with too little room the one control returns; a phone's bar keeps the one control. How many stand changes with the width, the brand's face and the app's places, so a harness never counts on it. What is kept, at every width and on both faces, is how a place is reached — one recipe:

2. If that element is visible, press it (it stands on the row).
3. If not, press `[data-testid="app-places-open"]` — "More" where places stand, the one control where none do, on a phone the page's first line — and press it in `[data-testid="app-places"]`, the list it opens.
4. `[data-testid="app-place-current"]` says the place the reader is on: the one control's words, or the place standing on the row, marked `aria-current="page"`.

The list is grouped as before (`data-place-group`: `home`, `lists`, `pictures`), holding the places that do not stand; `app-places-open` is absent only when every place stands. The places standing on the row are inside `nav[data-testid="app-places-standing"]`.

How a list arranges is the look too: one quiet line under its title — the count in words ("16 tasks", "4 of 16 tasks" where something narrowed it), then "Sort", "Group" and "Filter", each opening a short list (`usePopover("arrange")`), and each condition as words with a ×; a narrow line is the count and one "Arrange". ## The conformance kit

`@graview/core/conformance` ships fixtures: declaration documents with the check findings and tool schemas this framework made of them, and op logs with the snapshot hash each folds to. `conformance()` runs them against this build, or against a build a host hands it, and returns the differences by fixture id. A host runs it before it takes a version.

The fixtures are append-only. `node scripts/conformance-fixtures.mjs` only ever adds a fixture with a new id, and a lock holds the rest. A change to a recorded fixture is an announced difference (`ANNOUNCED`), with the version that made it and what changed.

## The Compatibility line

A pull request that touches a file on one of the five surfaces asks every changeset it adds for a line:

```md
Compatibility: additive — `Operation.via` is a new optional field; ops without it read as before.
```

The line says the surface, whether the change is *additive*, *breaking* or *unchanged*, and for whom. `scripts/require-changeset.mjs` refuses a changeset without one (CI's `changeset` job), and the files that count as each surface are in `scripts/lib/surfaces.mjs`. The line goes into each package's CHANGELOG with the rest of the changeset, so every release lists what it did to compatibility.

## `capabilities()`

```ts
import { capabilities } from "@graview/core";

capabilities();
// { version: "0.1.22", protocol: 1, documentFormats: ["graview-document@1"], formats: { snapshot: 1, op: 1 },
//   shipped: ["FR-06", "FR-11", …] }
```

`shipped` lists the ids of the seams this build ships, by the ids Graview Cloud filed them under. A host retires its interim for a seam when the id appears. A test holds the list to the FR ids the changesets name, so a seam cannot ship unannounced or be announced without shipping.

`FRAMEWORK_VERSION` is the version alone, for a host that records which framework folded a store.
