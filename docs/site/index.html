Two programming interfaces. One declaration.

A declaration is a context graph, and a context graph is the one thing a model reads as well as a person does. Not a chat box bolted to a CRUD app — the same object is the source for your interface, your agent's tools and the checker that keeps them honest.

For a person

Surfaces, derived and replaceable

  • The scene. Every kind a district, every record a building on its own plot, every edge a road with the words on it — zoom, pan, come down.
  • The pages. Lists, records, forms and problems, routed. Replace one page or every surface with your own design over the same store.
  • The acts. What a selection may have done to it comes from the mutations and the policy. A seat never sees a button that would fail.
  • The lenses. A timeline, a calendar, a coverage matrix, a board and a plan, each bound to roles rather than field names — and the reach, which needs none.
  • The way in. An empty installation says what can be made now and what the rest are waiting for, in the order the declaration already states.
For a model

The whole app, readable and writable

  • Typed tools. Every act is a tool with a schema and a sentence, narrowed by the same policy a person is under.
  • graview describe. What a seat can do on day one, derived, so it cannot drift — the rung between the checker and a browser for something that cannot see.
  • graview docs. An llms.txt and an agents.md written out of the declaration.
  • Thirteen skills. Each teaches a model one shape of the declaration and ends in graview check, reporting what it actually said.
  • A plan before a change. What comes back is one row per thing, what it was sure about, what goes with what if you decline something — then one batch, one undo.

What you do not write

All of this is derived from the one declaration. Every piece of it is replaceable, and none of it has to be.

  • The picture. Every kind is a district of one city, standing on ground you can zoom and pan; every record a building on its own plot, a card among its relations when you come down to it; the words on the lines are the declaration's own, read from whichever end you are standing on.
  • The acts, and the checks. What a selection may have done to it comes from the mutations and the policy — a seat never sees a button that would fail. graview check reads the whole declaration and says what is wrong before a page does.
  • The pages. The same declaration, routed: lists, records and forms for the person who wanted an ordinary web app — with the app's own pictures as pages, a map saying how the kinds fit together in the declaration's words, and the assistant on every route. Every surface is replaceable, up to a product design of the app's own over the same store.
  • The agent's seat. Every act is a typed tool with a sentence attached. A model works the same graph, in the same operation log, under the same policy, and its turns can be taken back. It sits in the frame's own rail — what you have in hand, what can be done with it, what it says — and marks what it just changed on the things themselves.
  • The way in. An empty installation is the screen nobody designs. beginning() reads the chain out of the declaration and says what can be made now, what the rest are waiting for, and — for a seat that may not — who can.
  • Five lenses that rebind. A timeline, a calendar, a coverage matrix, a board and a plan, each binding roles rather than field names, so one written for your domain works unchanged in somebody else’s. The reach — what a thing is connected to, at any distance — needs no binding at all.

The tool, and the framework

graview is the command line a person installs. @graview/* is the framework a product imports. Thirteen packages, one version, each with its own page in the docs.

  • graviewThe one command line: create, check, docs, describe, lens, figure, serve, skills. Every subcommand lives in the package whose concern it is; this dispatches.
  • @graview/coreThe graph, the log, the schema and the checker. Everything a product declares.
  • @graview/layoutWhere every node goes: three planes, one pure function of the graph and the view.
  • @graview/toolsDerived affordances and the agent tool surface, from the same declaration.
  • @graview/renderThe spatial renderer. The DOM path ships; the GPU capture path is opt-in.
  • @graview/reactThe React binding: a provider, a scene, and the hooks an app builds on.
  • @graview/primitivesThe primitive set, the lenses, the workbench and the visual system.
  • @graview/pagesThe routed face: an ordinary web app derived from the declaration that drives the scene.
  • @graview/shipPersistence wiring, op-log-native migrations, export, health — and graview serve.
  • @graview/studioThe declaration as a graph, edited with ordinary acts and written back as files.
  • @graview/embedMount a declared app into any element — the scene, the Graview or the pages — as this page does.
  • @graview/skillsThe authoring moves an assistant reads before it writes, each ending in a real check.
  • create-graviewThe door npm create graview walks through. Three lines, on purpose.
  • Run it anywhere. graview serve puts the store behind HTTP with the data in a folder you can open, or in SQLite. Migrations are operations in the same log. Export and health come with it.
  • Self-hosted today. One declaration and one adapter, behind whatever you already run. Graview Cloud, which runs it for you, is on its way.
  • Open under the Elastic License 2.0. Build products on it and ship them freely; what it withholds is offering Graview itself as a managed service to third parties.

Start a product

One command from anywhere. What it writes is chapter one for your own domain: the declaration split into domain and UI, an eighty-line shell, a headless test, a CI workflow, and the skills your assistant needs to take it from there.

$npm create graview@latest my-appor: pnpm create graview my-app
$cd my-app && npm run devthe scene; /pages is the routed face
$npm run verifytypecheck, tests, build, graview check
$npx graview describe ./dist/domain/app.jswhat a seat can do on day one
$git clone https://github.com/en-dash-consulting/graviewthe framework, and the garden
$pnpm install && pnpm buildevery package
$pnpm graview create ../my-app --link .a product consuming the checkout by path
$pnpm dev:seedbedthe garden — ?chapter=N opens any chapter

Where it stands

0.1, and pre-1.0 on purpose. The packages are on npm under one version and the public API is designed to be depended on — but it still moves between minor versions while the shape settles, and the changelogs say what changed and why.
  • The capture path is experimental. Capture falls off a cliff past about 128 live captures a frame, and every claim above is measured against the DOM path. Use it for the per-plane blur, not because it is the default.
  • The calendar sync has never run against Google. Echo suppression, conflict detection and offline reconciliation are covered against a scripted remote. A token that expires mid-run is not.
  • No screen-reader pass with real assistive technology. The tree is populated and axe-core reports nothing. A populated tree is not proof that VoiceOver reads it well.
