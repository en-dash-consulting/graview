description: "The launcher (apps/launcher, \"the desk\") surveys two demos against eleven capabilities read from their declarations: the three lens starters, an entity-bound lens, rules as nodes, field roles, an edge to any kind, a mutation for any kind, repairs, a kind with no custom view, and a persistence adapter — the last two true by assertion. That is the framework of six months ago. It says nothing about the routed face, places, seats and policy, the agent seat, the installation and profiles, brand and kit, remembering and migrations, the embed, the checker, modules, the horizon, derived edits, undo and the trail, or the studio — which is what a person opening the launcher for the first time needs to be shown. Realign it: the capability list becomes the platform's, in the order a person meets them (declare → look at it: scene, altitude, horizon → the routed face → lenses and places → rules and repairs → undo and the trail → the agent seat → who may do what and seats → the installation and profiles → brand and kit → remember and ship, migrations → on somebody else's page → the studio → checked), each decided from the declaration where it can be (lenses, policy, roles, modules, brand, kit, version and migrations, intelligence) and from the app's own manifest where it cannot (remembers, embeds, custom design, studio entrypoint) — never by assertion. Each capability carries WHERE to see it: an app and a stop URL, or a seedbed chapter, so pressing it opens the demo there. The desk's rules become the onboarding's own: every capability is shown by at least one demo (a gap is a problem on the standing, with \"add it to <app>\" as the repair the agent can propose), a lens needs two users, every app uses a lens. The launcher lists every demo this repository ships — Things, Seedbed and its chapters as stops, and the third demo — with liveness and the command to start each. Its own picture is the matrix: apps down, capabilities across, the onboarding order left to right, so the front door is itself a Graview.
