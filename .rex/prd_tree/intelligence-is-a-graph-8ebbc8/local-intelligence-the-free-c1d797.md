description: "The intelligence ladder gets its middle rung: models that run in the person's own browser, so useful AI costs nothing marginal and nothing leaves the machine. The seams already exist — a local model is one Completion function or one Responder — so this feature is adapters plus honest capability detection, not architecture.\n\nTrack A — LOCAL GENERATIVE (the conversational free tier). A @graview/local (or tools/local) adapter wrapping an in-browser LLM behind the existing Completion seam: WebLLM (MLC) over WebGPU as primary, Chrome's built-in Prompt API (Gemini Nano) where present, transformers.js as the wasm fallback. Realities to engineer, not discover: model weights are 1–2GB (lazy fetch with progress UI, cached via the browser; never on the critical path — the chat opens on graphResponder and upgrades when the model is warm); WebGPU contention with the scene's own renderer; small models are unreliable at strict JSON, so the adapter leans on the existing validateProposals gate plus one constrained retry, degrading to words — never to wrong calls. Capability detection is a declaration the interface states plainly (\"answers stay on this machine\" / \"no local model here — the graph still answers\").\n\nTrack B — ELM WHERE ELM FITS (classification, not generation). AsterMind-ELM trains in milliseconds on small data, predicts in microseconds, and serializes to small JSON — evaluate it for: (1) chat intent routing trained in-browser on the app's own declared vocabulary (mutation titles, kind plurals, edge descriptions) replacing today's regexes in graphResponder; (2) per-workspace affordance RANKING learned from the op log — which suggestions this household actually applies — private, instant, no server, feeding the existing score field. Both are Responder/provider-internal upgrades; if evaluation shows no lift over the derived heuristics, record that and drop it.\n\nProduct tie-in: this is the entitlement ladder for the household product/graview-cloud — free tier = graph-native + local model, paid tier = frontier via customer key or metered seats. The trust story never changes: whatever answers, proposals travel the one validated path."
