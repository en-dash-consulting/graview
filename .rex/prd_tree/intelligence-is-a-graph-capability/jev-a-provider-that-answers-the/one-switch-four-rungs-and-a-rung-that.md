description: "IntelligenceConfig already climbs graph -> local -> remote over one Responder contract, and the graph rung is keyless and always there. Jev makes it four: graph only, onboard AI, Jev, LLM — one setting a person changes, as asked. The care it needs is that the ladder has TWO axes and pretending it has one is how a switch starts lying. A Responder answers in prose and Jev has none, so Jev cannot climb that axis at all; a DECISION — which surface is this, which zone does it stand in, does this practice address that concern — can be answered by the graph's own rules, by Jev exactly, or by an LLM with the whole parse-and-refuse layer behind it, and there Jev is the best rung rather than a middle one. So a rung declares which capabilities it serves, a surface asks for a capability rather than for a provider, and anything a rung cannot serve falls DOWN to the graph, which is keyless and always there. On the Jev rung the chat seat should say plainly that this rung decides rather than talks and that the graph is answering here — the same honesty the seat already shows when it is refused an act. Switching must be live and must not lose work: a run half done on one rung does not silently finish on another."
