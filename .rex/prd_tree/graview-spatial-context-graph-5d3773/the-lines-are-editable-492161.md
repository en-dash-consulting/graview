description: "The scene draws relations as lines, but a line is currently scenery: you cannot select one, ask what it is, or act on it. The concrete gap that surfaced it: fullscreen a Run in the household example and the Children attached to it (rides-in edges) are visible but untouchable — the only offered action is reassigning the Run's owner, because reassign is the one mutation whose subject binding reaches that neighborhood. Removing a rider, adding one, or moving one to another run should be as direct as right-clicking the line.\n\nWhat this needs, in the framework's own grammar:\n\n1. **Edges join the selection model.** A connector becomes a pick target (click selects the EDGE, right-click opens the pointer menu on it) — likely a selection entry shaped like `edge:<kind>:<from>:<to>` beside node ids, carried in the URL like everything else now is. The inspector for a selected edge says what the relation IS (the declaration already carries the description — \"who is along for it\"), names both endpoints as chips, and offers its legal actions.\n\n2. **Edge affordances derive, they are not wired.** Mirror the `creates` seam: mutations declare the edge kinds they `connect` and `sever` (e.g. The household example gains remove-rider/add-rider declaring rides-in), so selecting a line derives \"Remove Ana from this run\" / \"Move Ana to another run\" with candidates from the graph — the schema provider's move, pointed at edges. `graview check` verifies declared edge kinds exist.\n\n3. **Inline everywhere the line is drawn.** The zoomed/fullscreen view and the ordinary stack offer the same edge actions in place — no travel required to edit an attachment. SelectionTies/Connectors need hover/hit affordances honest about which line is under the pointer (the DOM-measured anchoring landed earlier is the substrate).\n\n4. **Agent parity for the mods.** Because the actions are ordinary derived affordances over declared mutations, the seat and tool surface get them for free — \"have an agent help me make those mods, inline\" is then just the existing intelligence seam pointed at an edge selection. Verify, don't assume.\n\nApp follow-through: the household example gains the missing rider mutations (remove-rider, add-rider/move-rider) with declared connect/sever edge kinds; the coaching example's filled-by would benefit identically (drop-from-position already exists — declare it)."
