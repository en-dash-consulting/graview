description: "The thing you are actually looking at is boxed. The focus panel is capped at about 1040 pixels wide and stops around 83% of the height to leave the kinds strip its band — so on a 1560-wide screen a week calendar, a nine-by-eight coverage matrix, a board and a three-column list are each drawn with roughly 260 pixels of dead ground either side, while the view itself is the densest thing on the screen and wants every pixel it can get.\n\nThe plane model is why, and it is right most of the time: the strip is a constant map and the focus reaching down over it is what makes the arc read as depth. But a calendar is not most of the time. Some views are dense enough that context should get out of their way, and the interface has no way to say so.\n\nThere are already two altitudes above this one — the Graview looking down on everything, and jacking in, which lifts a single view out as a modal page and takes the scene with it. What is missing is the one in between: the focus FILLING THE SCENE, with the strip and the relation plane receding rather than disappearing, still in the same picture, still with its connectors, still a stop you can back out of.\n\nDesign questions this has to answer rather than assume:\n\n- **Is it a view state?** Almost certainly, because everything else here is: it should be a URL, the back button should work, and `interpolate` should tween into and out of it for free.\n- **What happens to the strip and plane 1?** Receding is not the same as removing — the whole argument for the constant strip is spatial memory, and a mode that deletes it and puts it back somewhere else would undo that.\n- **Who decides?** A person, always. Possibly also a lens, which knows better than the framework whether it is dense — the coverage matrix and the timeline would ask for it and a single node's detail panel would not. That is the same shape as `natural`, which the shrunk-interface work already established for the other end of this axis.\n- **Does it survive travel and place changes?** A mode you have to re-enter after every navigation is a mode nobody uses.</parameter>\n<parameter name=\"acceptanceCriteria\">[\"A dense view can fill the scene — the focus takes the width and height the window has, not a fixed cap\", \"It is a view state: a URL, a back-button stop, and it tweens in and out through the existing interpolation rather than snapping\", \"The kinds strip and the relation plane RECEDE rather than vanish, so spatial memory survives the change\", \"Entering and leaving is one gesture, and the control says which state you are in\", \"A lens can declare that it wants the room, and a person can always override that in either direction\", \"The mode survives travelling to another node and switching place\", \"The three dense lenses — timeline, coverage, board — and the todo lists all measurably gain drawing area, verified in a browser in both schemes\", \"Nothing about the plane model or the capture pipeline changes: the transform stays affine\"]</parameter>\n</invoke>\n"
